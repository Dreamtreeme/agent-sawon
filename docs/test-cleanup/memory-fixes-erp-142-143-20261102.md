## 남은 문제: 어느 연결에서 다시 판단하게 되는가

### 1. 실제 행동의 진행을 원본 배치와 연결하는 단위가 좁다

`brain/graph/memory_retrieval.py:589`의 `_replacement_group`은 배치 전체의 행동 수가
같아야 하며, 스크롤도 정확한 기존 point 또는 과거 대상 bbox 안인지를 비교한다.

- **same:** seq122는 원본과 같은 상단 5fill + 스크롤을 실행했다. 앞의 5개는 source와
  영역이 모두 맞았다. 그러나 스크롤 `[1137,400]`은 원본 `[600,400]`과 다르고 과거
  `품명` bbox 밖이어서 **배치 전체 진도 연결이 실패**했다. 스크롤 자체는 정상 실행됐다.
  원본 스크롤 point도 그 입력칸 밖인데 정확히 같은 point라는 이유로만 허용되는 구조다.
- **changed:** seq122의 5fill과 seq161의 스크롤로 나뉘어 실행했다. 원본은 6행동 한
  묶음이므로 5와 1 어느 쪽도 연결되지 않았다. 최종 상세 스크롤 `[600,450]`도 원본
  `[600,400]`과 달라 연결되지 않았으며, seq423 교육 완료 관찰로 진도가 회복됐다.

상단 그룹이 남으면서 하단이 보이는데도 경로의 첫 그룹은 상단이다. 하단 그룹의 화면
거리는 same 4, changed 0으로 허용 범위지만 `_matching_route`는 남은 첫 그룹만 확인한다.
다만 입력 확인 대기도 모델 호출을 독립적으로 요구하므로, 진도 연결만 고치면 해당 호출이
모두 사라진다고 계산해서는 안 된다. pHash 제거는 배치 단위·스크롤 의미까지 바꾼 수정이 아니다.

### 2. 현재의 더 짧은 경로와 기억의 원본 순서가 다르다

두 실행은 조회창의 실제 신규 버튼으로 바로 등록에 들어갔다. 닫기 후에는 원본이 기대한
메뉴가 아니라 이미 결과행이 있는 조회창으로 돌아왔다. 원본의 다음 그룹은 메뉴여서
viewport와 화면 거리가 맞지 않고, 나중의 결과 열기 그룹이 화면과 맞아도 직접 선택하지 않는다.
모델이 결과행을 열고 교육 단계 완료를 보고하면 그제야 원본 메뉴·조회·열기 구간을 함께
소비한다. same seq379가 이 회복 지점이다. 두 실행 모두 첫 결과행 double_click으로 상세에
들어갔고, 140/142에서 보인 불필요한 단일 클릭 반복은 143에서는 없었다.

따라서 이번에 옛 버튼의 의미는 바로잡혔지만, 이번 실행에서 선택된 더 직접적인 경로에 맞춰
원본 기억 진도를 즉시 맞추는 문제까지 해결된 것은 아니다.

### 3. 저장 알림 재사용은 OCR 띄어쓰기에도 실패한다

changed seq303 `save_result_not_bound` 뒤 seq307이 저장 확인창을 다시 판단했다.
`brain/cache/methods.py:842`의 `_bind_save_review`에서 실제 OCR `저장번호:1`과
기억의 `저장 번호:1`이 달랐다. `normalize`는 내부 띄어쓰기를 제거하지 않으므로 메시지
검증 전체가 실패했다. 실제 캡처·입력의 무료 함수 재생에서도 확인했다. 과거 입력값이
재주입되거나 저장에 실패한 경우는 아니다. 현재 화면의 저장 성공 알림과 확인 버튼을
모델이 읽고 처리했다. 이 비교 규칙은 이번 승인 범위에서 수정하지 않았다.

저장 행동 누락의 원인이라는 가설은 이 사례에 맞지 않는다.

## 판정·검사·반증 조건

- 현재값 입력·누적·저장 후 별도 확인은 유지됐다. 두 실행의 최종 수용 관찰과 메모가 모두
  연결됐다. 실제 API 의미 교정과 거리 14 복구 진도 연결도 확인했다.
- 이번 2회에서 실행 계획의 좌표/bbox 검증 거절·검증 예외는 0건이다. 다른 시드와 모든 모델 응답을
  검증했다는 뜻은 아니다. 기존 zero-size 및 과거 메모 보완 xfail 2건의 해결을 주장하지 않는다.
- 모델 없는 완전 재현은 둘 다 false다. 이번 목적은 그 지표의 달성이 아니라 세 수정의
  기능 유지와 남은 문제의 실제 발생 지점 확인이다.
- 제품 변경이 없으므로 전체 테스트를 다시 돌리지 않았다. 대상 커밋의 검사 결과는
  [복구 진도 보고서](recovery-route-link-20261102.md)의 778 passed, 2 xfailed와 Ruff 통과다.
  이번에는 합성 profiler 무료 시험, 실제 편찬 1회, 실제 ERP 142/143 각 2회, 원문·프레임
  대조, 실제 함수 무료 재생, protocol 해시 확인 및 문서 `git diff --check`를 수행했다.
- 과거 값이 현재 읽은 값으로 발행되거나, 최종 수용 source/value가 메모에서 사라지거나,
  다른 단계 행동이 원본 단계로 잘못 연결되면 기능 유지 판단을 재검토한다. 이번에는 발견하지 못했다.
- 스크롤/배치 연결을 바꿔도 입력 검토 호출이 그대로 필요할 수 있다. 후속 개선은 모델 호출
  감소를 먼저 가정하지 말고, 실제 진도 연결과 여전히 필요한 관찰을 분리해 확인해야 한다.
