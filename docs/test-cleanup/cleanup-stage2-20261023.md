# 2차 정리: 재계획 응답 처리 중복

## 후보와 범위

전체 그래프 재생 확보 후 [정리 기준](cleanup-criteria-20261023.md)의 중복 구현 항목을
진행했다. 086의 OCR 누락으로 미재생 구간에 걸리는 상태 소유·계획 인계 통합은 보류한다.
이번 변경은 screen_decision.validate_or_replan 한 함수의 두 보완 경로에 한정한다.

| 후보 | 유형·실패 영향 | 근거·조치 | 전→후 |
|---|---|---|---|
| C02 입력 표면/확신도 거절 이후 보완 처리 | 중복 구현, 두 경로 수정 불일치의 유지보수 위험. 실제 실패 원인으로 확정한 사례 없음 | 오류별 안내문·artifact 이름·이벤트 이름은 유지하고 요청 구성, 호출, 로컬 변환, 증거 결합, 재검증, 기록을 공유 | 처리 본문 2→1, 함수 173→149줄 |

별도 서비스·클래스·상태나 새 정책 함수를 만들지 않았다. 한 번 실행할 때의 변환 수와
모델 호출 수는 그대로다. 이는 런타임 비용 절감이 아니라 중복 구현 감소다.
확신도/입력 표면의 거절 조건과 observe_only 분기는 변경하지 않았다.
모델·교육·이미지·프롬프트 문구와 오류 처리도 변경하지 않았다.

## 검증

- 수정 전 함수를 로컬 복사본에서 메모리로 로딩하여 수정 후와 동일한 합성 입력을 실행했다.
  두 오류 × 정상/잘못된 보완 응답의 4조건에서 요청 프롬프트 원문이 전후 완전히 같았다.
- tests/test_replan_pipeline.py의 두 파라미터는 두 오류 각각에서 정상 응답 전달과
  잘못된 보완 응답의 재거절을 검사한다. 공용 외부 경계는 fake이며 합성 입력임을 명시했다.
  반환 대상, 문맥, 호출 수, artifact 종류, 이벤트 payload와 입력 불변을 확인한다.
- 테스트 프로세스에서 보완 응답의 prepare_screen_plan 호출을 제거한 합성 변이는
  두 오류 모두에서 단언 실패로 탐지됐다(2/2). 제품 파일에는 변이를 적용하지 않았다.
- 089의 전체 오프라인 그래프 재생은 요청 19회·행동 29건·노드 88회, 종료 상태와
  11개 verified/post_save_verified 키가 이전과 같았다. 이 정상 경로가 두 오류 분기를
  모두 실행한다는 주장은 하지 않는다. 오류 경로는 위 합성 전후 비교로 별도 확인했다.
- 전체 pytest **698 passed, 60.02초**, lint 통과, format 229개 파일 통과,
  vulture 80% 경고 0건, git diff --check 통과. 테스트는 삭제하지 않았다.
  이번에는 coverage 및 전체 변이 점수를 측정하지 않는다.

비공개 측정은 `.tools/cleanup-stage2/`에 보존한다. 원본 기록·화면을 커밋하지 않는다.
실제 ERP·유료 모델 호출은 없었다. 기존 미커밋 제품 수정은 기준선에 포함하되,
이번 커밋에는 validate_or_replan 통합 부분만 포함한다.

## 반증 조건과 다음 후보

같은 오류에서 프롬프트, 반환 대상, 보완 응답 검증, artifact 또는 이벤트가 달라지면
동작 보존 주장은 반증된다. 재생 성공은 실제 데스크톱 환경이나 미재생 086 구간까지
보증하지 않는다.

grounded plan/replan의 해석 결합(M02)은 mapping 보존과 각 경로의 검증 차이를 더
확인한 뒤 판단한다. 상태 메모와 저장 후 확인 메모를 단어가 비슷하다는 이유로 합치지 않는다.
