## 수정 세 항목의 판정

1. **제거 구간 진입 연결: 실제 검증 미해당.** 편찬 모델이 14개 후보를 모두 유지했고
   removed_groups가 비어 있었다. 이전 135 기록의 오프라인 검증 결과만 유지한다.
2. **다른 행동 복구 후 상세 진입: 작동했으나 후보 확대 회귀도 확인.** 인출 seq357에서
   모델의 더블클릭이 전달된 뒤 seq362에 상세 검토의 원본 메서드가 결합했다.
   반면 아래의 빈 입력 화면에서도 과거 결과가 선행조건을 대신 충족시켜 후보가 늘었다.
3. **완료 관찰 보존: 편찬 성공, 실제 사용 미확인.** 산출물 completion은 존재하지만
   method_completion_bound는 0건이다. 마지막 화면에서 이전 입력 그룹이 선택됐고,
   복구 모델의 새 관찰을 누적하여 완료했다. 완료 기억 인출 성공으로 보고하지 않는다.

## 화면과 로그로 확인한 회귀

인출 seq169 직전 화면의 포장 수량·단위·중량·컨테이너·항구 입력칸은 비어 있다.
이 캡처와 최종 저장 후 하단 캡처를 직접 열어 대조했다.
현재 메모의 완료 단계는 login, open-query, check-duplicate, open-new-record뿐이었다.

같은 편찬물·캡처·당시 전달 이력·메모를 임시 라이브러리에 읽기 전용 재생한 결과:

| `25b9f5572e9f4c1d` | 205 | 0 | 하단 6개 입력 | 앞선 입력·스크롤 그룹 실제 전달 |
| `ff710773e26dbb6d` | 340 | 6 | 저장 클릭 | 해당 기억의 과거 `enter-record-fields completed=true` |

`_satisfied_groups(method, group.observed_step_results)`가 후보 자신의 과거 완료 판단으로
같은 교육 단계의 미전달 선행 그룹들을 충족시켰다. 화면 유사도 6까지 허용하는 조건에서
빈칸 화면과 입력 완료 화면이 모두 결합되어 후보가 2개가 됐다. `match_pattern`은 유일한
후보를 고르지 못해 모델을 호출했다. 이 호출은 새로운 복구 허용 기준이 만든 회귀로 확인했다.
이전 실제 전달 기준만 적용하면 저장 후보의 선행 그룹은 미충족이었다.
모든 추가 호출이 같은 원인이라고 확정하지는 않는다.
