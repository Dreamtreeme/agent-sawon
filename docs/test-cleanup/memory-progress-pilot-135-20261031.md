core `df208042490b65f3f3a6e01552e817e458eddd6c`, bench
`badbb5f6aa900aed57be742ff58d2acec9c12cfa`이며 실행 중 제품 코드는 변경하지 않았다.
시드 1, 회사 001 교육, ID none, visual_only, Haiku 5.5 / low / 8192,
화면 실행·편찬 각각 $3 상한이다. 교육 SHA256은
`9cfeeeb5cc0715cfd85fadb911887712280b9e88f3ce4dfea0a9c748c32b4263`이다.
탐색과 인출은 서로 다른 빈 화면 캐시를 사용했다. 인출 메서드만 이번 편찬물을 사용했다.

## 수정 동작을 확인한 지점

탐색의 저장 후 상단 캡처는 저장 번호와 상단 5개 값을, 하단 캡처는 나머지 6개 값을 보여준다.
두 이미지를 직접 검토했다. 인출의 마지막 하단 캡처도 저장 번호와 실제 저장값을 확인했다.

| 경로 | 로그 순서 | 확인 내용 |
|---|---|---|
| 탐색 | 407 → 408 → 410 | 상세 검토 시작 → 재조회 교육 완료 → 상단 5개 저장 후 확인 |
| 탐색 | 438 → 440 → 444 | 최종 교육 완료 → 하단 합산 11개 확인 → 누적 증거로 정상 종료 |
| 인출 | 357 → 358 → 360 | 상세 검토 시작 → 교육 완료 → 상단 5개 확인 |
| 인출 | 387 → 389 → 393 | 교육 완료 → 누적 11개 확인 → 정상 종료 |

탐색 436의 모델 원문은 현재 하단 6개와 앞서 같은 범위에서 확인한 상단 값을 함께 사용해
`operation=complete`를 반환했다. 이후 상단 재방문이나 navigation_cycle 중단은 없었다.
인출도 같은 범위의 5→11 누적 후 종료했다. 같은 교육 완료와 관찰 결과가 편찬된 행동 그룹
11개에 보존되었고, 원본 그룹 10개를 전달했다. 새 클래스나 상태 기계 없이 기존 계약을 사용한다.

이번 실제 상세 화면 분류는 editor였다. dialog로 분류된 실제 실행과 실패 예산 소진 상황은
이번에 발생하지 않았으므로 해당 두 분기의 실제 재현 검증까지 완료했다고 주장하지 않는다.
그 분기들은 앞선 합성 회귀·결함 주입 시험에서 검증했다.

## 인출에서 남은 모델 호출 3회

모두 `completion_review`지만 실제 역할은 다르다.

| 호출 seq | 실제 역할 | 직접 확인한 원인 |
|---:|---|---|
| 318 | 조회 화면에서 입력·조회·상세 열기 선택 | 312 화면 유사도 불일치. 예정된 재조회 그룹과 같은 크기지만 pHash 거리 10으로 허용값 6 초과 |
| 350 | 재조회 상세 상단 확인 후 아래 스크롤 | 344 화면 유사도 거리 0이나 348 `no_unique_next_plan`. 원본 선행 재조회 그룹이 미전달 상태 |
| 381 | 하단과 누적 상단을 합친 최종 완료 | 375 화면 유사도 거리 0이나 완료 메서드가 없고 379 `no_unique_next_plan` |

첫 호출의 화면은 원본과 같은 조회 결과를 보인다. 직접 비교한 캡처에서 조회 버튼과 새 건
등록 버튼의 포커스 표시가 다르다. 이 차이만이 거리 10의 전부인지까지 분리 실험하지 않았다.
편찬은 무변화 단일 클릭 c010을 제거하고 c011 더블클릭을 유지했다.
모델 복구는 원본 더블클릭 한 동작과 달리 입력·조회·더블클릭을 반환했다. 원본 그룹을
대체했다고 연결되지 않아, `memory_retrieval.py`의 선행 그룹 조건이 다음 인출에 영향을 준다.

최종 완료 원문에는 입력 evidence와 observed_step_results가 있지만 completion_evidence는
빈 목록이다. `brain/cache/methods.py:method_completion_from_match`는 두 증거 목록을
모두 요구하므로 None을 반환했고 편찬물의 completion도 null이다. 이번 수정의 결과 전달은
작동하지만 이 기존 편찬 조건까지 맞춰진 것은 아니다. 관찰만 했고 제품 코드를 수정하지 않았다.
