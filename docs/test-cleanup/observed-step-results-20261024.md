# 097 조회 반복: 관찰 결과를 다음 행동보다 먼저 답하는 계약

## 가설과 범위

097에서는 모델이 이미 전달한 조회와 현재 0건 표시를 연결하지 않고 조회를 반복했다.
입력값 증거는 메모에 누적되지만 일반 교육 단계의 완료를 모델 응답에서 받는 항목은 없었다.
이 누락이 모든 반복의 유일한 원인이라는 주장은 하지 않는다. 093은 같은 빈 완료 메모로도
신규 등록까지 진행했으므로 모델 판단의 변동도 남아 있다.

특정 결과 문구 파싱, 버튼 좌표 고정, 추가 검토 호출, 반복 행동 거절 완화는 하지 않았다.
기존 교육·관찰·계획 계약에서 결과를 표현하고 기존 완료 집합에 전달하는 범위다.

## 서로 다른 두 시도

097 seq 92의 이미지와 요청 JSON을 그대로 두고 현재 프롬프트/스키마로 1회씩 호출했다.
이미지·문맥은 동일하지만 확률적 모델의 단일 응답 비교이며 개선율 측정은 아니다.

| 방식 | 실제 응답 | 호출 시간 | 비용 |
|---|---|---:|---:|
| 완료 ID 목록만 추가 | 빈 목록, 다시 조회 선택 | 6.58초 | $0.0014346 |
| 단계 ID·관찰 결과·완료 여부를 다음 행동 전에 답함 | 중복 확인 완료, 새 건 등록 [271,729] 선택 | 13.73초 | $0.0019659 |

첫 방식의 코드 계약은 두 번째 방식으로 대체했다. 실패한 호출도 보존했다.
비공개 산출물: `cases/query-outcome-098`, `cases/query-outcome-098b`.

## 최종 구현

- `ObservedStepResult(step_id, observed_result, completed)`와
  `ScreenMapping.observed_step_results`를 추가했다. 완료 목록을 이중으로 정의하지 않는다.
- `ScreenPlan`/`ScreenMatch`와 로컬 변환·계획 조합은 결과 목록을 보존한다.
- 관찰과 별도 선택 양쪽의 기존 `_remember_model_task_evidence`가 완료 항목을 실행 전에
  `_complete_taught_procedure_step`으로 전달한다. 기존 완료 집합과 교육 문맥을 재사용한다.
- 미등록 교육 ID는 기존 방식으로 무시하고, 중복 완료는 멱등 처리한다. 미완료 항목은 완료로
  추가하지 않는다. 다음 행동을 선택하거나 전달한 사실만으로 완료 처리하지 않는다.
- 입력값, 좌표, 허용 창, 최종 완료 판정은 변경하지 않는다. 상태 머신이나 추가 호출 없음.
- 스키마 fixture 2개는 의도적으로 갱신했다. intent·role·키 어휘는 변경하지 않았다.

## 검증과 반증 조건

새 합성 테스트는 실제 관찰/선택/검토/실행 경로를 연결한다. 최초 구현 전 두 경로 모두 새 필드
미지원으로 실패했고, 구현 후 완료 메모가 실행 전에 보이는지와 호출 수 불변을 확인했다.
기존 계획 조합의 grounded/replan 테스트도 결과 보존을 단언한다.

실제 모델이 완료 결과를 쓰고도 같은 조회를 반복하거나, 그 결과가 다음 요청에서 유실되거나,
완료하지 않은 교육을 완료로 기록하면 가설 또는 구현을 재검토해야 한다. 합성 테스트 통과는
실제 모델의 해석 정확성이나 전체 ERP 성공을 보증하지 않는다.

최종 구현의 무료 검사:

- core `python -m pytest`: 712 passed, 37.85초.
- core `python -m ruff check .`, `python -m ruff format --check .`, `git diff --check`: 통과.
- bench `python -m pytest tests/test_relay.py tests/test_relay_windows.py tests/test_visual_relay.py -q`:
  96 passed, 2.51초. 기존 Starlette/httpx 사용 중단 예정 경고 1개.
- 시험 프로세스에서만 완료 결과를 빈 목록으로 치환하는 변이를 주입하면 새 회귀 두 경로가
  모두 `completed_taught_steps` 단언에서 실패한다. 제품 파일은 변이하지 않았다.
- 처음 지정한 bench `test_relay_desktop.py`는 존재하지 않아 수집 없이 종료했으며,
  실제 테스트 경로를 확인해 위 96건을 실행했다.

ERP 실행 결과는 실행 후 별도로 기록한다.
