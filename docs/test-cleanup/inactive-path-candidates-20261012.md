기준 커밋: 72c7f6f. 현재 config/brain.visual.toml과 앞선 657건 호출 경로 기록을 대조했다.
이번 작업은 후보 식별이며 테스트·프로덕션 코드는 수정하지 않았다. 전체 삭제 타당성이나
변이 점수를 증명한 것은 아니다. 이번에는 테스트를 재실행하지 않고 직전 계측 결과를 사용했다.

## 실제 삭제 후보와 단순 설정 차이를 구분

- 앞의 18건은 현재 주 경로나 새 산출물을 검증하지 않는 부분을 포함한다.
  파일 통째로 삭제하라는 뜻은 아니다. source 누락, 실행 순서, 비밀 중복 입력 방지,
  전달/업무 완료 구분처럼 현재도 필요한 단언은 새 경로로 옮겨야 한다.
- OCR 앵커 분기는 코드에 남아 있으며, 과거 형식 warm_compiled 캐시를 로드하면
  현재 프로필에서도 도달할 수 있다. 따라서 완전한 사망 코드로 판정하지 않았다.
- runtime_trace 네 케이스는 테스트 fixture가 compiled_only=False인 별도 동작을 검증한다.
- 단일 화면 학습은 README에 CLI가 명시돼 있고 main에서 learn_method를 호출한다.
  일반 파일럿에 포함되지 않는다고 해서 호출처가 없다고 판단하면 안 된다.
  warm_methods는 같은 모듈의 read_screen을 사용하므로 모듈 통삭제 대상도 아니다.
- 분리 호출·구형 정책은 설정으로 재활성화할 수 있다. 현재 미사용과 도달 불가능은 다르다.

## 이번 목록에 넣지 않은 항목

- 50건의 비매칭 run 진입 테스트 전체: 비용, IO, CLI 오류, 부분 실패 등 공통 검증도 있어
  모두 불필요하다고 분류하지 않았다.
- test_candidate_compiler_removes_instance_anchors_and_repeated_retries: 과거 앵커를 쓰지만
  중복 제거와 인스턴스값 제거라는 현재 공용 동작도 검사하므로 별도 단언 분해가 필요하다.
- 내부 numeric handle / Decision 좌표 금지 테스트: 모델 외부 계약이 아니라 실행기 내부
  계약을 검증하므로 숫자가 있다는 이유만으로 레거시 후보로 잡지 않았다.
- 저장소·공급자·문서 처리 테스트: 화면 파일럿에 직접 나타나지 않아도 해당 기능은 별도다.

## 우선 정리 순서

1. 과거 좌표 기대값 6건과 raw trace fixture 4건을 현재 screenshot-bound compiled 경로로 대체.
2. 분리 모드 1건은 해당 모드 유지 여부와 함께 정리.
3. 구형 정책 6건·전체 업무 1건은 공통 단언을 보존하여 현재 Brain.run 경로로 이전.
4. 단일 화면 학습 CLI 2건은 그 기능을 폐기할 때 코드·문서와 함께 제거.

이 목록의 테스트가 모두 완전히 미사용인 것은 아니다. 현재 설계와 다른 경로를 보존하는
구체적인 후보 20건을 찾았으며, 이들 중 호출 불가능하다고 확정한 항목은 없다.
