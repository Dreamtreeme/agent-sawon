# 편찬·인출 경계 수정과 오프라인 검증

기준 코드는 `dfb3a9b`이며, 사용자가 승인한 세 경계를 수정했다. 이번 작업에서는
실제 ERP·유료 모델을 실행하지 않았다. 135의 원본 로그·이미지·편찬 응답은 변경하지 않았다.

## 변경

| 경계 | 이전 동작 | 변경 |
|---|---|---|
| 제거 구간과 다음 행동 | 선행 그룹 ID만 연결하고 제거된 행동 이후 화면을 요구 | 첫 제거 후보의 행동 전 화면·관찰 기억을 진입점으로 연결. 유지 행동의 좌표·대상 기하는 보존 |
| 복구 후 재진입 | 원본 행동 전달 또는 같은 길이·행동의 대체 연결만 사용 | 현재 실행의 교육 완료와 현재 화면에 유일하게 결합되는 관찰 완료 결과도 사용 |
| 완료 편찬 | 별도 완료 주석이 없으면 실제 성공의 최종 관찰도 버림 | 마지막 성공 종료 관찰과 직전 누적 완료 검토를 연결하여 마지막 관찰을 보존 |

`used`에는 실제 전달 그룹만 기록한다. 생략 그룹의 허위 전달 처리를 제거했고, 동일 행동의
검증된 대체 관계는 기존 실행 이력에서 읽는다. 완료 판정에는 현재 실행의 저장·재조회 상태와
누적 확인값을 사용하며, 이전 실행의 성공 플래그나 확인 완료 집합을 복사하지 않는다.
기존 `RetrievalContext`에 현재 `completed_taught_steps`의 읽기 참조를 추가했다. 새 상태 기계,
영속 상태 집합, 모델 응답 스키마, 프롬프트, pHash 임계값은 추가하거나 변경하지 않았다.

완료 편찬의 `verified_fields`는 source reader가 실제 성공 검토에서 전달하는 임시 인자다.
일반 완료 편찬과 온라인 `remember()`는 이 근거가 없으면 기존 완료 조건 주석을 요구한다.
현재 `observe_only` 그래프의 누적 완료 판정은 변경하지 않았다.

## 검증

- 수정 전 합성 시험에서 제거 구간의 진입 해시 불일치, 복구 재진입 실패 두 경로,
  누적 완료의 편찬 누락을 확인했다. 입력은 기존 fake를 사용한 합성이라고 표시했다.
- 기존 상세 관찰 회귀를 완료까지 확장했다. 별도 완료 주석 없이 두 화면의 확인값을 합쳐
  실제 그래프·메모 경로에서 정상 종료하고 모델 호출은 0회다.
- 없는 교육 결과, 다른 교육 ID, 여러 동일 화면 후보, 다른 최종 관찰, 불완전 검토,
  같은 관찰의 더 늦은 행동 뒤에 남은 오래된 완료 계획을 수용하지 않는 경계를 확인했다.
- 변경한 기존 단언 2건: 선택하지 않은 분기와 대체된 원본 그룹을 실제 전달로 세지 않는다.
- `.\.venv\Scripts\python.exe -m pytest`: **741 passed, 3 xfailed, 42.57초**.
- Ruff check, Ruff format --check, `git diff --check`: 통과.
- 기존 xfail 3건은 선언되지 않은 클릭 대상, 미사용 0크기 필드, 보완 요청의 이전 메모 사용이며
  이번 수정 범위와 별개로 유지했다.

## 135 실제 기록을 이용한 읽기 전용 재생

기존 탐색 로그와 `assembly-draft.json`을 새 모델 호출 없이 메모리에서 재편찬했다.
인출 시험의 라이브러리·진행 상태는 임시 디렉터리에서 만들었으며 실제 기록은 덮어쓰지 않았다.

| 확인 지점 | 결과 |
|---|---|
| 편찬 그룹 수 | 12개 유지 |
| 조회 더블클릭 진입 | 이전 해시 10740855956681386027 → 9515595313367608107. 저장된 웜 조회 캡처와 거리 0 |
| 더블클릭 행동 | `[190, 187]` 유지 |
| 모델 복구 후 상세 상단 | 원본 재조회 그룹을 `used`에 넣지 않고 다음 `pagedown` 결합 성공 |
| 마지막 상세 하단 | 완료 계획과 현재 화면 6개 입력 증거 복원 성공 |
| 최종 편찬 근거 | 성공 직전 누적 검토의 11개 확인 키와 종료 관찰이 연결됨 |

원본 경로와 실행 조건은 [135 보고](memory-progress-pilot-135-20261031.md)를 따른다.
원본 호출 318·350·381의 연결 실패 지점을 오프라인에서 확인한 것이며, 신규 ERP 실행의
성공률·시간·호출 감소를 측정한 결과는 아니다.

## 남은 확인과 반증 조건

제거 구간이 업무 효과와 다음 행동의 전제조건을 보존하는지 판단하는 주체는 기존 편찬
모델이다. 이번 변경은 그 선택의 진입 관찰을 연결하며 삭제 판단 자체를 새 규칙으로 대체하지 않는다.
현재 업무 결과가 확인되지 않았는데 다음 그룹으로 넘어가거나, 현재 누적 증거가 부족한데
완료하거나, 진입 화면을 바꾸면서 유지 행동의 좌표가 달라지면 이 수정의 가설은 기각된다.
실제 ERP 재실행은 아직 하지 않았으므로 새 실행의 결과는 미확인이다.
