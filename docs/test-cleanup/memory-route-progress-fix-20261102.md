# 분할 행동 진도와 현재 관찰 기반 경로 재개 수정

2026-11-02. 사전 조사: [조건 제거 실험](route-condition-removal-audit-20261102.md).
실제 ERP·유료 호출 없이 제품 수정, 합성 회귀, 143 기록의 무료 재생을 수행했다.

## 변경

- `brain/graph/memory_retrieval.py`: 원본 그룹과 응답의 동일 행동 개수 조건과 strict zip을
  제거했다. 기존 전달 이력에 `action_progress={group_id,start,end}`를 기록하고 효과 검토가
  성공한 원본 행동의 연속 범위를 누적한다. 그룹 끝까지 연결된 경우에만 `replaced_edge`로
  소진한다. 행동 종류·순서·입력 출처·방향·viewport는 유지한다.
- 같은 파일: 휠 스크롤은 실행 경계에서 쓰던 `is_wheel_scroll`을 재사용한다. 휠 위치를
  입력칸 bbox에 귀속하는 비교를 제거했다. 일반 클릭·입력의 컨트롤 위치 비교는 유지한다.
- 같은 파일: 인출 절차와 계획은 이미 수행한 앞부분을 제외한다. 나머지 재생은 실제 suffix만
  학습 기록으로 남겨, 승격할 때 이전 입력이 중복 복원되지 않게 한다.
- 같은 파일: 다음 관찰 중 임시 진도로 준비한 suffix는 이전 효과 검토가 실패했을 때 누락된
  앞부분까지 완료로 연결하지 않는다. 행동을 새로 거절하는 규칙은 추가하지 않았다.
- `screen_mapping.py`, `screen_decision.py`: 기존 화면 응답에 선택적 `resume_group_id`를
  추가했다. 현재 모델은 같은 교육 단계 안에서도 현재 도착 위치에 맞는 다음 그룹을 지정한다.
  이전 그룹은 기존 `resumed_group_ids`에 기록하며 전달·교육 완료로 만들지 않는다.
- 모델 문맥의 두 그룹 제한을 제거하고 남은 그룹의 목적·화면 경로·행동·기대 결과를 제공한다.
  과거 좌표·입력값은 이 요약에 넣지 않는다. 실행 시 모든 유사 그룹을 경쟁시키지 않고,
  현재 진도의 첫 그룹만 결합하는 규칙을 유지한다.
- 화면 캐시의 과거 cursor는 초기화한다. 기존 `allow_recovery=False`도 유지한다.
  cursor 미지정 시 현재 교육 완료 관찰에 의한 재개는 기존대로 작동한다.
- `docs/contracts.md`, `docs/current-runtime.md`, `docs/code-flow.md`를 함께 갱신했다.
  `ScreenPlan`/`ScreenMatch` 스키마 fixture 두 개와 해시만 의도된 필드 추가에 맞췄다.

기존 스크롤·교육 프롬프트는 삭제하지 않았다. 새 안내는 현재 화면과 누적 메모로
`method_memory.methods`의 다음 그룹을 고르고, 경유 생략을 전달·교육 완료와 구분하도록 한다.
별도 모델 호출·클래스·상태 기계는 추가하지 않았다.

## 무료 재생

| 입력 | 수정 결과 |
|---|---|
| 실제 143 same seq129: 다섯 입력+다른 위치 scroll | 원본 행동 범위 `[0,6)` 연결 |
| 실제 143 changed seq128: 다섯 입력만 | `[0,5)`만 연결, 그룹 미완료 |
| 위 범위의 검토 성공을 주입하고 실제 seq166 scroll을 이어 넣은 합성 상태 | `[5,6)` 연결 |
| 실제 143 changed seq393: 다른 위치의 상세 scroll | 원본 `[0,1)` 연결 |
| 실제 조회 화면과 **합성** resume_group_id | 같은 교육 단계의 메뉴·조회 경유를 재개 이력으로 넘기고 상세 열기 그룹 유지 |

마지막 두 상태 구성은 새 실제 실행 결과가 아니다. 특히 과거 로그에는 새 cursor가 없으므로
모델이 새 프롬프트에서 이를 올바르게 선택했다는 증거로 사용하지 않는다. 원본 로그·편찬물의
SHA256 불변을 확인했다. 재생 스크립트는 비공개 `.tools/route-condition-fix-145/replay.py`다.

## 회귀와 한계

`tests/test_memory_progress.py`는 전체/분할 배치, 위치가 바뀐 휠, 검토 실패·미확인,
suffix만 재생·승격, 반대 방향 휠, 앞 검토가 실패한 뒤 준비된 suffix의 진도 연결을 검증한다.
`tests/test_memory_route_progress.py`는 의미 응답 투영부터 같은 교육 단계 내 재개까지,
캐시·미등록·현재 첫 그룹·이미 지난 그룹 지정을 검사한다. 기존 첫 화면의 순차 실행과
미입력 상태의 후속 save 선택 반례는 유지한다.

구형 배치 개수 조건을 프로세스 안에서 다시 넣는 변이 실험에서는 전체 배치는 통과하고
분할 배치 테스트는 `action_progress` 누락으로 실패했다. 따라서 원래 결함을 검출한다.

실제 API·ERP 실행은 하지 않았다. 화면 변화로 저장 기하가 결합되지 않으면 기존 모델
복구가 필요하다. 다중 스크롤 영역 간 오연결이나 모델의 잘못된 cursor 선택 가능성은 이번
무료 시험으로 해소되었다고 주장하지 않는다. 남은 경로 전체를 모델에 제공하므로 요청 크기는
늘 수 있으며, 호출 수·비용·시간 개선 여부는 미측정이다.
