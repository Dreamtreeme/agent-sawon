# 편찬 경로의 다음 단계 실행으로 후보 선택 정리

사용자의 고정 경로 실행 지시에 따라 136에서 확인한 후보 경쟁을 수정했다.
정상 인출은 편찬된 순서와 이번 입력값으로 진행하고, 예외는 기존 모델 경로로 넘긴다.
실제 ERP 실행과 유료 호출은 하지 않았다.

## 변경

- `memory_retrieval.py`: 편찬 trace 순서를 보존한다. 인출과 행동 결합은 같은
  `_matching_route`에서 선택된 메서드의 다음 그룹만 확인한다. 경로가 끝나면 완료 기억을
  사용한다. 전체 잔여 그룹 재검색과 후보 자신의 과거 완료 결과에 의한 자격 승인을 제거했다.
- `engine.py`: 인출 서비스에 전역 `completed_taught_steps`를 전달하지 않는다. 교육 진행
  메모 자체와 업무 완료 검증은 유지한다.
- 현재 모델 복구 응답의 완료 관찰만 남은 연속 선두 그룹을 건너뛸 수 있다.
  `method_route_resumed` / `resumed_group_ids`에 남기며 실제 전달 `used`와 구분한다.
  새 상태 클래스나 모델 응답 필드는 추가하지 않았다.
- 실행 전 거절로 임시 계획이 사라져도, 복구 행동을 고정된 다음 그룹과 비교한다. 같은
  행동의 실제 전달·효과 확인은 기존 `replaced_edge`로 연결한다. 다른 행동은 같은 행동으로
  취급하지 않는다.
- `screen_decision.py`: 화면 캐시 응답에는 `allow_recovery=False`를 전달하여 과거 완료
  정보로 진행 위치를 바꾸거나 거절을 해제하지 못하게 한다.
- 현행 계약·흐름·용어 문서 4개를 구현에 맞췄다. 모델 프롬프트·스키마·설정·bench는 변경하지 않았다.

## 검증 근거

수정 전 제품 코드에서 합성 회귀 6건이 실패하는 것을 확인했다. 입력과 저장 화면의 거리
0/6 충돌, trace와 교육·파일 순서의 차이, 예상 화면 불일치, 현재 모델 관찰에 의한 복구,
과거·전역 완료 정보에 의한 잘못된 건너뛰기, 완료 기억 결합을 검사한다.
기존의 과거 결과 자기 승인·런타임 교육 재정렬 단언은 새 실행 계약으로 교체했다.
거절 후 연결과 캐시 출처 검사도 추가하고, 해당 처리를 monkeypatch로 무력화하면 실패하는지
확인했다. 제품 파일에 결함을 주입하지 않았다.

136의 원본 편찬물·실제 캡처·seq169 이전 전달 이력·메모를 임시 런타임에서 재생했다.
기존에는 하단 입력과 저장 두 후보가 경쟁했지만 수정 후에는 인출과 행동 선택이 모두
`25b9f5572e9f4c1d`를 사용했다. 선택 행동은 포장 수량·단위·중량·컨테이너·출발항·도착항의
6개 fill이며 화면 거리는 0이다. 모델 호출과 ERP 입력은 0회이고 과거 파일은 변경하지 않았다.

| 검사 | 결과 |
|---|---|
| `.venv/Scripts/python.exe -m pytest -q` | 742 passed, 3 existing xfailed, 46.81초 |
| `.venv/Scripts/python.exe -m ruff check .` | 통과 |
| `.venv/Scripts/python.exe -m ruff format --check .` | 271 files 통과 |
| `git diff --check` | 통과 |

세 xfail은 기존 106 관찰 계약 항목이며 이번에 해제하거나 변경하지 않았다.

## 반증 조건과 범위

정상 경로에서 뒤쪽 저장 그룹이 현재 입력과 경쟁하거나, 가까운 다른 메서드로 바뀌거나,
경로 소진 뒤 과거 입력 그룹이 다시 선택되면 수정이 실패한 것이다. 캐시의 과거 완료 정보가
진행 위치를 바꾸거나 동일 행동 복구가 다음 그룹에 연결되지 않아도 실패다.

현재 복구 응답은 교육 단계의 완료를 표현한다. 같은 단계 안의 임의 그룹으로 재개하는 별도
모델 계약은 추가하지 않았다. 실제 호출 수·실행 시간의 개선과 ERP 전체 경로 성공은 새 화면
실행으로 검증해야 하며, 위 단일 과거 프레임 재생을 전체 실행 성공으로 해석하지 않는다.
