## 목적과 판정 원칙

같은 사실을 여러 곳에서 소유·변환·판단하여 생기는 결함과 유지보수 비용을 줄인다.
줄 수, 파일 수, 테스트 수 감소 자체는 목표가 아니다. 모델 호출도 그 자체로 낭비가 아니다.
현재 시점에 유효한 정보나 실행 가능한 계획이 이미 있는데 전달 과정에서 잃거나,
동일 사실을 중복 거절·재판단하여 다시 호출한 경우를 낭비 호출 후보로 잡는다.
새 화면, 정보 부족, 실제 행동 실패 때문에 필요한 복구 호출은 별도로 분류한다.

실제 실패 기록, 현재 코드의 경로, 합성 재현을 구분한다. 과거에 실패했다는 사실만으로
현재 코드도 결함이라고 표시하지 않는다. 현재 남은 결함 수정과 동작 보존 정리는 구분한다.

통합 가치는 줄 수 자체보다 독립 수정 위치 감소와 추가 추상화의 유지 비용으로 판단한다.

테스트만 호출한다면 그 테스트가 현재 지원 계약을 대표하는지 먼저 확인한다.

## 영향도와 기준 의미 선택

우선순위는 실제 영향, 발생 근거, 수정 위험 순으로 정한다. 잘못된 대상/값 조작·정보 유실,
업무 중단, 불필요한 호출·지연, 유지보수 부담을 구분하고 발생 실행을 연결한다.
빈도가 없는 후보를 빈번한 문제라고 추정하지 않는다. 광범위한 통합은 작은 중복보다
영향이 클 수 있으므로 의존 경계와 검증 가능성을 함께 판단한다.

기준 의미는 해당 경계에서 외부로 관찰되는 행동·효과에 가장 가까운 계약을 선택한다.
원본 모델 표현을 보존하고 실행용 표현을 한 경계에서 파생한다. 실행 전달 사실과
업무 결과 사실, 사용자 의도와 관찰 결과는 서로 다른 사실이므로 하나로 합치지 않는다.
예를 들어 완료 알림 닫기와 저장 승인 확인은 버튼명이 같아도 다른 효과다.
단어가 같거나 비슷하다는 이유만으로 어휘를 통합하지 않는다.

## 결함 주입으로 테스트 가치 확인

제품 파일의 영구 변경 없이 격리 복사본이나 테스트 monkeypatch에서 결함을 하나씩 주입한다.
예: 현재 계획 인계 제거, 완료창 정규화 제거, 활성 창 우선 선택 제거.
유료 모델이나 실제 ERP는 실행하지 않는다. 미커밋 기준선까지 포함한 복사본을 사용한다.

후보별로 원본 통과 → 변이에서 예상 assertion 실패 → 원복 후 통과를 확인한다.
import 오류·문법 오류나 무관한 timeout은 해당 결함 탐지로 세지 않는다.
변이가 살아남으면 테스트를 보강하거나 삭제를 보류한다.

테스트 삭제 전에는 결함별로 후보 테스트와 남길 테스트의 탐지 행렬을 만든다.
남길 테스트가 동일 결함을 실제로 잡는지 실행하고, 공개 계약·경계값·상태 조합 중
후보만 검증하던 것이 없는지도 확인한다. 유한한 변이 집합에서 탐지가 같다는 사실을
모든 가능한 결함에 대한 완전 중복 증명으로 과장하지 않는다.

## 후보 기록과 완료 기준

각 후보는 다음 열을 가진다.

| ID·위치 | 주 유형·파생 영향 | 책임·생산자·소비자 | 실패 영향·실행/seq | 증거 수준·현재 해결 여부 | 기준 의미/상태 소유자 | 조치·위험 | 정리 전→후 수치 | 탐지 테스트·변이 결과 | 보류 이유 |
|---|---|---|---|---|---|---|---|---|---|
| 후보마다 작성 | 복수 표기 가능 | 동적 호출 포함 | 업무 중단/오조작/지연/유지보수 구분 | 실제 기록/합성/미확인 구분 | 유지할 정의와 파생 경계 | 삭제/통합/유지/별도 결함 수정 | 아래 지표 | 후보와 잔존 테스트 각각 | 미확인 사실 명시 |

측정 단위와 분모를 고정하여 다음 값을 비교한다.

- 동일 사실의 독립 정의·쓰기 위치 수. 단순 import/읽기 위치는 중복 정의로 세지 않는다.
- 같은 대표 실행 경로에서 복사·변환 횟수와 동일 사실의 재검증 횟수.
- 불필요한 호출 후보는 재생 구간별 추가 원격 요청 수. fake 지연으로 실서비스 시간을 추정하지 않는다.
- 테스트 수·실행 시간·statement/branch coverage와 지정 결함 탐지율(탐지 수/주입 수).
  제품 코드 삭제 시 커버리지 분모가 변하므로 원래 유지 대상 라인/분기의 누락도 별도로 비교한다.

전후 실측이 없으면 미측정으로 남긴다. 각 후보는 목표 수치를 사전에 적고 결과와 비교한다.
예: 독립 정의 3→1, 같은 경로 변환 4→2, 특정 유실로 인한 추가 요청 1→0.
이는 예시이며 현재 측정값이 아니다. 파일 분리로 함수만 짧아지거나 복잡성이 다른 곳으로
옮겨졌다면 중복 감소로 인정하지 않는다.

완료는 기준 회귀 유지, 지정 변이 탐지 유지, 잔존 경로 확인, 후보별 목표 실측으로 판단한다.
코드 변경 때 lint·format·전체 테스트를 실행한다. 순수 정리의 모델 요청·실행 행동·상태
결과가 달라지면 차이를 설명하고 별도 동작 변경으로 분류한다. 테스트 정리에서는
커버리지 0.5%p 이상 하락 또는 지정 변이 탐지 감소 시 원인을 확인하고 해당 변경을 보류한다.
단일 파일럿 시간이나 모델 호출 변동을 정리 효과로 확정하지 않는다.
