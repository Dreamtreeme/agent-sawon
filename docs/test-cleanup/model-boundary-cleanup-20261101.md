# 모델 판단 주변 중복 처리 정리

기준 코드: `8df46d2`. 실제 GUI 행동 수가 아니라 같은 정보를 여러 표현으로 바꾸고
덮어쓰는 코드와, 현재 모드에서 소비하지 않는 준비 작업을 대상으로 했다.

## 적용한 변경

| 대상 | 이전 | 변경 |
|---|---|---|
| 화면 요소 이름·값 | OCR로 생성한 요소를 `_apply_field_values`가 다시 순회하며 모델 값으로 덮음 | `bind_scene`에서 권위 있는 값을 선택해 한 번 생성. 후처리 함수와 호출 3곳 삭제 |
| 의미 매핑의 OCR ID | 로컬 OCR ID → 모델용 텍스트 마커 → 로컬 OCR ID | 로컬 ID 그대로 사용. 숫자 마커 응답만 해당 변환 경계를 사용 |
| 재판단의 source | 새 매핑의 source를 같은 위치의 이전 source가 덮을 수 있음 | 이전 source 상속 삭제. 현재 매핑을 사용 |
| 저장 증거 준비 | 모델 검토 모드도 코드 검토기용 필드·행 바인딩을 생성 | 모델 모드에서는 준비하지 않음. 코드 검토 모드의 부모행 탐색은 공용 `ancestors` 사용 |
| 요청의 검토 범위 | 문맥 생성과 인출 판단이 각각 flags를 해석 | 기존 요청의 `evidence_scope`에서 한 번 계산해 공유. 지속 상태 추가 없음 |
| 미선언 행동 대상 | 변환 중 KeyError로 유효한 현재 관찰까지 유실 | 기존 `plan_error` 인계 사용. 관찰·원문을 보존하고 잘못된 실행 계획과 캐시 후보를 만들지 않음 |

첫 응답뿐 아니라 빈 행동 보완의 미선언 대상도 같은 경계를 사용해야 한다는 점을
코드 검토에서 발견했다. 기존 합성 회귀를 두 호출 경로로 확장하여 확인한다.
프롬프트 문구, 모델 응답 스키마, 업무 완료 조건은 변경하지 않는다.
선택 → 검증 → grounding의 일반·메서드 fallback 중복 블록을 같은 오류 경계로 합쳤다.
메서드가 거절된 뒤의 fallback은 기존처럼 최대 한 번이며 새 모델 재시도는 추가하지 않았다.

제품 코드 7개 파일은 143줄 추가·161줄 삭제로 순감 18줄이다. 관찰 유실을 막는 처리가
함께 들어갔으므로 대규모 코드 축소로 해석하지 않는다. 이름·값 후처리 함수와 독자적인
부모행 순회 함수를 제거하고, 검토 범위 파생 속성 하나를 추가했다.

## 삭제하지 않은 항목

- 스크롤의 모델 표현과 실행·저장 표현은 서로 다른 계약이다. 통일하려면 저장된
  메서드와 실행 소비자까지 변경해야 하므로 단순 중복으로 삭제하지 않았다.
- `_remaining_groups`의 실제 전달, 검토된 대체, 모델이 확인한 재개, 검토 대기는
  서로 다른 사실이다. `used`에 합치면 생략을 실제 전달로 기록하므로 유지했다.
- `screen_matching=False`에서도 인출 콜백이 연결된다. 이 설정에서 도달 가능한
  scanner의 보충 경로를 미사용으로 간주하지 않았다.
- 입력 전달과 화면에서 읽은 값, 저장 전 입력 확인과 저장 후 상세 확인은 계속 구분한다.

## 검증 범위

기존 테스트를 수정·확장했다. 합성 106의 미선언 click 테스트는 strict xfail을 해제하고,
현재 값 보존, 원문 행동 보존, 실행 steps 제거, 캐시 후보 없음, 실제 전달 없음까지 확인한다.
같은 캡처에서 입력 키를 교정하는 기존 테스트와 scene의 일반 OCR·모델 값·값 생략·빈칸·
비밀값 마스킹 테스트도 사용한다. 모델/코드 검토 모드의 부모행 바인딩은 같은 기존 테스트로 비교한다.

실제 ERP와 유료 모델은 실행하지 않았다. 실행 시간이나 모델 호출 감소를 실측한 변경은 아니다.
기존 예상 실패인 미사용 0 크기 영역과 빈 행동 보완의 이전 메모 문제는 이번 변경에서 해결하지 않는다.
