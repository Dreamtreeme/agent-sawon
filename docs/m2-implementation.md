# M2 구현·재적용 작업 기록

2026-09-29 사용자 지시: “그러면 m2까지 구현한뒤 다시적용”.
M2 3·4단계 구현까지 범위를 확장한다. M1 미완료 측정, 사람의 종료 점검,
D3–D8 등 제안 결정은 자동 승인하거나 완료로 바꾸지 않는다.

## 구현과 통합 순서

- [x] 현재 관찰 기반 업무 근거 검토를 그래프 책임으로 분리한다.
- [x] 식별자·필드 근거 부족과 실제 중복·불일치를 구분하고 한도 내 복구한다.
- [x] 의미 기반 캐시 저장·조회·갱신·실패 재시도/무효화와 cache.enabled를 구현한다.
- [x] 중계의 관찰 전용 시연 기록과 값 변화의 의미 입력 변환을 구현한다.
- [x] 검증한 캐시 행동과 모델 행동이 동일한 현재 상태·실행·사후 검사를 거치게 한다.
- [x] 공공 코드 자료의 다운로드·출처 기록, 합성 HBL/송장/포장명세서 PDF를 구현한다.
- [x] 미취합·중량 차이·개수 차이·품명 차이·컨테이너 오류와 팩스풍 열화를 구현한다.
- [x] PaddleOCR·측정 비전 모델 추출, 위치 근거, 교차 검증 기반 확신도를 구현한다.
- [x] 차단 오류가 있는 추출 결과는 입력하지 않고, 준비된 추출 레코드를 Brain에 연결한다.
- [x] fake/replay 회귀 검사와 양 저장소 필수 검사를 수행한다.
- [x] 동일 조건의 캐시 전후 및 서류 오류 측정과 실제 화면 재적용을 수행한다.
- [x] 연속 환경 실패 중단, 팩스 원본·처리 OCR 근거 보존, 엄격한 필드 비교를 보완한다.
- [x] 계획된 전체 분모를 유지하는 3회 반복 서류 측정 CLI를 구현한다.
- [x] 빈 캐시·고정 스냅샷에서 시작하는 독립 실행과 초기/최종 무결성 기록을 구현한다.

## 고정 경계

두뇌의 환경 접근은 relay뿐이다. 캐시는 관찰 ref·좌표·AutomationId·입력값·자격증명을
영속 저장하지 않으며 현재 관찰의 의미 대상에 다시 대응한다. 새 경로의 검증 전 승격,
과거 관찰을 합쳐 현재 행 검증으로 간주하는 처리, 실제 기업/평가 시드 사용은 하지 않는다.
테스트는 fake/replay, 실제 모델은 ModelClient 비용 한도를 거친다. 데이터 생성 정답은
채점 전용이며 추출기와 모델 입력에 섞지 않는다. 영속 경험 학습과 실행 중 상태는 구분한다.

## 측정 상태

기능 구현·회귀 검사·개발 파일럿과 재적용을 완료했다. 최신 후속 코드의 일반 테스트는
비공개 513개, 벤치마크 476개 통과(GUI 5개 제외)이며 양쪽 린트·포맷 검사를 통과했다.
아래 [이전 실측 보고서](../../agent-sawon-bench/evidence/m2/README.md)는 실패·미실행을 포함한
최초 M2 파일럿 기록이다. 당시 수치와 실패는 덮어쓰지 않는다.

- 경량 기본+상위 1회 복구로 화면 완료 4건, 모두 저장·최종 조회 10/10, 중복·무권한 전송 0.
- 비교 표본: 캐시 없음 28호출/$0.0531266/64.19초 → 캐시 19호출/$0.03675117/52.72초.
- 한글 서류→OCR·비전→검사→ERP→결재 대기 통과: 총20호출/$0.03891301.
- 오류 6조건 모두 탐지, 정정 판정 7/8. 정상 팩스는 2개 OCR 오독을 교차 검증이 발견해 차단했다.
- 이 파일럿 이후의 반복 검증·팩스 개선은 별도 후속 기록으로 구분한다.

[후속 반복 검증](../../agent-sawon-bench/evidence/m2-followup-20260929/README.md)은 개발 서류
8조건×3회, 총 24/24회 기대한 결과를 냈다. 일반 서류 7조건은 경량 모델, 정상 팩스는
원본·처리 OCR과 상위 모델을 사용했다. 정상 팩스3/3 준비 통과, 전체 오류18/18 탐지,
63호출/$0.2432193이며 새 API 오류·비용 미확정은 없다. 별도 진단9호출/$0.0496498은 제외한 수치다.
미취합 사전 차단3건도 계획 분모에 남겨 대표 필드는 합계210/240이며 서류별630/690이다.
각 조건의 동일 시드 0 입력을 반복한 개발 결과이고, 이번 반복에서는 ERP 화면 입력을 실행하지 않았다.

[새 개발 시드17 검증](../../agent-sawon-bench/evidence/m2-seed17-20260929/README.md)도
동일한 8조건×3회에서 기대 판정24/24, 오류18/18 탐지, 정상 팩스3/3 준비 통과를 기록했다.
대표 필드210/240·서류별630/690이며 미취합3건의 미추출을 분모에 남겼다.
일반21회는 경량 기본 OCR, 팩스3회는 상위 모델과 원본·처리 OCR을 사용했다.
새 캠페인은63호출/$0.25255065, API 오류·비용 미확정0이며 코드·입력·설정 해시는 유지됐다.
최초24건 계획은 요약 교체 오류 전1건만 완료(3호출/$0.0084713)하고23건은 시작하지 못했다.
수정 후 새 계획24건과 별도로 보존하며, 두 계획 합계는48건 중25건 평가·23건 미시작이다.
최초 중단분을 포함한 서류 비용은$0.26102195다. 이 결과는 서류 준비 검증이며 ERP 실행과
평가용 시드 일반화는 검증하지 않았다. 이번 화면 시도까지의 확인 비용 합계는$0.37545613이다.

현재 [코드 흐름](code-flow.md)을 갱신했다. M2 실행 설정은 `config/brain.m2.toml`,
캐시 없는 동일 복구 정책은 `config/brain.m2-no-cache.toml`이다. 문서 처리 설정과 한글 OCR은
`config/pipeline.toml`, `config/pipeline.korean.toml`이며 `pipeline.workflow`가 하네스와 연결한다.

## 다음 화면 비교의 시작 조건

`config/harness_agents.cache-isolated.json`은 캐시 없음, 빈 캐시, 고정 스냅샷의 세 조건을
같은 모델·복구 정책으로 비교하도록 준비한 예시다. 고정 스냅샷은 학습 건과 비용을 따로 기록한 뒤
명시적으로 제공해야 한다. 기존 전역 캐시나 이전 반복의 최종 상태를 암묵적으로 재사용하지 않는다.
각 새 건에 초기 사본·작업 사본·해시·완료 무결성을 남기며 초기 또는 최종 자료가 손상되면
완전한 비교 근거로 간주하지 않는다. 업무 실패·중단 기록도 그대로 보존한다.

현재 격리 옵션은 수기 레코드의 새 `brain.run` 건에 적용된다. `--prepared-case`로 들어오는
서류→ERP 건은 별도 연결 작업이 필요하다. 자세한 사용법은 [캐시 안내](../brain/cache/README.md)에 있다.
이 격리 기능의 테스트 통과를 실제 화면 효율 향상이나 캐시 실패 복구율로 표시하지 않는다.

후속 실행에서 새 cold 학습이 저장·최종 재조회10/10으로 성공해 11개 항목을 고정했다.
캐시없음/cold/고정snapshot × 시드0/17 × 3회, 18건 계획 중 첫 캐시없음1건은 성공했고
다음 ERP의 전경 활성화 거부로1건 실패·16건 취소됐다. 같은 시드·반복의 세 조건이 모두 성공한
묶음이 없어 효율 차이는 산출하지 않았다. [격리 비교 기록](../../agent-sawon-bench/evidence/m2-isolated-cache-20260929/README.md)에
학습 비용, 처음 중단한 학습 시도와 전체18건 분모를 보존했다.
별도 [시작 진단4회](../../agent-sawon-bench/evidence/m2-desktop-startup-20260929/README.md)는
모델 호출 없이도 동일한 전경 활성화 거부를 재현했다. 외부 전경 스레드 연결은 Windows 오류5를
반환했고 최소 프로세스 조회도 거부됐다. 모델 차이나 사용자 조작으로 단정하지 않는다.
일반 권한의 전경 환경 또는 전용 데스크톱에서 시작 확인을 통과해야 캐시 행렬을 재개할 수 있다.

이 과정에서 외부 에이전트가 success를 남긴 뒤 비정상 종료해도 ERP 결과만으로 성공 처리되던
하네스 경계를 수정했다. 독립 ERP 채점과 실행의 정상 종료를 구분하며 캐시 증거의 완결성도 별도로 검사한다.
또한 개발 시드17 서류 측정의 요약 교체 접근 거부와 같은 오류를 Windows 읽기 핸들로 재현하고
제한된 재시도를 보완했다. 최초 거부의 정확한 주체는 확정하지 않았다.
일시적인 Windows 오류5/32/33만 최대6회, 합계0.775초 대기하며 동일한 완성 임시 파일을 교체한다.
기존 파일을 먼저 삭제하는 대체 경로는 없고, 계속 실패하면 원본과 실패 기록을 보존한다.

남은 작업은 추가 개발 서류 시드·변형, 위 조건의 GUI 반복 비교와 실제 캐시 실패 복구,
사람 시연의 수기 검증, 전용 VM의 전경 안정화, M1 전체 매트릭스와 D6–D8 결정이다.
기능 구현 완료가 마일스톤 종료 승인이라는 뜻은 아니다.
