# 108: 과거 실제 ERP 캡처 48쌍의 화면 변화 판정 비교

## 결론

현재 pHash 완전일치 비교는 이 표본에서 오탐 8건·미탐 2건이다. 거리 6을 허용하면
오탐은 1건으로 줄지만 미탐이 12건으로 늘었다. SSIM 평균은 오탐 1건·미탐 0건,
ORB 기반 비교는 오탐 0건·미탐 2건이었다. 이는 이 데이터와 아래 임계값의 결과이며
알고리즘 전체의 우열이나 운영 정확도를 확정하는 결과가 아니다.

제품 코드·설정·프롬프트는 변경하지 않았다. 새 ERP, 모델 API, OCR 실행도 없다.
기존 로컬 OpenCV 4.10.0의 quality 모듈을 사용했으며 의존성을 설치하지 않았다.

## 자료 선정과 사람이 확인한 기준

086, 088, 089, 103, 104, 105, 106, 107 계열의 43개 run_log를 조사했다.
`action_transition` 중 navigate/select_tab/search/confirm_save/save/login의 전후 캡처가
존재하고 크기가 같은 204쌍을 찾았다. 이미지 파일 SHA-256 전후 쌍이 중복된 것을 제거하면
65쌍이다. 크기가 다른 창 전환은 이번 평가에서 제외했다.

- pHash 거리 1~6인 17쌍 전부.
- 거리 0인 18쌍 전부.
- 거리 7 이상 30쌍 중 고정 random seed 108로 선택한 13쌍.
- 합계 **48쌍(전후 이미지 96개 위치), 20개 실행**. 같은 이미지를 공유하는 쌍은 있으므로
  독립적인 48회 실험이나 고유 이미지 96장이라고 해석하지 않는다.

모든 쌍의 좌우 이미지를 직접 검토했다. 판정은 **내용·viewport 위치가 바뀌었는가**이며,
사업 성공이나 원래 목표를 달성했는가와 다르다. 스크롤로 새 입력이 드러나지 않았어도
내용 위치가 실제로 이동했다면 변화로 분류한다. 커서·포커스·스크롤바 hover 장식은 무변화다.

| 육안 분류 | 쌍 수 |
| --- | ---: |
| 실제 스크롤 | 18 |
| 기본/추가 탭 전환 | 4 |
| 조회 입력·상태 문구 변화 | 2 |
| 포커스·커서 변화만 있음 | 10 |
| 내용과 위치 유지, 일부 스크롤바 표시 변화 포함 | 14 |
| 합계 | 48 |

최초 분류는 측정 전에 저장했다. 결과 불일치를 조사하면서 P06을 원본 크기로 다시 보니
필드 위치는 같고 커서·스크롤바만 달라, scroll에서 focus_caret로 **1건 정정**했다.
최초 labels, 정정 사유, 최종 labels를 모두 보존했다. P26/P33은 원본 크기에서도 내용이
조금씩 위로 이동함을 확인했다. 표본 내 재검토이므로 독립 holdout 검증이 아니다.

**48건 모두 과거 오류였다고 주장하지 않는다.** 기록의 changed/no_change와 화면 검토가
다른 것은 10건이다. 35건은 pHash 0~6의 어려운 후보, 13건은 대조군이다.

## 비교 구현과 사전 지정 임계값

분류 대상은 같은 크기의 캡처 쌍이다. OpenCV 방법들은 grayscale, 긴 변 최대 960px로
동일 축소했다. 회사별 ROI, 모델 응답, OCR 텍스트, 정답 행동은 알고리즘에 넣지 않았다.
아래 임계값을 정해 첫 측정을 실행했으며 결과를 보고 수치를 최적화하지 않았다.

| 방법 | 변화 판정 |
| --- | --- |
| 현행 pHash | distance > 0 |
| pHash 거리 허용 | distance > 6 |
| SSIM 평균 | `cv2.quality.QualitySSIM_compute` 평균 < 0.995 |
| SSIM 차이 영역 | 국소 SSIM < 0.9인 픽셀 비율 > 0.5% |
| 허용 오차 픽셀 차이 | 밝기 차이 > 24/255인 픽셀 비율 > 0.5% |
| 전체 위상 상관 | phaseCorrelate 응답 >= 0.3이면 이동량 > 3px; 응답 미달은 unknown |
| 4×4 영역 위상 상관 | 위 기준을 만족하며 이동한 영역 >= 4개 |
| Optical Flow | 최대 600 특징점, LK 전후 왕복 오차 < 1.5px, 유효점 >= 20; 3px 초과 이동점 비율 > 15% |
| ORB 특징점 | 최대 1200점, Hamming 0.75 ratio 매칭 >= 20; 3px 초과 이동 비율 > 15% 또는 매칭 비율 < 50% |

ORB는 특징점 대응·이동 비율 비교이며 별도 RANSAC/homography 정합은 사용하지 않았다.
픽셀 비교는 numpy/OpenCV 허용 오차 비교이며 Pixelmatch 라이브러리/AA 제거 구현이 아니다.
SSIM의 영역 비율도 후보 구현 하나일 뿐, 의미 있는 변화 영역을 자동 이해하는 모델은 아니다.

## 결과

양성 24쌍(내용·위치 변화), 음성 24쌍(커서·포커스 등만 변화/무변화).
오탐은 음성을 변화로, 미탐은 양성을 무변화로 판정한 수다. unknown은 정답에 포함하지 않는다.

| 방법 | 정확 판정 / 48 | 오탐 | 미탐 | unknown | 중앙 처리시간 ms |
| --- | ---: | ---: | ---: | ---: | ---: |
| pHash 완전일치 | 38 | 8 | 2 | 0 | 20.49* |
| pHash 거리 6 | 35 | 1 | 12 | 0 | 20.49* |
| SSIM 평균 | 47 | 1 | 0 | 0 | 21.08 |
| SSIM 차이 영역 | 40 | 8 | 0 | 0 | 21.08 |
| 허용 오차 픽셀 차이 | 46 | 2 | 0 | 0 | 0.51 |
| 전체 위상 상관 | 26 | 0 | 15 | 7 | 16.04 |
| 4×4 영역 위상 상관 | 33 | 0 | 15 | 0 | 8.23 |
| Optical Flow | 35 | 0 | 13 | 0 | 15.73 |
| ORB 특징점 | 46 | 0 | 2 | 0 | 22.75 |

각 OpenCV 방법은 쌍마다 워밍업 1회 후 5회 반복의 중앙값, 표는 다시 48쌍의 중앙값이다.
OpenCV 스레드는 1개로 고정했다. 이미지 읽기·축소는 제외했다.
* pHash는 **현재 제품 함수 그대로 파일 읽기까지 포함하여** 3회 반복했다.
따라서 시간 열은 동일 범위의 엄밀한 속도 순위가 아니다. 기존 카탈로그의 사전 계산된
pHash끼리 비교하는 비용은 이 값보다 훨씬 작다. SSIM 평균과 차이 지도는 같은 호출로 나온다.

## 판단과 다음 검증

1. 거리 6으로 바꾸기만 하는 안은 이 표본에서 현행보다 오류가 많으므로 채택 근거가 없다.
2. SSIM 평균은 우선 검토 후보지만 포커스 변화 P16을 해결하지 못했다. 임계값을 이번 자료에
   맞춰 낮춰서 끝내지 않고, 다른 실행의 작은 팝업·버튼 상태 변경·로딩·창 크기 변화를
   별도 검증해야 한다.
3. ORB는 스크롤·탭 분리에 유리했지만 작은 결과 문구를 놓쳤다. 업무 결과 판정을 맡길 수 없다.
4. 전체 화면 유사도와 행동 효과를 동일한 의미로 취급하지 않는다. 실제 스크롤이 있었다는
   사실과 찾던 입력칸이 노출됐다는 사실도 별개다.
5. 현재는 기존 알고리즘과 후보 수치를 함께 기록하는 오프라인/관찰 비교 단계가 적절하다.
   제품 경로 교체는 승인·추가 검증 없이 수행하지 않았다.

이 데이터는 기존 실패 주변을 과대표집했고 같은 화면·인접 프레임을 공유한다.
통계적 일반화, 독립 성공률 또는 47/48 운영 보장은 주장하지 않는다.
