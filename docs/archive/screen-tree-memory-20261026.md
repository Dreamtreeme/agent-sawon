# 화면 탐색 기억과 입력 전달 이력의 연결

2026-10-26. 실제 파일럿 116 이후 코드 변경과 무료 회귀 검증 기록.
현재 계약은 [contracts.md](../contracts.md)의 화면 노드 선택과 관찰 기억을 따른다.

## 변경 이유

116 시드 1에서는 상단 입력 5개와 스크롤을 연속 실행했다. seq 175 응답은 상단을 입력했다고
설명했지만, 하단 입력 뒤 seq 217 요청의 확인된 입력은 비어 있고 직전 전달 이력은 하단만
남았다. 등록 노드에는 서로 다른 관찰의 상·하단 bbox가 함께 있었다. seq 217 응답은 현재
보이지 않는 상단 필드를 빈 값과 과거 bbox로 다시 선언했다. 과거 상단 bbox 5개와 응답의
5개가 모두 같았으며, 이후 화면에서 항구 필드에 수입자/품명이 입력된 것을 확인했다.

이 변경은 전달 이력의 수명과 모델용 기억 표현을 수정한다. 모델이 어떤 화면 의미를 선택할지
규칙으로 강제하거나, 과거 좌표를 스크롤 절대좌표로 변환하는 변경은 아니다.

## 구현

- `screen_memory.py`: 기존 경로 인덱스를 단일 저장소로 사용한다. 방문한 부모/자식 노드에
  업무 키별 필드와 이름별 컨트롤을 누적한다. 안 보이는 항목은 보존한다.
- `engine.py`: 관찰 기록은 기존 갱신 경로를 사용한다. relay가 성공을 반환한 입력은 해당
  노드 필드의 delivery에 값과 범위를 기록한다. 전달 직후 기존 수첩 JSON을 저장한다.
  부분 실패에서 미전달 입력은 기록하지 않는다.
- `context_recall.py`: 상태 인덱스를 중첩 `screen_tree`로 투영한다. 과거 bbox/ref/관찰 ID를
  이 트리에 노출하지 않는다. 마지막 관찰값과 입력 전달 이력을 분리한다. 같은 증거 범위의
  누적 확인 대기를 모델에 전달한다.
- `screen_mapping.py`: 트리 읽는 법, 마지막 관찰과 현재 가시성의 차이, 미확인과 미입력의
  차이를 설명한다. 모델 응답 스키마와 행동 거절 조건은 바꾸지 않았다.
- 현재 계약·실행 기준·흐름 문서를 함께 갱신했다. bench와 실행 설정은 변경하지 않았다.

입력 상태는 전달 후 `awaiting_observation`, 후속 읽기 결과에 따라 `observed_match` 또는
`observed_mismatch`다. 전달은 verified나 ERP 저장 성공으로 취급하지 않는다. entry 이력을
saved_detail 확인 대기로 넘기지 않는다. `seen_in_last_view`는 해당 노드의 직전 관찰에 포함된
것이며 새 캡처에서 보인다는 뜻이 아니다. 현재 좌표는 현재 화면 판단에서 정한다.

이름/주석에 명시했다. 실제 모델이 새 문맥을 보고 올바르게 선택했다는 검증은 아니다.

## 반증 조건과 남은 확인

- 다음 배치 뒤 앞선 입력 delivery가 없어지거나 미전달 입력이 기록되면 구현 실패다.
- 다른 탭·저장 범위의 사실이 현재 확인 완료로 승격되면 계약 위반이다.
- 모델 요청의 screen_tree에 과거 실행 좌표가 다시 포함되면 이번 분리의 목적을 충족하지 못한다.
- 위 조건을 만족해도 실제 모델이 현재 화면을 잘못 읽을 수 있다. 실제 ERP·유료 호출은 이번에
  실행하지 않았으며 모델 오류 감소나 실행시간 개선은 아직 측정하지 않았다.
