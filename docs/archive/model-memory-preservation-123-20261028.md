# 123 후속: 모델의 누적 메모를 OCR로 대체하던 처리 수정

이 문서는 조사·변경 기록이다. 현행 계약은 `../contracts.md`와 `../current-runtime.md`를 따른다.

## 잘못 구현한 부분

123 실행의 요구는 정상 기억 인출에서 모델이 누적해 확인한 정보를 재사용하고 예외에서만
모델을 호출하는 것이었다. 제품 커밋 `4f13488`은 경로·필드·행동을 복원했지만 확인값은
OCR에서 다시 만들었다. 보고 커밋 `5fdfd11`의 실행 결과가 이 차이를 드러냈다.

확인값이 사라지는 곳은 두 군데였다.

1. `method_from_match`와 `method_completion_from_match`가 필드 기하·입력 키만 편찬하고
   모델이 읽은 `value`는 보존하지 않았다.
2. `ScreenScanner._semantic_request`의 기억 필드 준비와 `MemoryRetrieval._restore_mapping`이
   OCR 문자열을 합쳐 `value`에 넣었다. 모델이 보정한 해석을 원시 OCR로 대체한 것이다.

123의 탐색 프레임과 인출 프레임은 1182×956의 RGB 픽셀 및 OCR 블록(문자열·좌표·확신도)이
같았다. RGB SHA256은 둘 다
`0d1e03e826213a8ff6276f5aeae6b5463e73697bc778790c34239a5499ca1b4a`이다.
품명 OCR은 `Syiueuie`, `Sampe pa`였고 탐색 모델은 `Synthetic sample parts`로 해석했다.
인출의 OCR 대입은 이를 `Syiueuie Sampe pa`로 바꿔 `delivered_value_not_observed`를 만들었다.
따라서 이 사례를 OCR 재실행의 불안정성으로 설명한 것은 잘못이다.

## 수정한 계약

- 행동 그룹과 최종 완료 기억에 `field_values`를 보존한다. 입력과 일치한 모델 확인값은
  `{"source": "description"}`처럼 현재 업무 입력에 연결한다. 다른 읽은 값은 그대로 보존한다.
- 명시적 빈 문자열, 읽은 값 생략, 확인값이 없는 과거 산출물(`None`)을 구분한다.
- 정상 인출은 선택된 그룹의 확인값과 이번 실행의 같은 노드·증거 범위에 누적된 메모를 사용한다.
  마지막 입력 전달 이후 더 새로 확인한 메모가 있으면 그 값을 우선한다.
- OCR은 현재 관찰 자료로 계속 제공하지만 인출 메모의 값을 다시 작성하지 않는다.
- 보이지 않는 이전 필드는 노드 메모에 남는다. 과거 산출물의 누락된 확인값은 OCR로 메우지
  않고 기존 복구 경로를 사용한다. 원래 로그에 매핑이 남아 있으면 유료 호출 없이 재편찬 가능하다.
- 프롬프트, 모델 응답 스키마, 설정, relay 및 화면 유사도 기준은 변경하지 않았다.

## 검증

합성 회귀 시험은 실제 관찰·검토·실행기·메모 코드를 연결한다. 읽을 수 있는 OCR과 잘못된 OCR
두 경우 모두 모델 메모로 입력 2건 → 다음 버튼 → 완료까지 진행하며 추가 모델 호출은 0회다.
현재 화면에 없는 기존 필드가 보존되고, 모델이 새로 수정한 값이 편찬 값보다 우선함도 확인한다.
기존의 “OCR 불일치이면 모델을 호출한다”는 단언은 잘못된 계약이므로 제거하고 이 단언으로 대체했다.
편찬·완료 시험은 입력 키 참조, 새 record 연결, 명시적 빈칸과 생략의 차이를 검증한다.

123의 원본 탐색 로그와 저장된 편찬 모델 응답으로 임시 기억을 다시 만들고, 인출 seq 162 직전
화면에 결합했다. 원본 증거·편찬물은 수정하지 않았다. 실제 API와 ERP는 호출하지 않았다.

| 항목 | 원래 123 인출 | 수정 코드의 읽기 전용 재생 |
|---|---|---|
| OCR | `Syiueuie Sampe pa` | 동일 |
| 품명 메모 | OCR 원문으로 대체 | `Synthetic sample parts` 복원 |
| 다음 행동 | 값 불일치로 모델 복구 | 기존 6개 fill 복원 |
| 행동 좌표 | 모델이 다시 선택 | 저장 좌표 재사용 |
| 이 재생의 모델 호출 | 해당 없음 | 0회 |

입력 record의 품명을 다른 문자열로 바꾼 합성 변형도 이전 문자열 대신 새 입력을 참조했다.
이는 입력 키 재결합 검증이며 해당 변형의 실제 화면 값이 맞았다는 검증은 아니다.

실행 명령은 루트 `.venv`의 `python -m pytest -q --tb=short`, `python -m ruff check .`,
`python -m ruff format --check .`, `git diff --check`이다. 전체 테스트는 728 passed,
3 xfailed이며 기존 106 관련 예상 실패 3건은 변경하지 않았다. 린트·포맷 검사를 통과했다.

## 확인 범위

이 검증은 123의 첫 OCR 대체 문제와 모델 메모 보존을 확인한다. 실제 ERP의 새 실행 시간,
전체 모델 호출 감소, 저장 성공률은 다시 측정하지 않았다. 123 후반의 대체된 원본 그룹을
다음 후보에서 제외하지 못한 문제는 이번 수정 대상이 아니다. 원래의 9회 모델 호출이 모두
제거되었다고 주장하지 않는다.

반증 조건은 같은 노드의 더 최신 모델 확인값이 OCR 또는 이전 편찬 값으로 덮이거나,
명시하지 않은 값이 빈칸으로 저장되거나, 현재 업무 값 대신 과거 입력 문자열을 복원하는 경우다.
