# 109: 화면 비교 상위 3개 후보 확대 정밀 비교

## 결론

108의 48쌍에서 신규 96쌍을 더해 **144쌍, 54개 실행**으로 확대했다.
기존 임계값을 고정했을 때 전체 오류는 ORB 3건, 허용 오차 픽셀 비교 6건,
SSIM 평균 9건이었다. **108의 ‘SSIM 우선 후보’ 판단을 그대로 유지할 근거는 없다.**
다만 ORB의 미탐 3건은 모두 조회 입력·상태 문구 변화다. 구조 변화에는 강하지만
작은 업무 상태 변화를 확인하는 단독 수단으로 선택하기 어렵다.
제품 코드·설정·프롬프트는 변경하지 않았다. ERP/API/OCR 실행 및 유료 호출은 없다.

## 자료와 판정

- 신규 조사: 071~082 계열과 seed3-recheck-09 계열 75개 로그, 조건에 맞는 361쌍.
- action_transition의 navigate/select_tab/search/confirm_save/save/login 중 전후 캡처가 있고 크기가 같은 쌍.
- 파일 SHA-256 전후 쌍 중복 및 이전 표본 중복 제거 후 97쌍. 고정 seed 109로 96쌍 선택.
- 거리 0/1~6/7 이상 각 32쌍을 목표로 하고, 부족분을 남은 후보로 채웠다.
  각 거리 구간 안에서는 intent별 순환 선택했다. 운영 빈도를 대표하는 무작위 표본이 아니다.
- 신규 96쌍은 34개 실행: 1182×956 79쌍, 1262×786 14쌍, 572×316 팝업 3쌍.
- 합계 144개의 고유 방향 있는 이미지 쌍. 디코딩한 픽셀 기준으로도 144쌍이다.
  고유 이미지는 141장, 방향을 무시하면 135쌍이다. 신규/기존 사이에 이미지 5장을 공유한다.
  288장의 독립 사진이나 144회의 독립 실행으로 해석하지 않는다.
- 모든 신규 쌍의 좌우 캡처를 직접 확인했다. 모호한 작은 이동과 오류 후보는 원본 크기 crop을 확인했다.
- 양성: 실제 내용/viewport 변화. 음성: 같은 내용·위치에서 커서/포커스/선택 표시만 변화.
  이는 업무 성공 판정도, 같은 화면 노드라는 정체성 판정도 아니다.
- 표 셀의 선택/편집 포커스만 바뀐 3건은 별도 분류하고, 이를 양성으로 바꾸는 민감도도 계산했다.

| 분류 | 기존 | 신규 | 합계 |
| --- | ---: | ---: | ---: |
| 스크롤 | 18 | 41 | 59 |
| 탭 변경 | 4 | 5 | 9 |
| 조회 입력/상태 문구 | 2 | 1 | 3 |
| 입력값 변경 + 위치 이동 | 0 | 1 | 1 |
| 저장 확인 → 완료 팝업 | 0 | 3 | 3 |
| 같은 내용/포커스/커서 | 24 | 42 | 66 |
| 표 셀 선택만 변경 | 0 | 3 | 3 |

최초 판정은 측정 전에 저장했다. 측정 불일치 뒤 원본 확대 확인으로 6건을 정정했다:
N023은 약 5px 실제 이동, N031은 조회 결과 0건 유지와 포커스만 변경,
N039/N046/N047/N057은 필드 위치 유지와 커서·스크롤바 변화였다.
최초/최종 라벨과 정정 사유를 보존했다. **라벨 재검토가 있었으므로 독립적인 맹검 holdout 결과는 아니다.**

## 고정한 구현과 측정 조건

OpenCV 4.10.0, CPU 단일 스레드, 회색조, 긴 변 최대 960px INTER_AREA 축소.
각 쌍·방법 워밍업 1회, 측정 5회 중앙값. 읽기/디코딩/축소 시간은 알고리즘 시간에서 제외했다.
동일 PC의 로컬 반복 측정이며 CI나 실제 작업자 지연 측정이 아니다.

| 방법 | 기존부터 고정한 변화 조건 |
| --- | --- |
| SSIM 평균 | QualitySSIM_compute의 평균 < 0.995 |
| 허용 오차 픽셀 | absdiff > 24인 픽셀이 전체의 0.5% 초과 |
| ORB | 최대 특징점 1,200개, Hamming kNN + 0.75 ratio; 매칭 20개 이상일 때 3px 초과 이동 비율 > 15% 또는 coverage < 50% |

ORB는 RANSAC/호모그래피를 사용하지 않는다. 특징점 매칭이 20개 미만이면 unknown이다.
이 자료에서는 세 방법 모두 unknown이 없었다. 픽셀 비교는 Pixelmatch 라이브러리가 아니며
색상 거리/안티앨리어싱 특수 처리가 없는 회색조 허용 오차 비교다.

## 실패 유형별 정밀 비교

스크롤 59쌍, 탭 9쌍, 팝업 3쌍, 입력값+위치 1쌍은 세 방법이 모두 검출했다.
차이는 아래 장면에서 발생했다.

| 장면/ID | 화면 직접 확인 | SSIM | 픽셀 | ORB |
| --- | --- | --- | --- | --- |
| P37/P47/N052 | 조회 입력 또는 안내 문구가 조회 결과로 변경 | 모두 검출 | 모두 검출 | 3건 모두 미탐 |
| N031/N034/N037/N040 | 조회 입력의 포커스 선만 생기거나 사라짐 | 4건 오탐 | 모두 무변화 | 모두 무변화 |
| N033 | 수하인 → 품명으로 입력 포커스 이동, 내용 유지 | 오탐 | 무변화 | 무변화 |
| N071/N077/N093 | 빈 표 셀의 선택·편집 포커스만 변경 | 3건 오탐 | 3건 오탐 | 모두 무변화 |
| N076 | 조회 결과 행은 같고 선택 헤더 표시만 변경 | 무변화 | 오탐 | 무변화 |
| P16 | 포커스/스크롤바 표시 변화, 내용 유지 | 오탐 | 오탐 | 무변화 |
| P43 | 버튼 포커스 변화 | 무변화 | 오탐 | 무변화 |

**N052:** 안내 문장이 짧은 조회 결과 문장으로 바뀌지만 대부분 화면은 빈 표로 유지된다.
SSIM=0.983130, 픽셀 변화율=0.5398%, ORB 이동 매칭 비율=6.43%, coverage=66.88%.
ORB의 두 조건을 모두 넘지 않아 미탐한다. ‘화면 구조 유지’와 ‘상태 문구 변경’이 공존하는 반례다.

**N033:** 긴 입력 포커스 선 두 개의 변화가 SSIM=0.989694를 만들어 0.995를 넘지 못한다.
픽셀 변화율은 0.4355%, ORB 이동 비율은 0.285%로 무변화다.
SSIM은 작은 변화에도 반응하지만, 그 변화가 업무상 필요한지 자체적으로 구분하지 않는다.

**N076:** 선택 헤더의 색/밝기 변화에 픽셀 비율 0.6748%가 반응한다.
SSIM=0.999448이므로 구조는 거의 같다. 픽셀 비교도 의미 분석을 대신할 수 없다.

## 판정 목적에 따른 순위 변화

표 선택만 바뀐 3건도 의미 있는 변화로 포함하면:

| 방법 | 오탐 | 미탐 | 정답 |
| --- | ---: | ---: | ---: |
| SSIM | 6 | 0 | 138/144 |
| 픽셀 | 3 | 0 | 141/144 |
| ORB | 0 | 6 | 138/144 |

이 경우 픽셀이 1위다. 따라서 ‘화면 노드가 바뀜’, ‘스크롤 위치가 바뀜’,
‘같은 화면에서 선택 상태가 바뀜’, ‘입력/저장 결과가 바뀜’을 한 점수로 동일하게 취급하면
방법 선택 자체가 흔들린다. 선택 강조는 클릭 성공의 증거일 수 있지만 상세 화면 진입의 증거는 아니다.

## 해상도 민감도: 신규 96쌍을 원본 크기로도 재측정

임계값과 특징점 수를 유지하고 축소만 제거했다. ORB의 3px 기준 역시 원본 픽셀 기준이다.
해상도에 맞춰 튜닝한 공정한 최적화 비교가 아니라, 전처리 변경의 민감도 실험이다.

| 방법 | 960px 오탐/미탐 | 원본 오탐/미탐 | 원본 중앙값 |
| --- | --- | --- | ---: |
| SSIM | 8 / 0 | 13 / 0 | 32.26ms |
| 픽셀 | 4 / 0 | 4 / 1 | 1.44ms |
| ORB | 0 / 1 | 0 / 1 | 30.70ms |

픽셀은 원본 크기에서 N052를 놓쳤다. SSIM은 포커스·스크롤바 장식에 대한 반응이 늘었다.
‘원본으로 키우면 항상 정확해진다’는 가정은 이 자료에서 성립하지 않는다.

## 임계값 탐색 — 운영 권고값으로 확정하지 않음

전체 144쌍을 본 뒤 계산한 표본 내 탐색이다. 별도 신규 자료에서 검증하지 않았다.

| 방법 | 임계값 | 오탐 | 미탐 |
| --- | --- | ---: | ---: |
| SSIM | < 0.980 | 2 | 1 |
| SSIM | < 0.985 | 3 | 0 |
| SSIM | < 0.990 | 5 | 0 |
| SSIM | < 0.995 (기존) | 9 | 0 |
| SSIM | < 0.998 | 28 | 0 |
| 픽셀 비율 | > 0.2% | 25 | 0 |
| 픽셀 비율 | > 0.5% (기존) | 6 | 0 |
| 픽셀 비율 | > 1% | 3 | 3 |
| ORB 이동 비율 | > 5% | 2 | 0 |
| ORB 이동 비율 | > 10% | 0 | 3 |
| ORB 이동 비율 | > 15% (기존) | 0 | 3 |

SSIM 0.985와 ORB 5%는 후속 후보일 뿐이다. ORB가 문구 의미를 읽은 것이 아니라
특징점 연결 변화가 임계값을 넘긴 것이므로, 낮추기만 해서 문구 검증이 해결됐다고 보지 않는다.

## 적용 판단과 한계

1. 구조·스크롤 변화에서 포커스 오탐을 줄이는 목적: 현재 자료에서는 ORB가 가장 적합하다.
2. 작은 문구·입력 결과 변화까지 빠르게 찾는 목적: 픽셀 비교가 좋은 비용 대비 후보지만 선택 강조에 취약하다.
3. SSIM: 문구 변화는 놓치지 않았으나 기존 0.995는 과민했다. 우선 후보로 바로 교체하기보다 임계값/전처리 검증이 필요하다.
4. 세 방법 중 무엇도 화면 의미나 업무 완료를 증명하지 않는다. OCR 결과와 모델/메모의 역할을 없앨 근거가 아니다.
5. 이 실험은 전후 변화 판정이다. 다른 실행 사이 캐시를 재사용해도 되는지, 다른 크기의 창을
   같은 화면으로 연결해도 되는지, 좌표가 안전한지를 검증하지 않았다.
6. 같은 Mock ERP·공통 화면을 여러 실행에서 반복한 자료다. 스크롤 편중, 팝업 3건·조회 문구 3건의
   작은 표본, 공유 이미지, 라벨 사후 재검토가 있어 운영 정확도나 통계적 우열을 확정하지 않는다.
