# 외부 정적 분석 검토와 실행 결과

## 판단

외부 분석이 지적한 핵심 결합과 대형 함수 문제는 타당했다. 특히 `matching.py`가 타입
없는 `brain` 인자를 통해 26개 속성을 92회 읽던 구조, `match_screen`, `_verify_node`,
`SavedEvidence.observe`의 다중 책임, 업무 식별자로 고정된 `hbl_no`, 오래된 coverage
파일과 로컬 절대 경로는 현재 소스에서도 재현됐다.

두 항목은 표현을 보정했다. 정적 타입 임포트를 포함하면 큰 순환 연결 요소가 보이지만
`TYPE_CHECKING` 경로를 제외한 런타임 임포트 그래프에는 순환 연결 요소가 없었다. 또한
분석에 사용한 합본 덤프의 파일·테스트 수와 현재 체크아웃의 수치는 달랐으므로, 삭제나
커버리지 판단에는 현재 체크아웃의 실행 결과를 사용했다.

## 적용한 변경

1. 오래된 `coverage_baseline.txt`를 제거하고 비주얼 검출기 Python 경로를 설정 파일
   기준 상대 경로로 바꿨다. 편집 흔적 주석과 항상 존재하는 속성의 방어적 `getattr`도
   제거했다. 커밋: `9582b2b`.
2. `TaskInstruction.identity_input_key`를 도입했다. 저장 후 조회 증거 결합은 이 계약을
   사용하며, 선적 예제만 `hbl_no`를 명시한다. 식별 필드가 없는 업무는 선적 전용 저장
   증거 흐름에 들어가지 않는다. 커밋: `54004ee`.
3. 화면 매칭 입력을 불변 `MatchRequest`, 부수효과를 `MatchServices`, 반환 상태를
   `MatchResult`로 분리했다. `matching.py`에서 `Brain` 속성을 직접 읽는 횟수는 0이다.
   커밋: `7b704e2`.
4. 매칭은 프롬프트 구성, 응답 출처 선택, 계획 검증·보정, 대상 연결·마무리 단계로
   분리했다. 검증 노드는 탐색 변화, 선택값, 텍스트 입력, 저장 조회 증거, 기록 단계로
   분리했다. 저장 증거는 조회 화면, 상세 화면, 식별 입력, 행 이월, 필드 할당 단계로
   분리했다. 커밋: `9142e0d` 및 후속 중복 정리 커밋.

| 대상 | 변경 전 | 변경 후 |
|---|---:|---:|
| `match_screen` | 351줄, 근사 복잡도 44 | 62줄, 근사 복잡도 6 |
| `_verify_node` | 307줄, 근사 복잡도 64 | 91줄, 근사 복잡도 20 |
| `SavedEvidence.observe` | 280줄, 근사 복잡도 92 | 38줄, 근사 복잡도 9 |
| `matching.py`의 직접 `Brain` 접근 | 26개 속성, 92회 | 0 |

복잡도는 외부 보고서와 같은 도구의 점수가 아니라 AST 분기 노드를 세는 저장소 내 비교용
근사값이다. 헬퍼로 이동한 판단을 삭제했다고 해석하지 않는다. 이름 있는 단계로 옮겨 실행
순서와 입출력 경계를 드러낸 결과다.

## 검증

- Ruff lint와 format 검사 통과
- 전체 테스트 677개 통과
- branch coverage 포함 종합 coverage 87.253%
- 일반 전체 테스트 실행 44.90초, 최종 coverage 실행 54.30초(각 1회)
- 변경 전 최근 기준 87.131% 대비 0.122%p 상승

이번 검증은 fake/replay 기반이며 유료 모델 호출이나 실제 ERP 입력을 실행하지 않았다.
`click_refinement`, `screen_batch`, `context`의 나머지 `Brain` 결합, 행동 준비 책임의 별도
객체화, `brain`과 `pipeline`의 공용 타입 패키지 분리는 후속 구조 변경 범위다. 이들은
변경 파일 수와 임포트 경로가 크게 늘어나므로 이번 경계 수정과 한 커밋에 섞지 않는다.
