## 발견 사항

- #2: 화면에 계정과 마스킹 비밀번호가 이미 있는데 자격 정보를 재입력했다. 첫 로그인 클릭이 왜 전환을 만들지 못했는지는 이 기록만으로 확정하지 않는다.

- #14: 화면의 추가 정보 6개 값이 맞다고 인식하고 purpose는 저장을 지시했지만 steps는 6개 fill이었다. 코드의 visual_proposal_fields_still_pending 거절 후 #15에서 저장 계획을 다시 얻었다. 코드가 정상 저장 액션을 삭제한 사례는 아니다.
- #17–18 및 #21–22: 요청한 교육 ID의 상세가 이미 첫 요청에 포함돼 있었다. select_match_response는 requested_instruction_ids가 있으면 포함 여부를 따지지 않고 재호출한다. 각각 3.13초, 7.24초가 들었다.
- #24–27: 재조회 후 기본 정보에서 품명만 화면 밖에 남았는데 추가 정보로 먼저 이동한 후 기본 정보로 복귀해 스크롤했다. 현재 탭의 검토를 끝내고 이동하는 순서가 더 효율적이다. 업무 실패는 아니다.
- 프롬프트에는 모델이 증거를 판단하라는 review_instruction과 ONLY after code verifies...라는 기존 조건이 함께 있다. remaining_inputs에는 방금 입력한 미확인 값도 남고 method_memory.current_purpose에는 이전 입력 지시가 남는다. 실제 문맥의 혼재는 확인됐지만 모델 오판의 단일 원인이라고 확정하지 않는다.
