# 시드 3 관찰 메모·실행 연결 수정과 확장 검증

## 수정 기준

성공 판정과 중간 행동의 타당성을 구분했다. 수정 범위를 교육 재호출에 고정하지 않고,
원문 응답·실행 순서·실제 캡처에서 확인한 결함까지 확장했다. 모델·교육 파일·시드별
버튼 순서는 변경하지 않았다. 기존의 잘못된 성공 전제를 가진 테스트도 재작성했다.

## 수정한 인과관계

새로운 별도 완료 검토기나 시드 전용 분기는 추가하지 않았다. 관찰값의 일치 여부는 기존
비교 함수를 재사용하며, 화면에서 무엇을 읽고 어느 입력에 연결할지는 모델이 결정한다.

## 화면 실행에서 발견한 추가 결함

069의 호출 7은 품명 필드를 스크롤로 드러내겠다고 설명했지만 실제로는 품명 라벨을
클릭했다. 클릭 전달은 성공했고 화면 내용은 그대로였다. seq 182는
`identical_form_reused`였으나 seq 184는 `navigation_observed_change`였다.
관찰 0007의 `capture_phash`는 `9623962237447187132`, 0008은 `null`이었다.
따라서 비교가 pHash 기반에서 의미 트리 기반으로 바뀌어, 동일 화면을 다른 상태로
기록했다. 이 결함은 모델의 클릭 선택과 별개이며 캐시·방법 효과 판정에도 영향을 준다.

069의 호출 18은 조회 입력을 채우고 조회 버튼을 누르는 계획이었다. 입력 행동은
`action=fill, intent=search, source=hbl_no`였다. source를 intent 기준으로 먼저 지워
`screen_match_step_not_executable`을 만들었고 호출 19에서 다시 계획했다.
이 경우를 단순 모델 오답으로 분류하지 않고 정규화 순서를 수정했다.

070은 ERP 10/10으로 끝났으나 호출 17에서 상세 입력 화면을 `dialog`로 분류했다.
대기 정보가 해당 행동 객체에만 있어 다음 탭 행동에서 유실되었고, 호출 19–21의
`evidence_scope`가 `entry`로 돌아갔다. 모델의 화면 분류 흔들림은 남을 수 있지만,
그 때문에 작업 메모까지 초기화되는 것은 코드 결함이다. 다음 수정은 특정 화면을
editor로 강제 분류하는 대신 대기 상태를 작업 상태에 보존한다.

## 테스트 정리

- 실제 값이 빈칸/WRONG인데 evidence만으로 성공을 기대하던 테스트를 수정했다.
- 과거 기억 보존 테스트를 내부 호출 금지 mock 대신 실제 관찰값 확인 → 다른 화면에서
  필드가 보이지 않는 순서로 재작성했다.
- 동일 화면 테스트는 모델 호출 수뿐 아니라 탐색 상태, 이름·값, 새 관찰 ID를 확인한다.
- `RunLog` 변조 테스트가 같은 길이 파일의 mtime 변화에 암묵적으로 의존하던 부분을
  명시적으로 만들었다. 메타데이터 변경과 `verify_each_append`의 동일 메타데이터
  변조 검출을 나누었다. 저장소 프로덕션 코드에는 변경이 없다.
- 테스트를 통과시키려고 입력 원문을 무시하거나 실제 실패를 xfail로 바꾸지 않았다.
  기존 `visual_proposal_unknown_marker` xfail 1건은 남아 있다.
