## 남아 있는 문제

### 1. 상세 열기 판별이 클릭 대상의 문자열에 묶여 있다

`brain/graph/engine.py:2217` 부근은 저장 후 query 화면에서 클릭한 대상의 `value/name`에 업무 식별값이 포함되어야 `post_save_identity_result_target=True`를 설정한다. 행에는 식별값이 있지만 `선택 건 수정` 버튼에는 없다. 따라서 새 검토 후보 범위와 상세 화면 검토 시작 둘 다 실행되지 않았다.

즉, 직전 수정은 이 플래그가 설정된 이후의 요청 시점을 바로잡았지만, 플래그를 만드는 조건의 누락까지 해결하지 않았다. 실제 상세 화면으로 전환됐다는 의미를 클릭 대상 문자열로만 추론하는 의존성이 남아 있다. 버튼명 추가 하드코딩보다는 재조회 결과와 다음 상세 관찰을 연결하는 공통 경로로 범위를 다시 잡아야 한다.

이번에는 모델이 호출 23에서 기본 4개, 24에서 추가 6개, 26에서 기본 4개와 품명을 실제 검토하고 완료했다. ERP 저장 성공도 확인됐다. 하지만 이전 증거가 새 검토 문맥에 남은 구현 결함은 여전히 존재한다.

### 2. 품명에서는 설명·행동·증거가 여전히 어긋났다

호출 13은 설명에서 품명을 이미 확인했고 추가 정보로 이동한다고 했지만, `steps`는 품명 fill이었다. `evidence`에는 품명이 빠졌다. seq302–303은 `screen_fill_evidence_missing`을 기록했고, seq309는 화면 값이 이미 일치하므로 해당 fill을 실제로 전달하지 않았다. 호출 14에서 다시 계획해 탭 이동으로 이어졌다. 단순 재입력을 실행한 것이 아니라, 모델 응답 불일치와 재계획 비용이 남은 것이다.

### 3. 스크롤·조회·로그인에서 반복이 남았다

- 로그인 첫 클릭은 seq27의 relay `screen_changed`로 거절되어 호출 2에서 재판단했다. 계정·비밀번호 입력은 전달됐다. 이 오류의 세부 원인은 이번 측정에서 확정하지 않았다.
- 품명 노출을 위한 호출 8–11은 스크롤바/아래 화살표 클릭을 반복하다 키 행동으로 전환했다. 이 네 호출 합은 약 36.83초이며 최초 입력 검토도 포함하므로 전부 절감 가능한 시간은 아니다. 직접 본 중간 프레임에서는 품명이 계속 가려져 있다가 이후 노출됐다.
- 조회를 마친 뒤 호출 5와 21에서 다시 조회했다. 특히 21은 교육 재호출만 제거됐고 모델이 선택한 조회 행동은 유지됐다.
