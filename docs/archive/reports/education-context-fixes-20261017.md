# 교육 재호출·상태 문맥 수정

2026-10-17. [066 감사](education-context-audit-066-20261017.md)의 확인된 결함을 아래 순서로 수정했다. 유료 모델 호출과 화면 파일럿은 실행하지 않았다.

## 우선순위와 실제 수정 범위

| 순위 | 확인된 문제 | 변경 | 범위 |
| --- | --- | --- | --- |
| 1 | 이미 제공한 교육 상세를 요청해도 행동 계획을 버리고 다시 호출 | 요청 ID에서 현재 제공한 ID를 제외한다. 새 상세가 없으면 기존 행동을 유지한다. 새 상세가 있으면 기존 상세와 합쳐 재계획한다. | `brain/graph/matching.py` |
| 2 | 조건부 다음 행동의 남은 입력을 실제 확인 목록으로 덮어써 문맥이 충돌 | 실행 계약의 조건부 목록을 보존하고 예상 확인 목록을 그 계약에서 파생한다. 실제 확인/미확인 목록은 따로 유지한다. 현재 task 프롬프트에서 갱신되지 않는 구형 조회 플래그 3개를 제외한다. | `brain/graph/context.py`, `brain/graph/matching.py` |
| 3 | 저장 상세를 처음 판단할 때 저장 전 확인 결과가 모두 전달 | 상세 열기 대기 중인 요청은 별도 검토 후보 범위로 전달한다. 현재 검토의 확인 목록·증거·정책·스크래치패드를 같은 범위로 구성한다. 실제 상세 화면 확인 전에는 전역 입력 증거를 지우지 않는다. | `brain/graph/engine.py`, `brain/graph/matching.py`, `brain/graph/screen_mapping.py` |
| 4 | 배치 입력은 최근 행동과 완료 이력 기록을 건너뜀 | 단일 행동과 배치 입력이 같은 기록 함수를 사용한다. 배치에서는 관찰로 확인한 입력만 기록한다. 모델 문맥의 이전 행동 설명은 `previous_action_purpose`로 구분한다. | `brain/graph/engine.py`, `brain/graph/method_runtime.py` |

새 FSM, 단계별 차단 규칙, 자동 완료 판정을 추가하지 않았다. 내부 조회 플래그와 영구 저장 형식의 `current_purpose`는 유지하며, 이번 변경은 해당 모델 문맥의 노출 방식을 고친다.

## 결함을 검출하는 테스트

- 이미 제공한 교육을 다시 요청해도 모델 호출은 1회이며 원래 행동을 보존한다. 아직 제공하지 않은 교육은 재호출하되 기존 상세를 잃지 않는다.
- 방금 입력한 값은 조건부 다음 행동에서는 입력 완료를 가정하지만 실제 확인 목록에는 아직 들어가지 않는다. 런타임 확인 상태를 조기에 변경하지 않는다.
- 저장 상세를 여는 첫 요청에 저장 전 확인 목록을 재사용하지 않는다. 실제로 조회 화면에 남아 있다면 상세 검토를 시작하지 않고 기존 입력 증거를 유지한다.
- 배치에서 확인된 입력의 최근 행동·완료 이력이 남는다. 같은 대상의 경계 행동은 입력 완료로 중복 기록하지 않는다.

기존 `tests/test_screen_matching.py`, `tests/test_screen_batch.py`, `tests/test_worker_context.py`의 관련 검증을 갱신했다. 상세 이동 실패 시 입력 증거를 보존하는 테스트 1건을 추가했다.

## 기대 효과와 아직 검증하지 않은 항목

066의 교육 재호출 18·22번은 이미 전달한 상세를 다시 요청한 사례였다. 같은 응답 조건에서는 추가 교육 호출을 생략한다. 당시 두 호출 시간 합계는 10.37초였지만, 새 실행에서의 실제 절감 시간은 아직 측정하지 않았다. 후속 모델 응답이 달라질 수 있으므로 27회에서 정확히 25회로 줄었다고 주장하지 않는다.

조건부 문맥의 모순과 첫 상세 검토의 증거 혼용을 제거했지만, 이들이 모델의 반복 입력·탭 이동의 유일한 원인이었다는 주장은 하지 않는다. 다음 화면 실행에서는 요청 원문과 프레임을 함께 확인해 재입력, 교육 재호출, 재조회 확인 순서를 측정해야 한다.

교육 상세의 턴 간 영구 보관이나 `completed_taught_steps` 갱신 정책 전체는 이번 범위에 포함하지 않았다. 실제 파일럿·웜 실행 결과 및 성능 향상은 미검증이다. 기존 작업 트리의 다른 수정은 그대로 보존했고, 이번 턴에서 커밋하지 않았다.
