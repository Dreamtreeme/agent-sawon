# P0: 교육 문맥·복합 응답·공통 계측

프로젝트 전체 방법론 검토의 첫 묶음(P0: 공통 계측 + 6/9/11)을 적용했다.
이 기록은 코드/회귀 검증 결과이며 실화면 속도 개선이나 업무 성공을 측정한 결과가 아니다.

## 교육의 선택과 완료 분리

- `Brain._taught_procedure_progress()`는 모든 교육 단계의 ID/설명 인덱스와 현재 주변 단계의
  상세 내용을 제공한다. 전체 목표·요구사항·완료 조건은 기존 task 문맥에 유지한다.
- 모델은 `requested_instruction_ids`로 어느 단계든 상세 actions/completion을 조회한다.
  같은 프레임에서 필요한 ID들을 함께 요청한다. 조회를 요청한 응답의 임시 행동은 실행하지
  않고, 상세 내용을 공급한 뒤 측정 모델로 다시 판단한다. 조회는 판단당 한 차례이며 잘못된
  ID나 반복 조회는 명시적인 실패로 기록된다. 정상 화면에는 이 추가 호출이 없다.
- 교육 초점을 바꾸는 것은 완료가 아니다. 이전 단계로 돌아갈 수 있고, 완료 함수는 확인한
  해당 단계만 기록한다. 앞 단계 모두를 자동 완료시키지 않는다.
- MethodRuntime의 별도 `procedure_prompt_context()`와 그 전용 테스트를 제거했다.
  메서드 전달 이력은 교육 진척의 작성자가 아니다. 메서드 바인딩 실패 후 폴백도 호출자가
  제공한 교육 문맥을 그대로 사용한다.
- 프롬프트 접두부와 JSON 양쪽에 반복되던 교육 규칙을 한 번만 제공한다.

## 현재 관찰 주장과 후속 실행 계획

- task 경로의 `duplicate_clear + steps`는 enforcement 모드와 무관하게 후속 행동을
  유지한다. 원 응답의 operation/grid/row/evidence/frame은 `MatchResult.observation_claim`,
  append-only 로그와 다음 판단의 피드백에 보존한다.
- 이 주장은 `reported_not_independently_verified`로 표시한다. 이를 수신했다고
  duplicate_clear 또는 업무 성공 플래그를 설정하지 않는다. `planned_operation`도 실행
  완료를 의미하지 않는다. 실제 전달은 기존 action/result 로그가 담당한다.
- complete/stop/duplicate_found처럼 종결 의미인 응답은 부수 행동보다 종결 판단을 우선한다.
  현재 필드 증거는 기존 관찰 접지·기록 경로를 사용한다. 저수준 실행 prefix와 부분 실패
  계약, 화면이 바뀐 뒤 재관찰하는 경계는 유지한다.
- 이 단계는 응답 정규화와 주장 보존이다. 모든 proof를 코드가 자동 인증하는 기능이나
  임의의 화면 횡단 행동 큐는 아니다. 역사 캐시가 이미 잃어버린 원 주장을 복원하지 않는다.

## 계측

- 측정 ModelClient가 호출 성공/실패에 관계없이 response schema, prompt/schema UTF-8 bytes,
  이미지 수와 호출 문맥을 기록한다. 실제 공급자 토큰·비용은 기존 필드에 별도로 남긴다.
- 화면 판단마다 decision ID와 frame을 만들고 해당 판단의 모델 호출과 최종 mapping에 연결한다.
  호출 지점에서 최초 판단/입력 검토/완료 단계 판단/교육 조회/이미지 보완/target 접지/
  검증 거부 후 재판단/누락 행동 보완을 구분한다. 임의 프롬프트 문자열로 사유를 추측하지 않는다.
- 최초 판단 문맥은 section별 UTF-8 bytes를 기록하고, 교육 추가 조회는 상세 문맥 크기를
  별도 기록한다. 문자·바이트를 토큰이나 청구량으로 표현하지 않는다.
- 문서 추출에도 동일한 `model_call_context`를 사용한다. context는 범위 종료/예외 시 복구돼
  다음 호출에 이전 판단 정보가 섞이지 않는다. provider API와 replay fingerprint는 유지한다.

## 검증과 남은 실측

회귀는 단계 건너뛰기/복귀가 완료를 만들지 않음, 상세 조회 전 행동 미실행, 같은 판단의 두
호출 연결, enforce/observe_only 양쪽의 관찰 주장 보존, 실패 호출 기록과 문맥 누수 방지,
메서드 이력이 교육 진행을 바꾸지 않음을 확인한다. 기존 전체 테스트에는 배치의 부분 실패,
증거 접지, 완료, 문서 인계와 모델 비용 검사도 포함된다.

다음 실측은 중간 화면 시작·재로그인·수정 화면 복귀·조회 확인과 다음 행동이 함께 오는 경우를
포함해야 한다. 추가 교육 호출이 줄인 오류와 늘린 지연을 함께 비교한다. 콜드/웜 및 다른
회사 교육을 나누며 테스트 통과만으로 실제 GUI 성공이나 지연 감소를 주장하지 않는다.
