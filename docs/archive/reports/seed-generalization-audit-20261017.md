# 개발 시드 검수 — 2026-10-17

## 실행 범위와 중지

개발 시드 0–29를 순서대로 검증하도록 준비했다. 사용자 조건은 첫 실패 시드의 다음
시드까지만 검증하고 중지하는 것이다. 1번 콜드가 최초 실패했고, 2번 콜드·웜까지 실행한
뒤 오케스트레이터가 `stopped_after_next_seed`로 종료했다. 3–29는 실행하지 않았다.
평가용 시드 5000–5999는 사용하지 않았다.

시드 통과는 작업자 success와 독립 ERP 성공이 모두 필요하다. ERP에 값이 저장됐더라도
재조회 검토를 끝내지 못하고 작업자가 stopped이면 실패로 판정했다. 콜드가 실패하면 웜은
실행하지 않으며, 편찬 실패도 시드 실패로 처리하도록 사전에 정했다. 재시도는 하지 않았다.

## 첫 실패: 1번의 스크롤 영역 역할 제한

0번은 탭을 가진 2열 배치, 1번은 길게 스크롤하는 1열 배치, 2번은 값들이 한 화면에
모인 2열 배치였다. 실제 캡처를 열어 입력값과 재조회 화면을 확인했다.

1번은 저장 후 같은 레코드를 재조회해 상세창까지 열었다. 하단값도 입력되어 있었지만
위/아래 증거를 모으는 과정에서 다음 문제가 발생했다.

1. 로그 seq328: 모델 선택 영역이 group인 클릭을 role_not_actionable로 거절.
   seq330에서 screen_match_action_surface_mismatch 검증 예외 발생.
2. seq408: pagedown 탐색이 navigation_cycle로 반려.
3. seq421: 품명 bbox `[49,90,1058,20]`을 대상으로 pageup하면서 점 `[600,250]`을
   지정해 visual_click_point_outside_target로 반려. 이 점은 선언한 영역 밖에 있다.
4. seq466: 모델은 `본문 스크롤 영역`을 클릭해 하단값을 확인하려 했다.
   bbox `[1125,99,22,546]`, point `[1136,520]`, role group이다.
   점은 영역 안이고 실제 프레임의 오른쪽 스크롤바 위치다.
   코드의 ACTION_CONTROL_ROLES.click에는 group이 없어 다시 거절했다.
5. seq468 검증 예외, seq469 같은 navigate 검증 오류 누적2회로 중단.
   최종 이유는 `repeated_subgoal_failure:task:navigate:verification_error:ValueError`.

직접 원인은 matching.py의 validate_action_surfaces와 vocabulary.py의 click 허용 role
목록 사이의 실행 제약이다. 현재 observe_only 설정에서도 이 변환/표면 검증은 작동한다.
모델이 모든 판단을 정확히 했다는 뜻은 아니다. seq421에는 실제로 bbox와 점의 불일치도 있었다.
그러나 최종 클릭은 좌표가 영역 밖이어서가 아니라 group 역할이라는 이유로 막혔다.

이 검수에서는 문제를 고치거나 실패 시드를 재실행하지 않았다. 스크롤의 별도 행동 표현,
영역의 역할 분류, 현재 계약의 허용 범위 중 무엇을 바꿀지는 후속 수정에서 결정할 문제다.
영역 비교를 전부 제거해야 한다는 결론은 이번 기록에서 나오지 않는다.

### 추가 추적: 첫 반려가 저장 후 검토 세션의 시작도 막았다

최종 group 클릭 거절만으로는 위/아래 확인 반복을 충분히 설명하지 못한다.
seq320의 결과 행 더블클릭은 성공했고, 바로 다음 d1fa318b 캡처에는 저장 번호1의 상세
편집 화면이 실제로 열려 있다. 모델도 열린 상세창과 상단5개 값의 일치를 인식했으나,
같은 응답에 포함된 다음 스크롤바 클릭이 seq328에서 거절됐다.

`_verify_node()` → `_observe()` → `visual_perception.observe()` 내부에서 다음 행동까지
검증하다 예외가 발생하므로, `_observe()`의 `_begin_saved_detail_review()`에는 도달하지
못한다. 이어 `_verify_node()`의 finally가 pending을 비워, 상세 진입 행동에 붙은
post_save_identity_result_target도 다음 관찰에서 사용할 수 없게 된다.

실제 로그의 model_saved_detail_review_started는0건이다. 그런데 seq343 이후 일반
model_task_evidence_recorded의 필드 합집합은11개 전체이며, 최종 task-notebook도
verified_inputs11개/remaining_inputs0개다. 따라서 값 자체를 전혀 읽지 못하거나 매번
전부 덮어쓴 문제가 아니다. 일반 입력 증거는 누적됐지만 저장 후 상세 검토 세션이 시작되지
않아, 그 전용 증거 누적과 완료 경로에 연결되지 않은 것이다.

seq343 상단5개 → seq362 하단6개 → seq384 상단5개 → seq406 하단6개로 확인이 반복됐다.
중간에는 pageup의 bbox/point 불일치와 Home 후 동일 하단 화면 유지도 있었다.
최종적으로 seq468의 같은 종류 검증 오류가 누적되어 중단했다.

근본 수정 검토 대상은 단순한 role 목록 확대만이 아니라, 이미 관찰된 이전 행동의 결과를
다음 행동의 적합성 검증 실패와 함께 버리는 처리 순서/예외 경계다. 이 분석에서는 코드를
수정하지 않았고, 해당 경계 수정 후 성공 여부는 아직 실측하지 않았다.
