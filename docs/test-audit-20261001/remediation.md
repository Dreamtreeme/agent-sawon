## 핵심 교정

- 가짜 ERP가 기대값으로 조회 결과를 만들어 주던 구조를 교정했다. 실제 전달된 입력을 복사해
  저장하고, 조회는 그 독립 스냅샷만 읽는다. 저장 후 입력·기대값을 바꿔도 저장행은 그대로임을 확인한다.
- 기존 시각 전체 흐름 4케이스를 현재 ScreenMatch 설정의 전체 흐름 4케이스로 교체했다.
  `tests/test_visual_workflow.py::test_visual_complete_flow_and_corrupt_reread_gate`는
  `tests/test_visual_workflow.py::test_screen_match_workflow_uses_actual_saved_snapshot`으로 대체됐다.
  정상 화면·커서 깜빡임·저장값 손상·저장 누락을 각각 검증한다.
- 전체 흐름은 로그인→메뉴→중복 조회→전체 필드 입력→저장 확인→최종 조회를 실제 Brain,
  VisualPerception, ScreenMatch, 공통 컴파일러·검증기·픽셀 실행기·SavedEvidence로 연결한다.
  OCR/탐지와 모델 응답은 replay이며 화면 PNG와 공개 프롬프트에 연결된다. 저장값은 정답에서 주입하지 않는다.
  로그인과 한 화면 입력의 연속 행동, 최종 11필드 증거, 정확한 실패 사유와 비밀정보 비노출도 검사한다.
- 다른 오류에 먼저 걸리던 음성 검사를 목적 조건만 바꾸는 입력으로 고치고 양성 대조를 붙였다.
  단순 `stopped` 검사 대신 정확한 거부 사유와 실제 행동 유무를 확인한다.
- OpenAI strict schema는 유효 응답의 실제 파싱과 로컬 계약 보존을 확인한다. 캐시 비활성화 검사는
  실제 Brain 성공 흐름에서 캐시 읽기·쓰기 호출이 없는지 검증한다. 비용 예약도 정확한 금액을 비교한다.
- 벤치는 실제 입력 종류·인수·횟수, 전경 복원→입력 순서, SendInput 부분 전달, 캡처 실패,
  저장 CSV·journal, 문서 글꼴 및 실제 PDF 렌더링 등을 기존 검사에서 보강했다.
