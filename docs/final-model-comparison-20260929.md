**이번 저장 상태에서는 모델의 판단 차이가 확인됐다. 반복 실패 전체를 모델만의
문제로 설명할 수는 없으며 현재 코드의 완료 후보 제공·복구 처리에도 결함이 있다.**

사용자의 “계속해서 문제가 생기는데 모델 차이가 맞나?” 요청에 따라 최신 실패
`20260929T013723Z-acb4820b`의 마지막 요청을 고정해 두 모델을 비교했다.
운영 코드·설정은 변경하지 않았고 ERP를 재실행하거나 화면을 조작하지 않았다.

## 같은 조건의 비교

저장된 relay 관찰과 모델 결정을 오프라인으로 재생했다. 계획을 포함한 원래 요청
30개의 SHA-256이 현재 코드에서 모두 일치했으며 같은 최종 중단 사유도 재현했다.
원래 실패의 응답 형식 오류를 추정한 실험이 아니다. 원래 30회는 모두 유효 응답이었다.

최종 요청 해시:
`931a6fbf1e07eab875abf662a73763f2538514b583827e90a101651af0b76f12`

관찰, 레코드, 지침, 상태, 피드백, 응답 스키마를 동일하게 두고 모델만 바꿨다.
두 설정 모두 temperature 0, 출력 한도 4,096, 시간 한도 60초다.
호출 순서는 Lite → Flash → Flash → Lite → Lite → Flash였다.
각 응답은 같은 현재 관찰과 운영 가드로 검사했으며 실제 행동은 실행하지 않았다.

| gemini-3.5-flash-lite | 3 | 3/3 유효 | 3/3 조기 완료, 현재 행 식별 근거 부족으로 거부 | $0.00596974 |

추가 6회 비용은 **$0.02466034**이며 HTTP 오류·비용 미확정은 없다.
모든 호출은 측정 ModelClient를 사용하고 SDK 자동 재시도를 비활성화했다.
호출 전 UTF-8 입력·스키마 상한과 출력 한도로 비용을 예약하고 총 $0.50을 제한했다.
사용량 및 단가 계산에는 제공자가 보고한 캐시·추론 토큰도 반영한다.

경량 모델의 두 응답은 근거 11개를 형식상 채웠지만, 결과 행 밖의 조회 입력칸을
HBL 증거로 쓰고 선적항 셀을 도착항 증거로 재사용했다. 나머지 한 응답은 HBL·도착항
두 근거를 생략했다. 세 응답 모두 현재 모든 값이 보인다고 주장했다.

상위 모델은 HBL·도착항 셀을 한 화면에서 확인해야 한다고 판단하고 현재 관찰에 있는
최대화 컨트롤을 선택했다. 그 행동의 대상과 선택 가능 여부는 확인했지만,
실제로 최대화한 뒤 모든 열이 보이는지와 전체 업무가 성공하는지는 이번에 측정하지 않았다.

## 모델과 별개로 확인된 코드 문제

1. `brain/graph/policy.py`의 완료 분기는 저장·검색 등 진행 플래그만 검사한다.
   현재 결과 행에서 식별자와 모든 필드가 관찰되는지는 완료 후보 제공 전에 반영하지 않는다.
2. `brain/graph/engine.py`는 현재 HBL 셀을 찾지 못하면
   `final_query_not_one_matching_row`로 즉시 종료한다. 이 사례처럼 열이 화면 밖인 경우와
   실제 중복 결과를 구분해 복구하지 않는다. 다른 필드 근거 누락은 제한된 재시도를 제공한다.
3. 최종 가드가 불충분한 완료를 거부한 것은 올바르다. 보완 대상은 모델에 제공할 후보와
   관찰 부족의 분류·복구이며, 가드를 완화하거나 과거 ref를 합쳐 통과시키는 것이 아니다.

동일 Lite에서 단계 지침만 좁혀 실패 3/3이 유효 검색 3/3으로 바뀐
[이전 실험](model-root-cause-20260929.md)과 스키마 표현만 바꾼
[계약 실험](contract-repair-20260929.md)도 로직·계약의 영향을 보여준다.
서로 다른 코드에서 실행한 GUI 결과를 한 성공률로 합산하지 않는다.

## 다음 구현 우선순위와 판단 범위

- 현재 관찰의 결과 행 식별·필드 근거 범위를 정책 입력에 반영해 불가능한 완료 후보를 제한한다.
- 식별 셀이 화면 밖인 상태와 실제 중복·불일치를 구분하고 관찰 기반 화면 조정·재관찰에
  제한된 복구를 제공한다. 특정 ERP의 최대화 라벨·ref·탐색 순서는 하드코딩하지 않는다.
- 회귀 테스트 후 상위 모델로 전체 업무를 확인하고, 같은 코드에서 경량 모델과 비교한다.

이번 결과는 **단일 실패 상태의 다음 판단 비교**다. temperature 0의 반복 호출은 독립적인

상위 모델도 전체 GUI 통과를 입증하지 않았고 경량 전체 성공·M1 완료는 여전히 미확인이다.
