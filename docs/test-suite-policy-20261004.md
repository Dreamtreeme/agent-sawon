# 최신 런타임 테스트 유지 기준 — 2026-10-04

테스트 수 자체를 품질로 보지 않는다. 기본 회귀 모음에는 다음 중 하나를 독립적으로 입증하는
테스트만 둔다.

1. 공개 입출력 계약이나 저장 형식이 잘못된 값을 거부한다.
2. 실제 행동 전에 창·좌표·비밀·비용·측정 경계를 지킨다.
3. Luna 일반 업무의 관찰→판단→실행→검토 또는 성공 trace→warm replay 상태 전이를 검증한다.
4. 현재 사용 중인 의미 캐시·시각 캐시·방법 그래프가 다른 값과 현재 화면에 안전하게 재결합된다.
5. 실제 파일럿에서 발생한 오류를 그 원인 하나로 재현하며, 수정 전에는 실패한다.

다음은 기본 회귀 모음에서 제외한다.

- 생산 동작 없이 테스트 도우미 자체만 검사하는 테스트
- 프롬프트 문구의 존재만 확인하고 schema·행동·상태 변화를 검사하지 않는 중복 테스트
- Pydantic·pytest 자체 동작을 다시 검사하는 테스트
- 동일한 실패 계약을 하위 단위와 상위 통합에서 같은 방식으로 반복하는 테스트
- 현재 `task_path + visual_model_only_review` 경로가 실행하지 않는 고정 선적 상태기계와 로컬
  코드 증거검토기만을 위한 테스트

이번 정리에서는 마지막 항목에 해당하는 `duplicate_query → enter → save_result → final_query`
전용 회귀, 로컬 최종행 할당/저장결과 검토 조합, 과거 고정 procedure 전체 replay를 제거했다.
생산 코드는 과거 결과 재현을 위해 남아 있지만, 이 호환 경로의 통과를 최신 일반 업무 성공으로
해석하지 않는다. Gemini/Jev 비교 어댑터, M1 의미 캐시·측정, 문서 추출, 안전·비용 계약은 현재
범위에 남아 있으므로 테스트를 유지한다.

정리 전 897개에서 정리 후 804개로 93개를 줄였다. 정리 후 전체 결과는
`804 passed in 186.63s`이며, 직전 나머지/신규 묶음 합산 약 313.53초보다 약 40.5% 짧다.
이 수치는 같은 작업 디렉터리의 연속 실행 참고값이며 성능 벤치마크로 사용하지 않는다.
