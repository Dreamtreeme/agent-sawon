# 최신 런타임 테스트 유지 기준 — 2026-10-08

테스트 수 자체를 품질로 보지 않는다. 기본 회귀 모음에는 다음 중 하나를 독립적으로 입증하는
테스트만 둔다.

1. 공개 입출력 계약이나 저장 형식이 잘못된 값을 거부한다.
2. 실제 행동 전에 창·좌표·비밀·비용·측정 경계를 지킨다.
3. Luna 일반 업무의 관찰→판단→검토→실행 또는 성공 trace→warm replay 상태 전이를 검증한다.
4. 현재 사용 중인 의미 캐시·시각 캐시·방법 그래프가 다른 값과 현재 화면에 안전하게 재결합된다.
5. 실제 파일럿에서 발생한 오류를 그 원인 하나로 재현하며, 수정 전에는 실패한다.

다음은 기본 회귀 모음에서 제외한다.

- 생산 동작 없이 테스트 도우미 자체만 검사하는 테스트
- 프롬프트 문구의 존재만 확인하고 schema·행동·상태 변화를 검사하지 않는 중복 테스트
- Pydantic·pytest 자체 동작을 다시 검사하는 테스트
- 동일한 실패 계약을 하위 단위와 상위 통합에서 같은 방식으로 반복하는 테스트
- 현재 `task_path + visual_model_only_review` 경로가 실행하지 않는 고정 선적 상태기계와 로컬
  코드 증거검토기만을 위한 테스트

2026-10-04 정리에서는 마지막 항목에 해당하는
`duplicate_query → enter → save_result → final_query` 전용 회귀, 로컬 최종행
할당/저장결과 검토 조합, 과거 고정 procedure 전체 replay를 제거했다. 이후 화면 작업자의
구형 Procedure 진입·고정 단계 분기를 생산 코드에서도 제거했고, UIA 필드 캐시·관찰 변화
시연 변환도 삭제했다. non-screen-matching 정책, Gemini/Jev 비교 어댑터, 현재 시각 캐시와
업무 방법, 문서 추출, 안전·비용 계약은 지원 범위에 있으므로 해당 테스트는 유지한다.
