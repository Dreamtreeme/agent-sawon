## 2단계 — 실행 상태 소유권

실제 입력·저장 증거, 조회 상태, 실패·탐색 기록, 좌표 바인딩과 롤링 이력을 WorkerState.progress로 통합했다. 사용되지 않던 observation.rolling_turns를 제거했다. Brain의 기존 속성은 동일 상태를 참조하는 접근자이며 별도 복사본을 저장하지 않는다. 클라이언트·파일 저장소·설정·자격증명 값은 상태에서 제외한다. notebook은 공개 이력 조회를 사용한다. 방법 학습의 실행 상태는 5단계에서 이전한다.

인계/반환 스냅샷을 수정해도 원본 증거·계획·롤링 이력이 오염되지 않는 기존 계약 테스트를 확장했다. 모델/relay 호출은 fake/replay만 사용했다.

검증: pytest 680 통과, 45.03초(일반 실행 1회, coverage 미포함). Ruff lint/format 통과. 이전 coverage 실행 107.83초와 직접 속도 비교하지 않는다.

## 3단계 — 판단 처리와 증거 연결 순서

최초 응답·보정 응답·최종 응답이 같은 task/교육/입력 대상 검증 함수를 사용한다. 나중에 추가된 행동도 마지막 검증과 대상 연결을 거친다. action만 아니라 evidence/completion_evidence 마커도 현재 관찰에 병합한 뒤 컴파일한다.

별도 결함 수정: sanitize_unused_controls가 의미 control 목록에 없다는 이유만으로 현재 화면의 evidence를 먼저 삭제하던 코드를 제거했다. 실제 마커의 의미가 빠졌다면 기존 보완 호출로 연결한다. 미연결 마커는 컴파일할 수 없고, 연결만으로 verified가 되지 않는다는 회귀 검증을 유지했다. 복구가 필요한 경우 보완 모델 호출 1회가 추가될 수 있다. 사용자 모델 증거를 버리는 호출 수 절감을 유지하지 않는다.

검증: pytest 680 통과, 51.82초. Ruff lint/format 통과. 캐시/방법 공급 경로 통합은 5단계에서 완료한다.
