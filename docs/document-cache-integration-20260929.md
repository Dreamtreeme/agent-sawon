# 서류 캐시 연결·입력 대상 복구

사용자 지시: 다음 계획에서 화면 비교를 제외하고 구현한다. M2 범위 안에서 코드와
fake/replay 검증만 진행하며 실제 ERP·OCR·유료 모델·평가용 시드는 실행하지 않는다.

## 구현 범위

1. 모델이 고른 텍스트 입력 대상이 입력 역할이 아니면 실행 전에 거절하고,
   설정된 한도 안에서 새 관찰·행동 선택을 수행한다. 창 제한·권한·비용 가드는 유지한다.
   이미 실행한 행동이나 결과가 불명확한 행동을 이 경로로 재시도하지 않는다.
2. 준비된 서류의 READY·출처·교차 검증·레코드/로그 정체성을 확인한 뒤
   건별 cold/snapshot 캐시를 설치한다. 기존 OCR 기록은 덧붙이기 방식으로 이어 쓴다.
3. `pipeline.workflow`가 격리 옵션을 전달하고 OCR부터 최종 업무까지 같은 비용 한도를 적용한다.
   기존 실행·캐시 증거를 덮어쓰거나 공유 캐시를 암묵적으로 사용하지 않는다.
4. 매 관찰의 ref·순서·구조 변경과 캐시 입력 실패를 fake로 재현해 한도 내 재시도,
   임시 매핑 무효화·일반 모델 복귀·원본 보존·전체 성공 후 승격을 확인한다.
5. 필수 lint/format/전체 테스트를 완료하고 사용법·진행 기록을 갱신한 뒤 비공개 원격에 푸시한다.

## 비교 실행 준비

`config/harness_agents.m2-workflow-cache-isolated.json`은 같은 문서 입력·모델·예산으로
캐시 없음/cold/정확 일치 snapshot/재연결 snapshot을 선택할 수 있는 예시다.
입력 manifest와 동결 캐시는 사용자가 준비한 명시적 비공개 경로이며 자동 생성하거나 학습하지 않는다.
각 실행은 새 건 폴더를 사용하고 OCR 비용과 ERP 비용을 합산한다. 준비 실패는 입력을 막는다.

실제 화면 비교·추가 서류 변형 실측·실제 캐시 실패 복구율·M1 전체 매트릭스는 이번 실행에서
진행하지 않는다. 테스트 통과를 새 GUI 성공률이나 마일스톤 종료 승인으로 표시하지 않는다.

## 자동 검증 범위

- 입력 대상 재선택: 쿼리/등록 정상 복귀, 새 참조 사용, 진행 후에도 누적되는 실행 전체 한도,
  비활성 설정, 없는/비활성 대상·권한·전경·비용·단계 제한, 전송 후 오류의 재선택 차단.
- 캐시 실패 복구: 매 관찰마다 참조·순서가 바뀌는 가짜 환경에서 직접/모델 제안 매핑의
  실패 횟수와 무효화를 확인하고 일반 모델로 복귀한다. 임시 매핑 실패는 원본 항목을 변경하지 않는다.
  전체 성공 시 새 설명을 저장하고 최종 조회 불일치 시 후보를 모두 폐기한다.
- 준비된 서류 연결: 실제 CLI와 Brain 경로를 가짜 중계·모델로 연결해 OCR 기록 접두부와
  전체 비용 한도를 확인한다. 손상/불일치한 준비 근거와 기존 실행은 재사용하지 않는다.

입력 대상 설정은 `max_input_target_retries`이며 기본1,0은 비활성,최대3이다.
모든 재선택 호출은 기존 ModelClient 계측과 예산 검사를 거친다. 이 옵션은 캐시 실패 재시도
`cache.max_retries`와 별개이며 D6 제안 결정을 확정하지 않는다.

격리 출처 기록은 새 쓰기에 비공개 스키마0.2를 사용하고 과거0.1을 읽을 수 있다.
준비된 서류 여부와 OCR 로그 해시/이벤트 수를 기록하고 종료 시 기존 로그 접두부를 재확인한다.
캐시 항목 저장 형식0.1은 바꾸지 않아 기존 동결 캐시를 그대로 입력할 수 있다.

## 검증 기록

- 전체 일반 테스트591개 통과(248.15초), ruff check·format 검사 통과.
- 후속 읽기 검토에서 빈 준비 로그가 비용 기록을 누락시킬 수 있는 경계를 발견해,
  비어 있는 로그도 캐시/모델 실행 전에 거절하도록 보완했다. 관련80개를 재검증했다(24.66초).
- 새 입력 대상 재선택18개·캐시 실패 전체 흐름3개, 준비된 서류의 실제 CLI 연결과
  상태/레코드/로그 정체성·접두부 보존·실패/중단 출처 기록·공통 예산을 검증했다.
- CLI 도움말과 네 비교 설정의 동일 입력·모델·예산 및 명시적 메타데이터 경로를 확인했다.
- 실제 화면·유료 모델 호출은0회다. 기존 실측 결과를 새 코드의 성능으로 재표시하지 않는다.
