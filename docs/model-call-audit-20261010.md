## 근본 원인과 수정 우선순위

1. `model_calls`가 로컬 검출과 원격 추론을 한 수치로 합친다. 요약을
   `local_perception_calls`, `reasoning_calls`, `reasoning_repair_calls`로 분리해야 한다.
2. `POST_ACTION_REVIEW_RULES`는 증거 검토 응답에 `operation=stop, steps=[]`를 강제한다.
   그래서 배치 입력 후 같은 화면을 모델에 한 번 더 보내야 한다. 모델이 한 응답에
   `evidence + next action`을 반환하게 하고, 런타임이 **증거 저장을 먼저 한 뒤 행동을 전송**하면
   사용자가 요구한 순서를 유지하면서 11→12, 21→22, 26→27의 이중 호출을 없앨 수 있다.
3. `screen_match_taught_target_mismatch`가 두 번째 계획에서도 발생하면 현재 접지 결과를 버리고
   전체 OmniParser+Haiku 관찰을 다시 시작한다. 같은 화면·같은 request hash였던 25/28이 실제
   증거다. 실패 시 전체 재관찰 대신 기존 grounded interpretation에서 plan만 제한 교정해야 한다.
4. 조회 0건 증거가 첫 결과 응답에 포함되지 않아 같은 조회를 두 번 눌렀다. 현재 교육 단계의
   `expected_result`에 해당하는 빈 결과 메시지/table state를 계획 전에 필수로 읽게 하면
   15~17 구간의 재조회와 후속 보완을 줄일 수 있다.
5. 상세 열기에서 단일 클릭을 두 번 반복한 뒤 좌표 보완과 전체 재계획을 거쳐 더블클릭했다.
   좌표가 맞고 화면 변화가 목표 후조건을 충족하지 않았다는 사실을 action effect에 남겨,
   같은 semantic target의 다음 후보 gesture를 기존 접지 위에서 고르게 해야 한다.
6. Haiku 한 호출의 입력이 13.4k~20.6k 토큰이고 모든 호출의 `cached_input_tokens=0`이다.
   정적 규칙·사용자 교육·스키마와 현재 화면의 동적 OCR/marker를 분리하고, 모델에는 현재
   subgoal·선택 가능한 control·미충족 후조건만 보내야 한다.

현재 기록으로는 호출 수를 무조건 11회로 고정할 근거는 없다. 다만 새 화면 판단 11회에
후검토가 필요한 화면을 합쳐도 Haiku 13~15회가 현실적인 1차 목표다. 동일 실행에서 외부 모델
지연을 약 156.6초에서 95~110초 범위로 낮출 가능성이 있다. 다음 warm run은 성공 후 승격된
14개 visual-match 캐시의 적중률을 별도로 측정해야 하며, post-action review는 현재 코드상
캐시 조회가 금지되어 있어 캐시만으로 위 구조적 중복은 없어지지 않는다.
