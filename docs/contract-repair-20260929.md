# 응답 계약과 무진행 복구 수정 — 2026-09-29

[앞선 원인 진단](model-root-cause-20260929.md)에 따라 사용자가 수정과 재실행을 요청했다.
기존 안전 검증·비용·실패·단계 한도를 유지하며 다음을 구현했다.

- 모델 응답을 `decision` 객체로 감싸고 act/stop/duplicate/complete를 구조적 union으로
  나눴다. 행동별 필수 target/source도 내보내는 스키마에 표현했다. 기존 내부 Decision과
  공개 relay 계약은 유지하며, 새 외부 응답 계약은 과거 요청 해시와 호환되지 않는다.
- 현재 단계에 맞는 안내를 제공하고 지난 단계의 보완 지침은 재전송하지 않는다.
- 검증 실패에 안전한 type/field path/rule만 기록한다. 원문 입력·예외 문구·동적 필드명은
  로그에 넣지 않는다. 신뢰된 schema의 분기명만 제거해 실제 필드 경로를 보존한다.
- 관찰의 ref·포커스·좌표·외부 화면 해시를 제외한 의미적 상태로 탐색 변화를 확인한다.
  변화 없는 행동은 실패로 세고, 그 대상은 현재 관찰에서 다시 대응시켜 모델에 제공한다.
  같은 상태의 같은 실패 대상 재선택은 실행 전에 차단한다. 실제 상태가 바뀌면 다시
  선택할 수 있다. 관찰 변화는 업무 완료의 증거로 사용하지 않는다.
- 관찰에서 얻은 실패 대상 설명도 신뢰하지 않는 화면 데이터로 취급한다.
- 세 번째 GUI에서 비밀번호 입력 반복이 발생해, 현재 창·컨트롤에 입력을 전달했다는
  상태를 기억하고 같은 입력의 재전달을 실행 전에 차단했다. 비밀번호 값 확인이나
  인증 성공으로 간주하지 않으며, 창 변경·사용자명 변경 시 제출 상태를 재평가한다.

모든 실측은 같은 `gemini-3.5-flash-lite`와 ModelClient를 사용했다. 각 호출의 예약 비용,
토큰, 비용, 지연을 기록했으며 SDK 자동 재시도를 사용하지 않았다. 실제 GUI와 아래
저장 관찰 실험은 구분한다. 원래 유실된 오류 응답을 복구했다고 주장하지 않는다.

진단 호출은 총 12회, $0.01613588이며 화면 조작은 없다. 모두 비용이 확인됐고 HTTP
오류는 없었다. 첫 검색 실험 뒤 계획 요청과 행동 선택 지침을 구분하는 문구를 명확히 했고,
탐색 단건 실험 뒤에는 실패 대상 설명을 비신뢰 데이터로 명시하는 문구를 추가했다.
단건 요청과 최종 GUI 요청이 모두 같은 소스 해시였다고 표시하지 않는다.

중복 근거 실패 요청은 첫 GUI 실행의 1–8번째 요청 해시를 모두 일치시켜 복원했다.
설명을 강화한 비교군과 enum 비교군은 프롬프트 바이트·모델·화면·상태가 같고,
내보낸 스키마의 `const`를 동등한 단일 값 `enum`으로 바꾼 것만 다르다.
const 비교군은 3/3 필수 grid_ref를 누락했으나 enum 비교군은 3/3 현재 활성 결과표의
문자열 ref를 제출했다. 이는 해당 요청에서 스키마 표현의 호환성 영향을 보여준다.
제공자 내부에서 어떤 제약을 무시했는지 직접 관찰한 것은 아니다.

[Gemini 공식 문서](https://ai.google.dev/gemini-api/docs/generate-content/structured-output?hl=en)는
enum 지원, JSON Schema 부분집합, 미지원 속성 무시 및 애플리케이션 검증 필요성을
설명한다. 이를 근거로 외부 WireModel의 내보내기에서 const를 enum으로 바꿨다.
요청 해시와 비용 예약도 동일하게 변환된 스키마를 사용한다. 로컬 Literal 검증은 유지한다.
다른 제약의 제공자 지원까지 일반화하거나 출력 검증을 제거하지 않는다.

## 실제 GUI 실행

모두 개발 시드 0 / stable / label_grouped / 새 DB이며 실제 데스크톱은
3840×2160, 시스템 DPI 144(150%)다. 실행 사이 코드를 수정했으므로 동일 코드의
반복 성공률로 합산하지 않는다. 실패를 보존하고 후속 실행을 별도로 기록한다.

두 번째 실행은 모델 응답 25개가 모두 유효하고 503과 전경 이탈이 없었다. 무진행 검증이
실제로 반복을 중단했지만, 실패한 컨트롤 정보가 피드백에 없어 같은 선택이 반복됐다.
이를 반영해 현재 ref로 대응한 실패 대상 목록과 실행 전 재선택 차단을 추가했다.
후속 단건은 관찰된 문서 닫기 컨트롤을 선택했다. 코드·프롬프트에 해당 ERP 라벨이나
ref를 넣거나 닫기를 자동 실행하지 않았다.

세 번째 실행은 응답 81개가 모두 유효하고 HTTP/503·전경 이탈이 없었지만 로그인 전
비밀번호 입력을 반복했다. 이후 입력 전달 기억과 반복 차단을 추가했다. 저장 관찰의
단건 호출은 정상 로그인 행동을 선택했으며 실제 클릭·인증·전체 업무 검증은 하지 않았다.

GUI 세 건의 확인 가능한 비용은 $0.13250364, 진단 12회를 합하면 $0.14863952다.
코드 변경을 사이에 둔 실패들이므로 동일 코드 반복 성공률로 합산하지 않는다.
비공개 전체 테스트 **237개 통과(108.31초)**, ruff·format 검사를 통과했다.
수정 후 GUI를 시작하기 전 사용자가 L2C 구현 조사를 요청해 재실행을 보류했다.
[L2C 비교와 다음 구현 순서](l2c-lessons-20260929.md)를 참고한다. 경량 전체 성공은
