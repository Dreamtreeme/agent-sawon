# 현행 런타임 기준

기준일: 2026-10-21

이 문서는 Agent Sawon의 현재 운영 기준입니다. `CODEX_BRIEF.md`, 날짜별 보고서, 과거 실행
기록과 내용이 다르면 이 문서와 체크인된 설정·코드를 우선합니다. 모델, 비용, 실행 경계가
바뀌면 구현과 함께 이 문서를 수정합니다.

## 실행 경로

화면 캡처 직후 유사도를 확인한다. 일치하면 Memory Retrieval, 미일치하면 Scanning으로
분기한 뒤 Context Recall → Pattern Matching → 화면 판단 경로로 연결한다. 기억 경로는
필드 기하·입력 키 대응·절차를 인출하고 현재 값은 OCR로 읽는다. Context Recall은 이번 실행의
상태를 읽기만 하며 모델 판단·검증·복구는 `screen_decision.py`가 담당한다.
같은 창·크기의 pHash 유사 캡처는 로컬 탐지 기하를 재사용하되 OCR은 현재 프레임에서 다시
실행하고 문맥·패턴·판단 순서를 거친다. 카탈로그 유사도도 `methods.max_phash_distance`를
사용하며 SHA256 완전일치는 사용하지 않는다. 성공 기록 정제는 Memory Compilation이다.
분기 조건과 저장 형식은 [용어와 코드 대응](runtime-terminology.md)에 명시한다.

1. `pipeline`이 문서를 렌더링하고 GPU OCR·추출·교차 검증을 수행합니다.
2. `brain.run`이 `TaskInstruction`, 입력 record, 설정과 relay를 연결합니다.
3. 작업자 그래프가 `WorkerState` 하나를 `Observation`, `Decision`, `Review`, `Execution`
   책임 노드 사이에 전달합니다. 다음 노드는 `lifecycle.route`가 결정합니다.
4. 환경 관찰과 입력은 `sawon_interfaces` 계약을 사용하는 relay HTTP로만 수행합니다.
5. 전체 성공한 원본 실행만 화면 캐시와 기억 편찬의 승격 근거가 됩니다.

기억 편찬 응답의 `context_anchors`가 8개를 넘으면 원래 순서의 첫 8개를 보존하고 초과분은
경고로 기록합니다. 후보 ID와 실행 필드의 검증은 유지합니다. 계약 위치와 경고 형식은
[계약 지도](contracts.md)를 참고합니다.
편찬 전체 설명문 `MemoryAssembly.purpose`는 300자까지 허용하고 산출물에 원문을
보존합니다. 그룹별 설명문과 다른 필드의 제한은 변경하지 않습니다.

업무별 버튼명, 좌표, 탭 순서는 프로덕션 코드에 넣지 않습니다. 사용자가 가르친 절차는
`TaskInstruction.procedure`에 참고 지식으로 보존하고, 현재 관찰과 함께 모델이 해석합니다.
같은 판단에서 추가 조회한 교육 상세는 후속 빈 행동 보완 요청에도 유지합니다.
이는 턴 간 교육 상세의 영구 보관을 뜻하지 않습니다.
저장 후 상세 검토가 처음 시작되면 현재 화면의 증거를 반영한 뒤, 그 이전 문맥으로 생성한
다음 계획을 같은 캡처에서 다시 선택합니다. 상세 재진입에서는 전환 대기만 해소하고 누적
검토 증거를 보존합니다. 완료된 교육 단계 선택은 실행을 차단하지 않으며 교육 초점을 되돌리지
않습니다. 이 경계의 재판단은 모델 호출을 추가할 수 있습니다([계약](contracts.md)).
구형 `--procedure`/`procedure_path` 진입점은 사용하지 않습니다.

## 화면 관찰과 의미 매핑

- PaddleOCR은 보이는 문자열과 bbox를 만듭니다.
- OmniParser v2는 조작 가능한 후보 bbox를 만듭니다. Florence-2 기능 캡션은 사용하지 않습니다.
- 로컬 의미 탐지 단계는 제공된 후보를 분류하기 위해 실행 중에만 유효한 marker ID를 사용할 수
  있습니다. 이 번호는 화면 요소의 영구 식별자가 아닙니다.
- 업무 판단 단계의 `ScreenMapping`은 스크린샷, OCR 텍스트+bbox, 컨트롤 bbox와 작업 상태를
  받아 `수량`, `포장정보/단위` 같은 보이는 의미 이름, 입력 key, 행동 point를 반환합니다.
  지속 상태와 편찬된 기억은 detector 번호를 업무 key로 저장하지 않습니다.
- 성공한 좌표는 같은 viewport와 허용 pHash 거리에서만 편찬된 기억로 재결합합니다. 결합에
  실패하면 현재 화면 모델 경로로 돌아갑니다.
- 인출된 입력 증거도 현재 화면의 대상 목록에 등록하여 관찰·메모 갱신까지 전달합니다.
  현재 OCR에서 입력값이 일치한 경우에만 증거가 되며 행동 전달만으로 확인 처리하지 않습니다.
- 편찬된 저장 결과는 분류, 메시지 이름·위치·텍스트, 수정 필드를 함께 보관합니다.
  현재 화면에서 메시지가 재결합되면 `save_result` 단계도 같은 메서드를 사용합니다.
  메시지가 다르거나 없는 경우와 저장 결과가 없는 구형 산출물은 기존 캐시·모델 판단을
  사용합니다. 구형 산출물은 새 정보를 포함하도록 재편찬해야 합니다.

전체 화면 픽셀 해시와 캡처 해시는 관찰 메타데이터, 캐시, 안정화 측정에 사용할 수 있습니다.
relay는 같은 허용 창·캡처 크기 안에서 픽셀이 달라졌다는 이유만으로 행동을 거절하지 않습니다.
관찰 만료, 창·DPI·캡처 기하 변화, 허용 창 이탈과 좌표 경계 검사는 유지합니다.

## 현재 사용하지 않는 동작

- 고정 선적 상태 기계와 구형 Procedure 로더
- Florence-2 기능 설명을 입력칸 의미로 사용하는 경로
- detector/Set-of-Mark 번호를 지속 업무 key로 저장하는 경로
- 입력 직전 전체 화면 픽셀의 정확한 일치만으로 행동을 거절하는 경로
- 날짜별 실험 프리셋을 운영 설정으로 자동 선택하는 경로

이 목록의 기능을 되살리려면 새 요구사항, 현재 코드 근거, 회귀 검증이 필요합니다. 과거 문서에
남은 설명만으로 복원하지 않습니다.

## 검증 기준

테스트 총개수는 계약이 아닙니다. `677 passed` 같은 과거 수치는 당시 기록으로만 취급합니다.
현재 기준은 저장소 루트에서 실행한 아래 명령의 실제 결과입니다.

```powershell
.\.venv\Scripts\python.exe -m ruff check .
.\.venv\Scripts\python.exe -m ruff format --check .
.\.venv\Scripts\python.exe -m pytest
```

실제 화면 동작을 바꿨다면 core 테스트만으로 완료를 선언하지 않고 bench의 relay 테스트와
파일럿 화면·로그를 함께 확인합니다.

## 실행 계약 보완 (2026-10-23)

- 화면 관찰에서 이미 얻은 현재 계획은 직전 이동의 무진행 처리 후에도 Review에 전달한다.
  실패 이력과 중단 한도는 유지하며, 새로운 계획을 실행했다고 기록하지 않는다.
- 현재 visual 경로의 `pagedown` / `pageup`은 viewport 휠 이동으로 전달한다.
  실제 키 전달로 바꾸는 실험은 텍스트 입력 포커스에서 무진행을 일으켜 철회했다.
- relay는 현재 허용된 입력 창을 우선 복구하고, NOACTIVATE 보조 창은 열거 후보에서 제외한다.
- 정상 업무 수행 검증에는 시드별 교육을 연결한다. 하나의 교육을 모든 시드에 고정하는
  비교 실험은 교육과 화면 배치가 다를 수 있으므로 별도 조건으로 보고한다.

저장 완료 응답 `ready_for_query`의 단일 `click + confirm_save`는 계약 변환부에서
`navigate`로 정리한다. 모델 원문, 대상, 좌표는 바꾸지 않으며 변환을
`save_acknowledgement_intent_normalized` 이벤트로 기록한다. 저장 승인 대기
`confirmation_required`의 `confirm_save`는 유지한다. 안내 닫기를 업무 완료로 간주하지 않는다.
