## 실행 경로

정보 수집 업무는 `TaskInstruction.result_keys`에 결과 항목만 선언한다. 검색어 등 공급 입력과
화면에서 처음 읽을 값은 분리하며, 명시적으로 관찰한 결과 값은 기존 화면 노드에 누적한다.
다음 판단의 `notebook.collected_result`와 종료 시 로컬 `task-result.json`은 같은 기억에서
값·출처·누락 항목을 파생한다. 수집 결과를 입력 검증 완료로 취급하거나 과거 값으로 채우지 않는다.
수집 source 하나에는 모델이 화면의 줄바꿈을 종합한 완전한 업무 값 하나를 반환한다.
OCR 줄마다 같은 source를 붙이거나 설명문 전체를 값으로 저장하는 계약이 아니다.
교육에서 `fill.input_key=collected_result.<결과 키>`를 지정하면 이번 실행에서 읽은 값이
기존 입력 실행 경로로 전달된다. 제공 입력은 변경하지 않고 현재 누적 메모에서 실행값을
파생한다. 원본 관찰 키와 목적지 참조 키를 구분하여 목적지의 빈칸이 원본을 지우지 않게 한다.
읽기 전에는 실행값이 없고, 원본의 정정·명시적 빈값은 다음 입력에 반영한다. 모든 수집 사실을
입력 의무로 추가하지 않는다. 세부 생산자·소비자와 수명은 [계약](contracts.md)에 정리한다.
교육에 수집 참조로 선언한 HBL 등의 식별자는 사전 제공하지 않고 화면에서 읽을 수 있다.
일반 식별자의 오타·누락 거절은 유지하며, 읽은 뒤의 조회·입력·숫자/단위 비교는 기존 실행과
같은 의미를 사용한다. 이 연결의 무료 회귀와 실제 앱 자료를 이용한 검증은 구분하여 보고한다.
모델은 relay가 관찰한 창 목록에서 `focus_window`를 선택할 수 있다. 창 전환은 좌표 행동과
분리해 전달하고 새 화면을 관찰한다. 실행별 창 handle은 재사용 캐시나 메서드에 저장하지 않는다.
`available_apps`의 등록 앱은 `open_app`으로 열 수 있다. 실행 대상과 창 규칙은 relay 설정에
두고 모델은 앱 ID만 선택한다. 기존 창이면 전환하고 없으면 정상 실행 후 관찰한다.
첫 관찰에서 허용 전경 창이 없고 `foreground_not_allowed`와 등록 앱 목록을 받으면, 모델은
화면 없이 업무 교육과 앱 목록으로 첫 앱을 고른다. 기존 `ScreenMatch`·실행·relay를 사용하며
바탕화면을 OCR하거나 임시 화면 요소를 만들지 않는다. 열린 앱의 다음 관찰부터 정상 탐색을
수행한다. relay의 `restore_allowed_focus`가 먼저 창을 고른 시작과 이 모델 선택 시작은 구분한다.
초기 진입 이후의 차단 처리는 유지한다. 구현·합성 검증과 실제 앱 실행의 성공은 구분한다.

화면 캡처와 현재 OCR 뒤 다음 기억의 결합 가능성을 확인한다. 일반 그룹은 viewport·pHash를,
활성 메서드의 다음 저장 결과 그룹은 현재 메시지와 행동 대상의 OCR 앵커를 사용한다. 일치하면
Memory Retrieval, 미일치하면 OmniParser 탐색으로 분기한 뒤 현재 실행 계약을 확보하고
Pattern Matching → 화면 판단 경로로 연결한다. 기억 경로는
필드 기하·입력 키 대응·행동과 절차를 인출하며 과거 관찰값은 인출하지 않는다. Context Recall은 이번 실행의
상태를 읽기만 하며 모델 판단·검증·복구는 `screen_decision.py`가 담당한다.
메서드의 다음 행동이 결합되면 입력 후 확인 대기만으로 모델용 문맥을 조립하거나 재판단하지 않는다.
화면 캐시 조회나 모델 판단·복구가 필요할 때 Context Recall 문맥을 한 번 생성해 재사용한다.
한 판단의 캐시 키도 조회와 후보 저장에서 공유한다. 저장 결과의 현재 모델 검토가 필요한
경로는 곧 폐기할 화면 캐시를 읽지 않으며, 기존 검토·성공 판정은 유지한다.
결합 전 현재 화면·메서드 문맥의 snapshot을 확보한다. `frame_input`이 OCR와 컨트롤의 포함
관계를 보존해 한 번 투영하고, 최종 프롬프트는 이 화면을 다시 구성하지 않는다. 새 화면 입력
구조는 캐시 키에도 반영되며 과거 캐시 파일을 소급 변경하지 않는다.
이미 검증·정리한 응답은 재사용하고 보완으로 응답 내용이 바뀌었을 때만 다시 검증한다.
같은 창·크기의 pHash 유사 캡처는 로컬 탐지 기하를 재사용하되 OCR은 현재 프레임에서 다시
실행하고 문맥·패턴·판단 순서를 거친다. 카탈로그 유사도도 `methods.max_phash_distance`를
사용하며 SHA256 완전일치는 사용하지 않는다. 성공 기록 정제는 Memory Compilation이다.
캡처 pHash는 카탈로그에서 재사용하고 모델에는 원본 캡처를 직접 전달한다. 번호표 이미지는
기하가 생성·변경될 때만 진단용으로 저장한다.
분기 조건과 저장 형식은 [용어와 코드 대응](runtime-terminology.md)에 명시한다.
모델은 화면 판단 응답의 `screen_path`로 부모 창과 활성 탭을 선택한다. 실행 중 기억은
`screen_nodes`에 분리해 보관하며, pHash 유사도만으로 이전 필드를 현재 관찰에 추가하지 않는다.
경로 없는 과거 편찬 기록의 노드를 추정하지 않으며, 새 매핑이 있을 때 노드 기억을 갱신한다.
탐색한 필드와 컨트롤은 부모/자식 경로에 누적하며 모델에는 `screen_tree`로 전달한다.
과거 좌표는 모델용 트리에서 제외하고 현재 이미지/OCR로 다시 연결한다. 입력 전달 이력은
필드별로 유지하여 스크롤이나 다음 배치 뒤에도 사라지지 않는다. 관찰값은 노드 필드 한 곳에
저장하고, 확인 대기는 같은 입력 키의 전달·관찰 순번에서 계산한다. 가시성·일치 상태 플래그나
전역 관찰 복사본은 두지 않는다. 화면을
다시 읽어 확인한 값과 전달만 성공한 값을 구분한다. 저장 전후의 의미는 모델이 경로·행동 이력과
사용자 조건을 함께 보고 판단한다([계약](contracts.md)).
모델 응답이 있는 관찰의 기억 갱신은 모델이 선택한 경로·명시적 입력 키 연결·읽은 값을
그대로 병합한다. 다음 행동이나 OCR 투영으로 기억을 다시 해석하지 않는다. 행동 선택·실행과
증거 기록은 같은 `fields[].source/value`를 사용하며, 기억 갱신용 별도 모델 호출은 추가하지 않는다.
대상 이름 일부·표시 값·컨트롤 role로 모델의 대상을 재추론하지 않는다. 입력 증거는 명시적
필드 source/value에서 파생하며, 실행 가능한 행동이 있다는 이유로 모델의 재탐지 요청을 지우지 않는다.
일반 화면 판단과 교육 조회·행동 보완·재계획 응답은 `purpose`에 선택 근거를 한국어 1~3문장,
160자 이내로 명시한다. `observed_step_results[].observed_result`에는 판단을 뒷받침하는
현재 화면 증거와 관련된 이전 메모를 짧게 적는다. 기존 응답 필드를 사용하며 단계별 내부
추론을 요구하거나 근거 설명을 새 행동·완료 증거로 간주하지 않는다.
정상 Memory Retrieval은 편찬 경로의 다음 그룹에 저장된 `screen_path`, 필드 의미·입력 키·좌표와
행동을 복원한다. 기억 인출과 행동 결합은 같은 경로 선택 함수를 사용한다. 메서드를 선택한 뒤에는
그 메서드를 유지하고, trace 순서의 남은 첫 그룹만 결합한다. 유사한 과거·후속 행동을 다시 경쟁시키거나
교육 순서로 편찬 경로를 재정렬하지 않는다. 경로를 모두 진행한 뒤 완료 기억을 결합한다.
`MemoryRetrieval._restore_structure`는 `value` 없는 필드와 행동으로 `ScreenMapping`을 구성한다.
입력 문자열은 실제 실행 시 현재 `request.values`에서 가져온다. 새 편찬물은 `field_values`를
저장하지 않고, 구형 산출물에 남은 해당 키는 로더에서 버린다. 원본 기록 파일을 소급 변경하지 않는다.
현재 실행에서 모델이 확인한 누적 메모는 이력으로 보존하지만, 인출한 매핑의 현재 값으로 복사하거나
새 관찰 ID·순번의 `last_observation`·verified·교육 완료로 다시 발행하지 않는다. 구조 매핑에 값이
없으면 미확인으로 유지하며 OCR이나 입력 요구값으로 채우지 않는다. 모델이 현재 응답에 명시한
빈 문자열만 빈칸 관찰이다.
입력 후에도 다음 메서드의 `act`가 결합되면 입력·스크롤·탭 이동·저장을 이어간다. 전달만 확인한
입력은 검토 유예로 남기며 verified·현재 관찰값·업무 완료로 바꾸지 않는다. 실제 전달 기록은
저장 행동의 자격에 사용할 수 있지만, 저장 결과와 최종 완료의 증거를 대신하지 않는다.
정상 기억 인출은 조회 입력의 미확인·상세 진입 대기 때문에 모델을 호출하지 않는다.
다음 행동 또는 완료 화면이 결합되면 이번 업무 값으로 경로를 계속 수행한다. 실행 이력으로
경로가 소진되고 현재 완료 화면이 일치하면 `method_route_complete`로 종료하며, 이 결과는
모델의 필드별 값 검증과 구분한다. verified·과거 관찰값·교육 완료를 만들어 채우지 않는다.
화면·필수 구조·저장 결과 불일치나 실행 실패에서는 기존 `ScreenMatch`로 탐색·복구한다.
실제 `_fail`이 발생한 메서드는 재사용을 보류하고 미리 만든 기억 계획도 폐기한다. 화면 캐시가
그 복구를 우회하지 않으며 현재 모델 응답을 수용한 뒤 다시 경로에 연결한다.
단순 화면 무변화나 확인 유예 자체는 이 실패를 뜻하지 않는다.
화면 캐시는 `act` 행동 계획만 재사용하고 중복 조회·완료·중단 판정은 현재 모델이 한다.
다음 계획 미결합이나 저장 결과 메시지·실행 계약 불일치도 기존 모델 판단으로 전환한다.
저장 결과 그룹은 공통 바인더로 현재 메시지와 확인 대상의 위치를 결합하고, 인출과 행동 준비가
같은 현재 기하를 사용한다. 업무 값 글자 때문에 전체 이미지 pHash가 달라져도 이 결합은 가능하다.
현재 대상을 연결하지 못하면 기존 모델 경로로 넘긴다. 실제 OCR 앵커가 없는 과거 저장 결과
그룹은 원문과 편찬 응답으로 재편찬하며, 모델이 붙인 대상 이름에서 앵커를 추정하지 않는다.
인출 예외는 `memory_retrieval_exception`, 기존 실행 검증 실패는 `method_fallback`에 이유를 남긴다.
모델 요청은 인출된 필드 구조·입력 요구값·현재 실행의 누적 메모·현재 OCR을 구분해 전달한다.
빈 행동 보완의 마지막 전체 관찰을 적용하며 이전 응답의 필드를 합쳐 오탐을 되살리지 않는다.

로그인은 일반 화면 행동과 같은 `ActionPlan`으로 순서 실행한다. 준비 클릭·credential 입력·
Tab/Enter·제출 순서를 보존하고, 전용 로그인 배치 문법으로 재계획하지 않는다. 사전 검사의
예상 credential 전달 사실과 relay가 확인한 실제 전달을 구분하며 실제 메모는 확인된 전달에서
한 번 갱신한다. 입력 실패 시 후속 제출은 실행하지 않고, 제출 후 관찰로 인증 결과를 검토한다.

현재 캡처의 대상에 연결한 다중 행동은 클릭·입력·키·스크롤이 섞여도 같은 `ActionBatch`로
전달한다. 실행 직전 한 번 좌표와 현재 업무 값을 준비하며 행동마다 캡처·좌표 결합을 반복하지
않는다. relay는 목록을 순서대로 수행하고 마지막에 한 번 관찰한다. 입력 후 스크롤까지 한
묶음으로 수행한 다음 새 관찰에서 가려졌던 필드를 연결할 수 있다. 전달 성공한 입력은 메모에
남지만 완성된 입력 계획 자체를 관찰값이나 업무 완료 증거로 쓰지 않는다.

1. `pipeline`이 문서를 렌더링하고 GPU OCR·추출·교차 검증을 수행합니다.
2. `brain.run`이 `TaskInstruction`, 입력 record, 설정과 relay를 연결합니다.
3. 작업자 그래프가 `WorkerState` 하나를 `Observation`, `Decision`, `Review`, `Execution`
   책임 노드 사이에 전달합니다. 다음 노드는 `lifecycle.route`가 결정합니다.
4. 환경 관찰과 입력은 `sawon_interfaces` 계약을 사용하는 relay HTTP로만 수행합니다.
5. 전체 성공한 원본 실행만 화면 캐시와 기억 편찬의 승격 근거가 됩니다.

`screen_plan_proposed.mapping`은 행동 캐시에 없는 최종 완료 응답까지 의미 매핑을 보존한다.
편찬은 이 매핑(과거 기록은 캐시)을 읽어 화면 경로와 완료 대상·조건을 기록한다.
행동 정제에는 실제 전달 이력만 사용한다. 최신 기록은 화면 캐시를 읽지 않고 로그의 응답
해시를 출처로 남긴다. 매핑이 없는 과거 기록에서만 캐시를 읽는다. 편찬 중에는 행동 그룹을
직접 만들고 최종 메서드를 한 번 조립한다. 제거한 행동 구간 뒤에는 진입 화면과 관찰 기억도
함께 연결하며 유지 행동의 좌표는 바꾸지 않는다.
매핑을 재투영하며 바뀐 임시 ID는 의미 이름으로 행동에 다시 연결한다. 편찬 모델에는 필드와
OCR의 위치, 실제 전달 행동, 후속 교육 관찰을 함께 제공한다. 잘못된 필드 이름은
`field_renames`로 교정하여 행동 대상과 관찰 기억에 함께 반영한다. 이는 이름 교정이며
기록된 좌표·행동 종류·입력 키는 유지한다. 기존 편찬물의 잘못된 이름은 자동으로 바뀌지 않는다.
원본 전달과 검토된 같은 행동의 대체가 경로를 진행시킨다. 분할 배치는 기존 전달 이력의
`action_progress`로 수행 범위를 누적하고 남은 행동만 인출한다. 입력 검토를 유예해도 relay가
확인한 fill의 연속 전달 범위는 진도에 반영하며, 값 확인 상태는 provisional로 유지한다. 스크롤의 휠 위치는 입력칸
bbox와 비교하지 않으며 방향을 연결한다. 그룹 전체가 연결될 때만 `replaced_edge`로 소진한다.
모델이 다른 경로로 목적 화면에 도착했다고 판단하면 현재 응답의 `resume_group_id`로 다음
그룹을 지정한다. 남은 그룹의 목적·행동·기대 결과를 문맥으로 제공하고, 앞의 경유 그룹을
`method_route_resumed`로 기록한다. 지정하지 않으면 현재 응답이 교육 완료를 확인한 연속
선두 그룹을 재개하는 기존 경로를 사용한다. 편찬물·캐시의 과거 재개 지점이나 완료 결과,
전역 교육 완료 집합으로 경로를 건너뛰지 않는다.
생략한 원본 그룹은 전달한 것으로 기록하지 않는다. 누적 검토로 성공한 최종 관찰도 실제
종료 기록과 연결하여 검토 대상·조건으로 편찬하며, 과거 실행의 관찰값이나 확인 완료 집합은
현재 증거로 복원하지 않는다. 기억 경로의 완료는 이번 실행의 경로 진행과 현재 종료 화면으로
판정한다. 탐색·복구의 모델 완료는 기존 현재 관찰·누적 증거 검증을 유지한다. 두 판정은 로그에서
구분하며 과거 성공 플래그만으로 종료하지 않는다.

기억 편찬 응답의 `context_anchors`가 8개를 넘으면 원래 순서의 첫 8개를 보존하고 초과분은
경고로 기록합니다. 후보 ID와 실행 필드의 검증은 유지합니다. 계약 위치와 경고 형식은
[계약 지도](contracts.md)를 참고합니다.
편찬 전체 설명문 `MemoryAssembly.purpose`는 300자까지 허용하고 산출물에 원문을
보존합니다. 그룹별 설명문과 다른 필드의 제한은 변경하지 않습니다.

업무별 버튼명, 좌표, 탭 순서는 프로덕션 코드에 넣지 않습니다. 사용자가 가르친 절차는
`TaskInstruction.procedure`에 참고 지식으로 보존하고, 현재 관찰과 함께 모델이 해석합니다.
같은 판단에서 추가 조회한 교육 상세는 후속 빈 행동 보완 요청에도 유지합니다.
이는 턴 간 교육 상세의 영구 보관을 뜻하지 않습니다.
모델은 직전 메모와 현재 화면을 함께 보고, 확인한 결과와 그 결과에 따른 다음 행동을 한 응답으로
반환합니다. 코드는 명시적 관찰과 교육 결과를 먼저 원본 메모에 반영한 뒤 같은 응답의 계획을
실행 경로에 전달합니다. 메모 반영만을 이유로 재호출하지 않습니다. 완료된 교육 단계 선택은
실행을 차단하지 않으며 교육 초점을 되돌리지 않습니다([계약](contracts.md)).
입력값 이외의 교육 완료도 같은 응답의 `observed_step_results`로 받아 실행 전에 진행 메모에
누적합니다. 완료 조건 해석은 현재 화면과 누적 메모를 받은 모델이 맡으며,
미완료 단계의 부분 관찰도 화면 노드·교육 단계별 목록에 보존합니다. 상단 확인 뒤 하단을 읽어도
상단의 확인 맥락을 지우지 않으며, 다음 모델은 이 메모를 진행된 사실로 사용합니다.
특정 업무의 결과 문구를 코드가 파싱해 다음 행동을 강제하지 않습니다. 모델 전용 경로는
입력 뒤 별도의 배치 재판정을 하지 않고 현재 응답의 다음 계획을 유지합니다. 상세 진입 플래그나
별도 확인 집합을 보관하지 않으며 필드 개수로 자동 완료하지 않습니다. 모델의 `complete`와
사용자 완료 조건을 검증하여 종료합니다. 편찬물의 관찰 완료 결과는 경로 설명으로 보존하지만
인출 응답의 `observed_step_results`는 비웁니다. 이번 실행의 교육 완료는 현재 모델 응답으로
갱신하며 이전 실행의 완료 ID나 과거 관찰 결과를 복사하지 않습니다.
모델 요청은 실행 완료 행동을 `execution.last_delivered_actions` 한 곳으로
전달합니다. 실제 대상 이름과 키/스크롤 방향을 보존하고 아직 수행하지 않은 계획이 섞인
subgoal이나 직전 목적문을 행동·피드백·기억 이력에 반복해 보내지 않습니다. 내부 실행 설명과
편찬·진단 원문은 보존합니다. 목표와 완료 조건은 `task`에서 읽으며 capability는 행동과 입력
범위만 전달합니다. 일반 `TaskInstruction` 업무는 저장 후에도 같은 `task` 판단을 유지합니다.
현재 화면·누적 메모·사용자 완료 조건으로 후속 행동 또는 `complete`를 선택하며,
`message_targets`나 저장 완료 안내문을 별도의 필수 증거로 요구하지 않습니다.
저장 전달 성공만으로 완료하지 않습니다. 교육 없는 고정 `ShipmentRecord` 경로만
`save_result`의 전용 검토 안내와 계약을 사용합니다.
확인 대기 입력 목록은 기록에서 계산하며 별도 성공·검토 대기 플래그는 보내지 않습니다. 행동 전달의
성공이 교육 단계나 전체 업무 완료를 뜻하지는 않습니다.
구형 `--procedure`/`procedure_path` 진입점은 사용하지 않습니다.

## 화면 관찰과 의미 매핑

- PaddleOCR은 보이는 문자열과 bbox를 만듭니다.
- OmniParser v2는 조작 가능한 후보 bbox를 만듭니다. Florence-2 기능 캡션은 사용하지 않습니다.
- 관찰·업무 판단·보완·녹화기는 같은 의미 이름 기반 `ScreenMapping` 모델 계약을 사용합니다.
  marker ID는 로컬 장면·실행 참조이며 모델 입력의 OCR 연결을 위해 재번호화하지 않습니다.
- 업무 판단 단계의 `ScreenMapping`은 스크린샷, OCR 텍스트+bbox, 컨트롤 bbox와 작업 상태를
  받아 `수량`, `포장정보/단위` 같은 보이는 의미 이름, 입력 key, 행동 point를 반환합니다.
  지속 상태와 편찬된 기억은 detector 번호를 업무 key로 저장하지 않습니다.
- 같은 화면 노드·입력 키의 최초 이름을 유지하고 현재 기하와 값은 갱신합니다. 이름이 어긋난
  행동은 현재 좌표가 유일하게 가리키는 선언 영역의 이름을 재사용하며 문자열 유사도로 추측하지
  않습니다. 판단용 스키마·프롬프트는 관찰 뒤 다음 실행 행동까지 요구합니다. 입력 뒤 스크롤도
  같은 배치로 계획할 수 있으며, 로그인만 허용하는 구형 배치 안내는 보내지 않습니다.
- 현재 입력은 전체 OCR와 각 후보 영역 안의 `contained_text`를 함께 보존합니다. 포함 관계는
  위치 관계이며 업무 의미나 빈 입력칸의 source를 코드가 추측하는 규칙이 아닙니다.
  보완도 전체 현재 의미 매핑을 받고 같은 실행 어댑터로 처리합니다. 편찬은 의미 매핑을 직접
  읽으며, 인출은 한 번 결합한 장면을 다시 재번호화하지 않습니다.
- 성공한 좌표는 같은 viewport와 허용 pHash 거리에서만 편찬된 기억로 재결합합니다. 결합에
  실패하면 현재 화면 모델 경로로 돌아갑니다.
- 인출된 필드 구조는 현재 화면의 대상 목록에 등록하지만 현재 입력 증거를 만들지 않습니다.
  이번 실행의 누적 메모는 이력으로 보존하며 현재 모델이 읽은 값만 새 관찰로 기록합니다.
  화면 캐시도 과거 값·교육 완료·저장 결과 판단을 제거한 행동 구조만 재사용합니다.
  화면 유사도만으로 모든 그룹을 완료 처리하지 않으며 현재 진행 순서와 실행 결과를 함께 사용합니다.
- 모델은 scroll과 direction(up/down)으로 휠 이동을 요청한다. 클릭에 keys/direction을
  섞지 않으며 키보드 key에는 pageup/pagedown을 사용하지 않는다. 내부 실행 호환 표현인
  pagedown/pageup 휠 좌표는 현재 이미지 범위로 검사하며 이름 붙인 입력칸 bbox 내부를
  요구하지 않습니다. 클릭·입력은 대상 영역 검사를 유지합니다. 계획의 좌표 거절은 실패한
  행동·bbox·point와 전체 계획 미전달 사실을 다음 모델 요청에 전달합니다([계약](contracts.md)).
- 행동 전후의 구조·위치 변화는 두 캡처의 ORB 특징점으로 비교합니다. 포커스 표시나 캐럿만
  바뀐 것을 이동 성공으로 보지 않으며, pHash 지문의 완전일치 여부로 효과를 판정하지 않습니다.
  캡처가 없거나 대응점이 부족하면 판정 불가로 남깁니다. 입력값·결과 문구·업무 완료는 기존
  OCR·모델·메모 검토로 확인합니다. 기억 인출과 좌표 재결합의 pHash 조건은 유지합니다.
  비교 결과와 출처가 있는 최근 행동 이력은 다음 모델 판단 전에 전달합니다. 이전 행동이
  무변화였더라도 현재 모델 계획을 Review로 넘깁니다. 같은 대상·화면 복귀 여부를 별도
  분류기로 거절하거나 좌표 보완 모델을 호출하지 않습니다.
  새 교육 완료와 저장 전·후 범위별 첫 필드 확인은 진전으로 기록하고, 같은 범위의 재확인은
  진전을 중복 기록하지 않습니다. 현재 완료·중단 응답도 Review로 전달하여 완료 판정
  조건을 적용합니다.
- 기존 편찬된 저장 결과는 분류, 메시지 이름·위치·텍스트, 수정 필드를 함께 보관합니다.
  현재 화면에서 메시지가 재결합되면 일반 `task` 판단의 같은 메서드 행동을 사용합니다.
  메시지가 다르거나 없는 경우와 저장 결과가 없는 구형 산출물은 기존 현재 화면 모델 검토를
  사용합니다. 이 메시지 결합은 해당 기억의 재사용 조건이며 일반 업무 완료의 필수 조건이
  아닙니다. 일반 업무의 현재 모델 판단은 같은 `task` 경로를 사용합니다.
  구형 산출물은 새 정보를 포함하도록 재편찬해야 합니다.

전체 화면 픽셀 해시와 캡처 해시는 관찰 메타데이터, 캐시, 안정화 측정에 사용할 수 있습니다.
relay는 같은 허용 창·캡처 크기 안에서 픽셀이 달라졌다는 이유만으로 행동을 거절하지 않습니다.
관찰 만료, 창·DPI·캡처 기하 변화, 허용 창 이탈과 좌표 경계 검사는 유지합니다.

## 현재 사용하지 않는 동작

- 고정 선적 상태 기계와 구형 Procedure 로더
- Florence-2 기능 설명을 입력칸 의미로 사용하는 경로
- detector/Set-of-Mark 번호를 지속 업무 key로 저장하는 경로
- 입력 직전 전체 화면 픽셀의 정확한 일치만으로 행동을 거절하는 경로
- 편찬 관찰값이나 누적 메모를 새 프레임의 읽은 값으로 복원하여 입력을 생략하는 경로
- 구형 `field_values`와 OCR 일치만으로 인출된 현재 입력 증거를 만드는 경로
- 날짜별 실험 프리셋을 운영 설정으로 자동 선택하는 경로

이 목록의 기능을 되살리려면 새 요구사항, 현재 코드 근거, 회귀 검증이 필요합니다. 과거 문서에
남은 설명만으로 복원하지 않습니다.

## 실행 계약 보완 (2026-10-23)

- 화면 관찰에서 이미 얻은 현재 계획은 직전 이동의 변화 여부와 함께 Review에 전달한다.
  관찰과 실제 전달을 구분하며 새로운 계획을 실행했다고 기록하지 않는다.
- 현재 visual 경로의 scroll/down·up은 내부 `pagedown` / `pageup`으로 변환한 뒤
  viewport 휠 이동으로 전달한다. 기존 편찬 메서드의 실행 표현은 유지한다.
  실제 키 전달로 바꾸는 실험은 텍스트 입력 포커스에서 무진행을 일으켜 철회했다.
- relay는 현재 허용된 입력 창을 우선 복구하고, NOACTIVATE 보조 창은 열거 후보에서 제외한다.
- 정상 업무 수행 검증에는 시드별 교육을 연결한다. 하나의 교육을 모든 시드에 고정하는
  비교 실험은 교육과 화면 배치가 다를 수 있으므로 별도 조건으로 보고한다.

저장 확인창의 `confirm_save`도 일반 행동으로 그대로 전달한다. 화면 매칭에서 별도의
저장 검토 래퍼를 만들거나 그 intent를 `navigate`로 바꾸지 않는다.
확인창 닫기와 전체 업무의 완료 판단은 구분한다.
