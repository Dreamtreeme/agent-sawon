# M2 캐시 재매칭 계획 · 2026-09-29

사용자 지시: L2C와의 차이를 반영해 계획을 다시 정의하고 실행한다.
목표는 화면의 중간 구조와 라벨 변화에서 검증된 입력 경험을 재사용하는 것이다.
기존 시드0/17의 18회 비교와 비용·실패 기록은 보존한다.

## 구현 순서와 완료 조건

1. 기존 정확 일치 모드를 유지하고 별도 `rebind` 설정을 추가한다. 저장 형식은 0.1을 유지한다.
2. 같은 최상위 의미 문맥에서 역할·라벨이 유일하게 대응되는 서로 다른 필드가 기본2개 이상이면
   중간 컨테이너 변화에 대한 직접 재매칭을 허용한다. 중복 대상·소스 충돌은 추측하지 않는다.
3. 라벨까지 다른 남은 필드는 기존 캐시의 업무 필드·관찰 의미와 현재 입력 요소만 모델에 제공해
   묶음으로 재연결한다. 호출은 ModelClient와 기존 예산을 거치며 기본 건당1회다.
   모델은 빈 제안을 반환할 수 있다. 오래된 관찰·존재하지 않는 대상·중복 필드/대상·역할 불일치는 거절한다.
4. 모델 재연결은 실행 내 임시 제안이다. 현재 관찰에서 다시 대상을 찾고 기존 입력 가드·값 재읽기를
   그대로 적용한다. 입력 및 업무 전체 성공 뒤 새 설명을 승격하며, 실패한 임시 제안은 원본 경험을 오염시키지 않는다.
5. 구조 변화·동일 라벨 충돌·잘못된 모델 바인딩·새 ref·값 검증 실패·승격 조건·비용 계측을 fake로 검증한다.
   저장된 개발 관찰은 오프라인 조회 검증에만 사용하고 ERP 내부 자료는 읽지 않는다.
6. 필수 lint/format/pytest 후 코드를 고정한다. 같은 기존11개 스냅샷으로 정확 일치/재매칭 ×
   개발 시드0/17 ×3회, 총12회를 새 계획으로 측정한다. 경량 기본+기존 상위 복구, 건별$0.5,
   전체$2, 240초, 환경 실패1회 뒤 중단. 코드·모델·설정은 측정 도중 바꾸지 않는다.
7. 성공률·필드 정확도·정확/라벨/모델 재매칭 적중·추가 모델 호출·비용을 분리해 보고하고 비공개 GitHub에 기록한다.

## 경계와 한계

좌표·AutomationId·ERP 라벨 사전·고정 경로를 가져오지 않는다. L2C의 국소 적용 판단과 실행 후 검증을
UIA 입력 매핑에 적용한다. 모든 라벨과 문맥이 바뀐 화면은 공통 단서가 부족하면 일반 모델 경로로 진행한다.
모델 제안은 의미적 정답을 보장하지 않으므로 fake와 실제 최종 조회 결과를 구분한다.
고정 스냅샷 반복과 이전 시행의 학습을 누적하는 실험은 다르다. 이번 실험은 전자다.
M1 미완료 측정, M2 종료 점검과 D6–D8 결정은 계속 남는다.
