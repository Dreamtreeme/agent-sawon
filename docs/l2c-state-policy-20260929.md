# L2C 조사 후 상태 정책과 전이 검증 수정 — 2026-09-29

적용 범위는 L2C의 일부 상태·전이 원칙이며 전체 그래프 이식은 아니다.
[현재 그래프 비교와 빠진 책임](l2c-graph-comparison-20260929.md)을 별도로 정리했다.
완료 후보의 선행 조건은 업무 진행 플래그이며 현재 행의 전체 근거 범위까지 포함하지 않는다.

후속 GUI 실행은 DB 10/10 저장 뒤 최종 조회의 화면 밖 필드 근거 부족으로 중단됐다.
[재실행 결과](l2c-rerun-20260929.md)에 전체 성공 여부와 원인을 분리해 기록했다.

사용자의 수정 요청에 따라 [조사에서 제안한 방법](l2c-lessons-20260929.md)을 M1 안에서
적용했다. 현재 업무 단계와 검증 사실에서 모델의 선택지, 응답 스키마, 실행 허용 검사를
함께 도출한다. 이미 입력한 비밀번호나 검증한 필드를 다시 입력하는 선택은 제외하고,
저장·중복 근거·완료는 선행 조건을 확인한 뒤에만 선택할 수 있게 했다.

## 변경

- [policy.py](../brain/graph/policy.py)의 불변 `ExecutionFacts`는 필드·자격증명 source의
  이름과 검증 여부만 담는다. 실제 입력값·비밀번호는 포함하지 않는다. 이 사실에서
  `DecisionPolicy`가 현재 단계와 허용된 intent/행동/source 조합을 만든다.
- 같은 정책으로 프롬프트의 `execution_policy`, 외부 응답 스키마, 실행 직전 검사를
  생성한다. 규칙마다 별도로 운영하던 일부 실행 예외·보완 문구를 제거했다. 현재 ref,
  대상 활성화 여부, 창 허용 범위, 실제 값과 결과 행 근거는 관찰에서 계속 검사한다.
- 저장은 모든 필드의 이전 검증 근거가 있을 때 선택 가능하다. 화면에 이미 값이 있다면
  근거를 제출하는 대기 행동으로 확인한 뒤 다음 판단에서 저장한다. 모델이 아직 확인되지
  않은 근거와 저장을 한꺼번에 요청해 검증 순서를 앞당기지 않는다.
- 새 관찰에서 입력 필드 값이 바뀌면 기존 필드 근거를 무효화한다. 검색 전 조회 입력값이나
  컨트롤이 바뀌어도 입력 선택지를 다시 연다. 검색을 제출한 뒤에는 필수 중복 근거
  검증을 유지하며 조회값 변경을 이유로 그 단계를 건너뛰지 않는다.
- [transitions.py](../brain/graph/transitions.py)의 `ActionTransition`은 행동 ID와
  전후 관찰 ID, 전달 결과, 기대 효과, 실제 관찰 효과, 새 사실의 이름을 연결한다.
  보호 입력 재확인은 비밀번호 값 검증이나 인증 성공으로 기록할 수 없다. 저장 전달과
  최종 조회 필드 검증도 별도 사건으로 유지한다.
- 의미적 화면 이력을 제한된 크기로 기억하고 A–B–A–B, A–B–C–A–B–C 순환을 탐지한다.
  정상적인 한 번의 복귀는 허용한다. 새 조회/필드 근거와 업무 단계 변경으로 이력 범위를
  갱신하며 화면 변화만으로 업무 근거가 늘었다고 취급하지 않는다. 같은 상태의 무효
  로그인 버튼도 재실행 전에 차단한다.
- 화면 이력 크기는 `config/brain.toml`의 `navigation_history_size=12`로 설정한다.
  기존 80단계·같은 하위 목표 실패 2회·건당 비용 상한과 전경 제한은 유지한다.

## 검증 방법

최종 검사: 비공개 `ruff check .`·`ruff format --check .` 통과,
전체 `pytest` **307개 통과(154.20초)**. 공개 저장소도 동일 검사와 비GUI 테스트
**384개 통과(12.46초), GUI 5개 제외**를 확인했다. 공개 런타임 변경은 없다.
공개 테스트에서 기존 Starlette/httpx 사용 중단 예정 경고 1개가 나왔고 실패는 없다.

실제 ERP/API를 반복 실행하는 대신 재현 가능한 fake/replay에서 다음 계약을 검증했다.

| 범위 | 검증 내용 |
| --- | --- |
| 상태 정책 | 내보낸 JSON Schema의 독립 판정, Pydantic 응답 검증, 실행 허용 판정이 일치 |
| 입력과 저장 | 제출한 비밀번호 제외, 잘못된 intent 조합 차단, 현재 근거 제출 후 저장 허용 |
| 변경된 화면 | 변경/소실된 조회 입력과 변경된 등록 필드의 재입력 허용, stale ref 차단 |
| 반복 | 무효 로그인 전달 1회, 재선택 차단, 화면 순환 시 기존 실패 한도 적용 |
| 정상 복귀 | 새 조회값·필드 근거를 얻은 뒤 같은 화면을 다시 방문하는 흐름 허용 |
| 완료 | 동일 결과 행의 전체 필드 검증과 `awaiting_approval`까지 컴파일된 그래프 실행 |

기존 테스트는 새 정책이 더 이른 응답 검증 단계에서 차단하는 부분의 예상 사유를
갱신했다. 실제 relay 전달 금지, 실패 한도, 비밀 정보 비노출, 현재 대상 확인과 최종
필드 근거 검증은 유지했다. 잘못된 응답 두 개를 명시적으로 재생하여 테스트 응답 고갈을
모델 장애로 오인하지 않게 했다.

이번 수정에서 새로운 실제 모델 호출·GUI 실행은 하지 않았다. 회귀 통과는 경량 모델의
전체 화면 성공을 뜻하지 않는다. 다음 실측은 같은 수정 코드·경량 모델로 한 건을 실행해
최종 화면 근거와 내부 성공 상태를 함께 확인하는 것이다. 실제 성공 전까지 M1 종료와
요약 전략 우열을 선언하지 않는다.

L2C 소스나 사이트별 경로는 복사하지 않았다. 새 영속 캐시·Critic·좌표 재생은 도입하지
않았으며, 모든 환경 관찰과 입력은 기존 relay 경계를 유지한다.
