# 사용자 교육 절차의 모델 선례·재사용 레시피

2026-10-03. 사용자가 실제 프로그램의 업무 절차를 자세히 가르치면 첫 실행은 모델이 현재
화면에서 그 설명을 해석해 행동한다. 전체 업무가 성공한 실행만 화면에 다시 결합할 수 있는
레시피로 컴파일하고, 다음 건은 레시피를 우선 실행한다.

## 계약과 실행 흐름

`TaskInstruction.procedure`는 순서가 있는 `id`, `instruction`, `completion` 목록이다. 화면명과
버튼명을 포함할 수 있으며 사용자가 가르친 업무 경로로 취급한다. 코드는 해당 ERP의 라벨,
좌표, 탭 순서를 분기문으로 알지 않는다.

1. 콜드 실행에서 Luna는 목표, 입력, 교육 절차, 현재 OCR·컨트롤을 보고 현재 단계와 행동을
   선택한다.
2. 공통 검토기는 현재 캡처의 ref, 허용 행동, 입력 source만 검사하고 공통 실행기로 전달한다.
3. 성공적으로 전달된 행동은 즉시 공유 레시피에 넣지 않고 case 내부에 격리한다.
4. 저장 후 재조회와 모든 값 대조까지 업무 완료가 확인된 실행만 후보를 컴파일한다.
5. 컴파일러는 자격 증명, 이번 건의 값이 들어간 앵커, 같은 화면의 중복 재시도를 제거한다.
6. 웜 실행은 순서대로 다음 행동 그룹 하나를 현재 OCR 라벨·상대 기하와 새 입력값에 결합한다.
   결합할 수 없으면 Luna가 현재 화면을 탐색하며, 전체 성공 후 새 그룹을 기존 레시피에 합친다.

따라서 첫 실행에서 모델이 프로그램 절차의 선례를 만들고, 그 선례가 성공으로 입증된 뒤에만
구조화된 실행 데이터로 재사용된다. 즉석 Python 코드를 생성하거나 과거 절대 좌표를 재생하지
않는다.

## seed17 파일럿 결과

콜드081과 새 값을 사용한 웜082는 모두 ERP 저장, 저장 후 식별번호 재조회, 상세 화면의 10/10
필드 대조까지 성공했다. 비인가 전송과 중복 추가 행은 없었다.

| 측정 | 콜드081 | 웜082 | 변화 |
|---|---:|---:|---:|
| 전체 시간 | 127.919초 | 75.180초 | -41.23% |
| 유료 Luna 호출 | 19 | 6 | -68.42% |
| 전체 모델 호출(로컬 포함) | 32 | 19 | -40.63% |
| 유료 모델 지연 | 88.983초 | 38.515초 | -56.72% |
| 비용 | $0.05162415 | $0.01810750 | -64.92% |
| 레시피 결합 | 0 | 9 | +9 |

웜 실행은 로그인 뒤 조회 진입, 중복 조회, 신규 화면, 11개 필드 입력, 저장 확인, 조회 화면
복귀의 9개 그룹을 재사용했다. 입력 반환 실패는 0건이고 콜드의 중복 검색 1회가 사라졌다.
최종 재조회 입력과 상세 이동은 Luna가 판단했고, 성공 뒤 기존 9개와 합쳐 실행값이 없는 11개
그룹 레시피가 됐다.

이 결과는 개발 시드17의 한 ERP 업무에 대한 제한 파일럿이다. 다른 배치·제품·업무에서 같은
성공률을 입증하지 않았으며 M1/M2 종료 근거로 사용하지 않는다.
