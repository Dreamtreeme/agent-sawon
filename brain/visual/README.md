# L2C 방식의 로컬 좌표와 의미 판단 분리

## 현재 화면 매칭 경로 (2026-10-01)

시각 프로필은 `screen_matching=true`를 사용한다. 사용자가 제공하는 업무 절차 JSON은
`procedure_path` 또는 CLI `--procedure`로 지정한다. 기본 파일은
`examples/shipment-procedure.json`이며 합성 선적 업무용 예제다. 실제 사용자 절차가
확정됐다고 간주하지 않는다. 현재 M1/M2 선적 업무의 단계·검증 계약 안에서 사용한다.
실행 시작 시 파일을 읽고 케이스의 `procedure.json`으로 보존한다. 최초 LLM 계획 생성은 없다.

GPU OCR·로컬 탐지의 현재 화면 JSON + 현재 단계의 절차 항목 + 중앙 작업 상태/필요 값 →
`ScreenMatch` 응답 한 번 → 현재 마커를 기존 실행 계약으로 변환 → 연속 입력 및 검증 순서다.
기본 응답의 `steps`는 `target/action/source/intent`를 담는다. 값·중심 좌표는 코드가 공급한다.
`controls`에는 실행/현재 입력 재검증/조회 근거에 필요한 역할·라벨 관계만 반환하며,
모든 화면 장식의 의미 목록과 별도의 번호 선택 응답을 요구하지 않는다.
`expected_result`는 기대 결과 기록일 뿐 성공 판정에 사용하지 않는다.
계정/비밀번호 값은 모델에 보내지 않고 코드가 출처 키로 공급한다.

OCR 텍스트와 로컬 컨트롤 탐지 영역을 모두 마커 후보 및 번호 표시 이미지에 포함한다.
텍스트 탭/버튼/메뉴는 OCR 영역을 클릭 대상으로 쓸 수 있으며, 글자 라벨을 입력 칸이나
표 영역으로 바꾸지는 않는다. Gemini/Luna의 화면 매칭에는 이미지에 표시한 마커 번호만 제공한다.
`marker_contract.py`가 응답의 라벨/값 번호를 내부 OCR 번호로 변환한다.
Jev 선택 경로와 분리형 의미 탐지의 내부 OCR 계약은 유지한다.

`visual_click_refinement=true`이면 이동 클릭을 실제 전달했지만 새 업무 화면 근거가 없을 때
`click_refinement.py`가 현재 번호 표시 OCR/컨트롤 캡처와 원래 목표·기대 결과를 모델에 보낸다.
모델은 기존 대상 영역 안의 구체적인 픽셀 좌표 또는 `replan`을 반환한다. 이미 선택됨,
비활성, 대기 중이거나 위치 보정 근거가 없으면 재계획하며, 같은 중심을 다시 클릭하지 않는다.
같은 단계/의미 대상의 이미지 보정 요청은 실행당1회다. 정상 동작과 입력/저장 오류에는
이 좌표 요청을 추가하지 않는다. `expected_result`는 판단 맥락이며 성공 증거가 아니다.
보정 클릭은 기존 ActionPlan/상태 정책/최신 동일 화면 갱신/relay/후속 검증을 재사용한다.
좌표는 현재 관찰에만 연결하고 한번 사용 후 폐기하며 의미 캐시 성공으로 저장하지 않는다.
원본 캡처·응답은 `case/click-refinement/<obs_id>/`, 비용·실행·검증은 공통 로그에 남긴다.
최근 실패/좌표 검토 정보는 중앙 메모와 다음 매칭 요청에 포함한다.

`required_verification`은 현재 조회 식별자와 방금 입력한 필드의 의미 식별 정보다.
다음 행동이 다른 컨트롤을 사용해도 현재 화면에서 이 항목들의 라벨·값 근거를 유지한다.
응답에 항목이 있으면 추가 호출하지 않는다. 실제 누락 때만 컨트롤 보완 요청을 한 번
실행하고 원래 행동/조회 판정 제안은 그대로 둔다. 현재 OCR/마커 포함 관계와 기존 값
검증을 통과해야 하며 과거 값·ref·좌표를 복사하지 않는다. 보완 뒤에도 누락이면
`required_verification_missing`으로 구분한다. 실제 값 불일치 검사는 유지한다.

매칭 `evidence`는 현재 화면의 필드 관찰 정보다. 중복 판정/중단에서는 이 정보를
최종 행 증거로 넘기지 않고, 중복 판정에 필요한 현재 표만 실행 계약에 연결한다.
조회 입력값은 기존 별도 검사로 검증한다. 완료 판정에는 grid/row/field evidence를 모두
유지하며, 일반 행동의 현재 필드 검증 정보도 기존 계약에 맞춰 전달한다.
`operation=act`에 동작이 없는 잘못된 응답은 현재 단계의 동작만1회 보완한다.
실행할 수 없으면 stop과 빈 배열을 반환한다. 보완 스키마는 빈 act/동작 있는 stop을
거절한다. 이미지/로컬 보완 탐지 요청 중에는 아직 동작이 없어도 실행 보완을 호출하지 않는다.

기본 매칭은 OCR/영역 JSON만 전송한다. `needs_image` 응답 때만 이미지 포함 요청을 한 번
추가한다. 필수 컨트롤 누락의 로컬 보완 탐지는 기존 제한 경로를 유지하므로 모든 경우가
정확히 한 호출인 것은 아니다. 로그인은 두 입력+버튼, 등록은 직접 입력 필드를 묶는다.
등록 입력과 저장/탭 전환은 서로 다른 검증 경계다. 저장 결과와 다음 명령은 한 응답이다.

동일 창·동일 크기·동일 PNG SHA256의 새 캡처에서는 OCR·탐지·관계 해석을 재사용한다.
화면이 바뀌면 다시 인식한다. 업무 단계만 바뀌면 보관한 화면 양식과 새 절차 단계로 매칭한다.
새 마커 관계는 로컬 좌표/포함 관계를 다시 검증하고, 새 관찰 ID로 연결하므로 과거 ref를
입력에 재사용하지 않는다. 사용자의 실제 절차 파일과 실제 화면에서의 성공/지연은 후속 측정이다.

## 공통 작업 메모와 실행

`brain/graph/notebook.py`는 계획·단계·검증 상태·현재 관찰 경로를
`case/task-notebook.json`에 원자적으로 기록한다. 중앙 Brain 상태가 원본이다.
자격 증명이나 과거 좌표를 기록하지 않고 이 파일만으로 실행을 재개하지 않는다.
이전 번호 선택/공동 판단 실험 경로는 제거했으며 현재 화면 매칭이 기존 공통
ActionPlan 실행기와 검증기를 사용한다. 과거 실험 내용은 Git과 진행 기록에 남아 있다.

실행 경로는 relay 캡처 → PaddleOCR + 로컬 OmniParser → 중복/글자 조각 제거 →
원본 이미지 좌표의 마커 목록/번호 이미지 → 측정된 모델의 ID별 의미 분석 →
로컬 좌표 결합 → 현재 캡처와 업무 가드 검증 → relay 입력 → 새 관찰이다.

사용자 지시에 따라 relay `restore_allowed_focus` 설정으로 캡처/입력 전 허용 ERP를
활성화한다. L2C의 캡처 전 window.activate() 흐름을 따르며 Windows에서는 최소화 복원,
BringWindowToTop/SetForegroundWindow와 임시 입력 스레드 연결을 사용한다.
입력 직전에는 관찰한 창으로 복귀하고 현재 픽셀 검사는 유지한다. 관찰 전용 모드는 수동적이다.
비밀번호 칸은 중계에서 덧칠하지 않는다. 사용자 지시에 따라 ERP 자체의 마스킹 문자와
테두리/커서를 원본 그대로 캡처한다. 입력 확인은 로그인 결과로 판단한다.

업무 입력값이 맞지 않고 해당 칸에 포커스가 남아 있으면 `visual_input_blur_recheck`
설정에 따라 한 번 `tab`을 보내고 같은 칸을 새 캡처에서 다시 읽는다. 다음 칸의 순서나
의미를 가정하지 않으며 추가 입력은 하지 않는다. 창/대상 변경·포커스 유지·값 불일치는
실패이며 `|` 같은 문자를 임의로 제거하지 않는다. 재검사 행동도 현재 캡처·상태 정책·
단계/비용 상한을 적용하고, 복합 행동을 단일 입력 캐시 성공으로 저장하지 않는다.
모델 스키마의 키는 relay 문법(`tab`, `shift+tab`, `enter` 등)을 그대로 사용한다.

`SemanticDetection`에는 bbox 필드가 없다. 모델이 좌표를 추가하면 스키마에서 거절한다.
현재 목록에 없는 ID, 중복 ID, OCR 라벨을 입력 칸으로 바꾸는 응답도 거절한다.
이미지 밖 검출 좌표를 화면 끝으로 강제 보정하지 않는다. OCR 값과 부모 포함 관계는
기존 `bind_scene`에서 다시 검사한다. 캡처 ID, 전경, 픽셀 해시와 물리 좌표 변환은
기존 relay/brain 경계를 유지한다. UIA나 ERP 내부 데이터 접근은 추가하지 않는다.

## L2C 소스에서 확인한 내용과 적용 범위

참조 위치는 로컬 `L2C/agent/`이며 L2C 패키지를 import하지 않는다.

| 확인한 원본 | 동작 | 이식 |
|---|---|---|
| tools/omni_parser.py | YOLO 모델의 xyxy 검출, resize 역변환 | detector_worker.py, 실제 정수 resize 후 x/y 배율 각각 복원 |
| tools/ocr_engine.py | PaddleOCR+아이콘 병합, 중복 제거, 번호와 사각형 표시 | markers.py, OCR 근거 보존 및 문자 내부 오탐 제거 |
| graph/worker_execution_context.py | 현재 current_markers에서 ID를 찾아 bbox 반환 | ground_meanings에서 현재 관찰 ID만 조회 |
| graph/worker_execution_dispatch.py | click/type 요청에 marker_id 사용 | 내부 관찰 ref와 로컬 bbox 결합 후 기존 ImageTarget 경로 |
| tools/actions.py | 검출 사각형 중심과 캡처 원점으로 클릭 좌표 계산 | 기존 Screenshot.desktop_point 사용, DPI 이중 적용 방지 |
| vision/target_snapshot.py | 대상 ID/사각형/중심을 실행 근거로 기록 | markers.json, meanings.json, perception.json, 기존 행동 로그 |

L2C의 브라우저 조작, 채용 사이트 지식, 자체 데이터베이스, 직접 pyautogui 호출은
가져오지 않는다. 캐시는 기존 의미 재연결을 유지하고 과거 마커 번호나 좌표를
새 관찰의 클릭 위치로 재사용하지 않는다.

차이: L2C의 `remove_text_containers`는 OCR 글자를 감싸는 아이콘 상자를 제거한다.
데스크톱에서는 입력 칸이나 버튼 자체일 수 있으므로 여기서는 큰 컨트롤을 보존한다.
입력 칸과 표의 역할은 모델이 해석하되, 탐지기가 찾지 못한 영역을 모델이 만들어
내지는 못한다. 표/행 영역 미검출은 여전히 업무 중단 원인이 될 수 있다.

후속 보완: `pixel_rectangles_enabled`가 켜진 visual 설정에서는 이미지의 수평·수직선으로
닫힌 사각형 후보를 추가한다. 네 변의 선 근거가 90% 미만이거나 이미지 끝에서 잘린 영역은
버린다. `pixel_rectangle` 출처를 따로 기록하고 최대80개로 제한한다. OCR 라벨/ERP 지식은
사용하지 않으며 표/입력 칸이라는 역할은 여전히 의미 모델이 판단한다. 후보 confidence1은
결정적 경계 후보 표시이고 의미 판단의 확률이 아니다. 테두리 없는 표는 여전히 미검출 가능하다.

모델 입력 그림에는 OCR 텍스트와 컨트롤 후보의 마커 번호를 모두 표시한다. 화면 매칭의 `label_ids`/`text_ids`는
텍스트 마커 ID이며 각 후보의 `contained_ocr_ids`도 같은 모델용 번호를 쓴다.
내부 의미 탐지/장면 검증에서는 변환된 OCR 블록 ID를 사용한다. 원본 탐지 점수는
`candidate_confidence`로 보내고 모델의 의미 확신과 구분한다. 로컬 연결 검증 실패에만
동일 캡처로 최대1회 교정한다. 거절 응답/오류/시도별 원본은 보존하고, API/파싱 실패나
비용 미확정은 이 교정으로 재시도하지 않는다. 두 호출 모두 기존 측정/예산 경계를 통과한다.

빈 조회 결과 확인은 구조화된 table_state/신뢰도와 실제 행 검사를 사용한다.
헤더 설명 같은 일반 경고는 보존하되 빈 표 판정의 거절 사유로 쓰지 않는다.
최종 행/값 검증은 일반 경고 검사를 유지하며, 표 영역에 겹친 컨트롤 불확실성은 계속 검사한다.
제목 표시줄 등 표 밖의 낮은 OCR 점수는 진단 기록에 남기되 표의 검증을 막지 않는다.
범위 정보가 없는 이전 scene/replay는 기존의 보수적 전체 불확실성 규칙을 유지한다.

`config/models.visual.toml`은 상위 모델의 시각 JSON용 출력 한도를8192로 둔다.
4096 한도의 저장 화면 비교에서는 추론3214+응답867토큰 뒤 JSON 파싱에 실패했다.
같은 캡처의8192 한도 비교는1회 연결 검증을 통과했으나 전체 업무 성능 비교는 아니다.

## 설정과 실행 근거

`BrainSettings.visual_detector`에 weights, python, confidence, max_dimension,
timeout_seconds를 둔다. weights 상대 경로는 brain 설정 파일 기준이다.
device 설정으로 추론 장치를 선택하며 현재 visual 프로필은 `cuda:0`이다.
이전 worker의 CPU 고정값을 제거했고 기본/보완 탐지 모두 같은 장치를 사용한다.
현재 visual 설정은 이 컴퓨터에 이미 설치된 L2C 가중치와 격리된 Python을 사용한다.
다른 컴퓨터에서는 해당 경로를 설정해야 한다. 가중치나 L2C 환경 자체는 커밋하지 않는다.
동일 환경 설치가 필요하면 optional extra `visual`을 사용한다. 자동 다운로드는 하지 않는다.
로컬 탐지 실패 자체에는 좌표 요청을 하지 않는다. 위의 실제 이동 클릭 실패에만 보정한다.

탐지 후보 confidence 기본값0.15는 L2C의 후보 수집 기준이다. 모델의 의미 분석
confidence 기본 문턱0.8과 다른 값이며 확률을 서로 곱하거나 동일시하지 않는다.
로컬 탐지와 의미 분석 모두 측정 ModelClient를 거친다. 로컬 탐지는 provider=local,
토큰 해당 없음(0), API비용0과 실제 지연을 기록하며 로컬 실패도 청구 미확정으로 바꾸지 않는다.
OCR과 탐지 worker는 작업 중 유지하며 화면이 바뀌어도 로드된 모델을 재사용한다.
탐지의 기본·보완 요청도 같은 YOLO를 사용한다. 각 캡처의 추론은 새로 수행하며,
실패/시간 초과 시 해당 worker를 종료하고 다음 요청에서 다시 시작한다.
작업 종료 시 소유한 worker와 자식 프로세스를 정리한다. 저장된 서로 다른 화면으로
동일 PID와 후속 모델 초기화 0ms를 확인했으며, 실제 업무 전체 지연은 별도 검증 대상이다.

시연 기록은 `python -m brain.visual.record`의 `--brain-config`로 같은 탐지 설정을 받는다.
UIA가 차단된 observation-only relay라는 기존 제한을 유지한다.

원본 그대로 캡처한다. 이전 덧칠·테두리 보존 실험은 아래 과거 오프라인 결과와

IoU 외에 중심·면적 비율을 사용해 중첩 아이콘을 정리하되 표/작은 자식은 유지한다.

## 화면별 연속 입력

`visual_screen_fill=true`(시각 실행 프로필)에서는 중복 조회 통과 후 보이는 등록 필드를
`ScreenFillPlan` 하나로 계획한다. 값은 레코드에서 가져오며 모델은 source/ref 연결만 반환한다.
계획 전체를 먼저 검사한 뒤 각 입력의 OCR/의미 해석/행동 판단 호출을 생략한다.
각 좌표 행동은 relay의 새 캡처에 묶고 같은 창·물리 위치/크기를 확인한다. 첫 행동 이후에는
예상된 입력 변화 때문에 최초 화면과 전체 픽셀 동일성을 요구하지 않는다.
새 창/창 이동/크기 변경 또는 입력 거절이면 남은 계획 실행을 멈추고 재관찰한다.
같은 창 안의 자동 레이아웃 변화는 중간 의미 분석으로 탐지하지 않으므로,
화면을 바꾸는 입력·검색·탭 이동은 연속 입력 목록에서 제외하도록 모델에 지시한다.
마지막 입력 후 한 번 Tab으로 편집을 마친 다음 전체 화면을 한 번 읽어 모든 값을 대조한다.
맞은 필드는 검증 사실로 저장하고 틀린 필드만 남긴다. 저장/확정은 이 입력 계획에 포함하지 않는다.
이후 판단은 검증에서 얻은 장면을 그대로 사용해 바로 전체 인식하는 중복을 제거한다.
필드 단위 semantic action cache는 이 모드의 입력 묶음으로 잘못 저장하지 않는다.
기본 라이브러리 설정은 false로 유지해 과거 실행 조건을 재현할 수 있다.

로그인에는 `LoginScreenPlan`을 사용해 남은 계정·비밀번호 입력과 로그인 버튼 클릭을
한 번에 계획한다. 세 동작 사이 OCR/모델 호출은 없으며 클릭 후 한 번 재관찰한다.
자격 증명은 실행기가 공급하고 모델은 source/ref만 지정한다. 현재 화면이 로그인 폼이 아니면
같은 응답의 일반 행동으로 진행한다. 입력 전달만으로 인증 성공을 만들지 않으며,
재관찰에도 로그인 컨트롤이 그대로 남으면 `login_screen_still_visible`로 실패 처리한다.
